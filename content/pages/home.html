How the course works

Every lesson is split into sessions of about an hour. A session is one sitting: read the section, run the code, do the hands-on exercise. Inside each lesson a divider marks where one session ends and the next begins, with a checkbox to tick it off. The quiz at the end of a lesson comes once you have finished all its sessions. The daily schedule lays the whole course out day by day, and its checkboxes record the same progress.

The order matters. Parts I to V build the mental model: Python, the maths, classical machine learning, neural networks and the transformer. Part VI is the day-to-day craft of an AI engineer: calling models, prompting, reasoning models, retrieval, agents, context engineering and evaluation. Part VII changes models and runs them efficiently: fine-tuning, post-training and inference. Part VIII is about running all of that in production. Part IX covers the wider field of AI beyond language models, and part X pulls everything together into system design, capstone projects and a portfolio.

If you already know a topic, skim the lesson, do the hands-on exercises and the quiz, and move on. If the exercises are easy and the quiz is clean, you have earned the skip.

Read on your phone, practise at your computer

The lessons are written to be read anywhere. The code is meant to be run on a computer. The course is built for switching between the two.

  1. Read on any screen. Open {{site_url}} on your phone. In Safari use Share, Add to Home Screen; in Chrome use Install app. It then opens like an app, and every lesson you open is saved for reading offline. The Aa button sets the text size, typeface and theme.
  2. Practise at your computer. Clone the repository, open the notebooks folder in JupyterLab or VS Code, and run the notebook with the same number as the lesson. Each exercise in a lesson is labelled At your computer and names the notebook cell to use. No setup on the day? Every lesson also has an Open in Colab link.
  3. Keep one set of ticks. Progress is saved in each browser separately. The Aa button gives you a sync link: open it on your other device and its ticks are merged in.

A good rhythm: read a session on your phone during the day, then sit down at your computer in the evening, open the notebook and do that session's exercise. The lesson page remembers where you stopped reading.

What you need

  • A computer with Python 3.11 or newer. Lesson 00 walks through the setup.
  • A free Google Colab account (or any machine with an NVIDIA GPU) for the deep learning, fine-tuning and inference lessons. Everything else runs on a laptop CPU.
  • An API key for a hosted model provider for part VI. A few US dollars of credit covers every exercise in the course.
  • A Git repository for your notes and code. Treat it as your lab notebook; it becomes your portfolio.

Companion notebooks

Every lesson has a Jupyter notebook in the notebooks folder with all of the lesson's code ready to run and an empty cell for each hands-on exercise. Complete, runnable solutions are in notebooks/solutions. notebooks/README.md explains how to run them locally or on Colab, and which ones need a GPU or an API key.

Habits that make this stick

Type the code rather than pasting it, at least through part V. Typing forces you to read every line, and the typos you fix teach you more than the code that ran first time.

Close the page and explain it back. At the end of each session, write three or four sentences in your learning log describing what you learned, without looking. If you cannot, reread the section. This is retrieval practice, and it is the single most effective study technique we know of.

Build something small every week. The hands-on exercises are designed to be extended. Change the dataset, swap the model, break it on purpose, and write down what happened.
