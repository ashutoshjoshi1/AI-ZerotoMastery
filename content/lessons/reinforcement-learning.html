Learning from consequences

Every model so far learned from examples with the right answer attached. In reinforcement learning (RL) nobody supplies the answer. An agent acts, the world responds with a number, and the agent must work out which of its past actions earned it. That is how a recommender learns what people come back for and, as lesson described, how frontier language models are finished.

The agent-environment loop

At each step the agent observes a state \(s_t\) and picks an action \(a_t\); the environment replies with a reward \(r_{t+1}\) and the next state. The agent's rule for choosing actions is its policy \(\pi(a \mid s)\), a probability for each action. One run from start to end is an episode.

Gymnasium gives many environments this interface. In CartPole you push a cart left or right to keep a pole upright, earning +1 per step, up to 500.

import gymnasium as gym

terminated means the task really ended (the pole fell); truncated means a time limit cut it short. A random policy lasts about 20 steps. The rest of this lesson is about getting to 500.

Returns and discounting

The agent maximises not the next reward but the return, the discounted sum of rewards from now on:

\[ G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \cdots = r_{t+1} + \gamma\, G_{t+1} \]

The discount \(\gamma\) between 0 and 1 keeps sums finite and sets a horizon: with \(\gamma = 0.99\) the agent looks roughly \(1/(1-\gamma) = 100\) steps ahead. The recursive form computes every return in one backward pass.

def discounted_returns(rewards, gamma):
    """G_t = r_{t+1} + gamma * G_{t+1}, computed backwards in one pass."""
    G, out = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        out.append(G)
    return out[::-1]

print(np.round(discounted_returns([0, 0, 0, 1], gamma=0.9), 3))   # reward at the end
print(round(discounted_returns([1] * 200, gamma=0.99)[0], 1))      # tends to 100
[0.729 0.81  0.9   1.   ]
86.6

Three things make RL harder than supervised learning. Credit assignment: a game is decided at move 60, so which moves deserve the credit? The data depends on the model: the policy decides what it sees, so the data shifts whenever the policy changes. And exploration: you only see the reward of the action you took, and there is no gradient through the world, only a number you observe.

Multi-armed bandits

Remove the states and exploration is all that is left. A multi-armed bandit is a row of slot machines, each paying out with an unknown probability. Pull the best-looking arm (exploit) and you may never find a better one; try others (explore) and you pay for every worse pull. A strategy is measured by its regret, the expected reward given up against always pulling the best arm:

\[ \text{regret}(T) = \sum_{t=1}^{T} \big(\mu^* - \mu_{a_t}\big) \]
  • Epsilon-greedy: with probability \(\varepsilon\) pull a random arm, otherwise the best average so far.
  • UCB: pull the arm with the highest optimistic estimate \(Q_a + \sqrt{2 \ln t / N_a}\); rarely tried arms get a big bonus.
  • Thompson sampling: keep a Beta distribution over each arm's payout rate, draw one sample from each, pull the largest. Each arm is chosen with the probability that it is the best.

The averages use \(Q \leftarrow Q + \tfrac{1}{n}(r - Q)\), the template for nearly every update in this lesson: estimate ← estimate + step × (target − estimate).

class EpsilonGreedy:
    def __init__(self, k, eps=0.1):
        self.eps, self.Q, self.N = eps, np.zeros(k), np.zeros(k)

    def choose(self, t, rng):
        if rng.random() < self.eps:
            return int(rng.integers(len(self.Q)))      # explore
        return int(np.argmax(self.Q))                  # exploit

    def update(self, a, r):
        self.N[a] += 1
        self.Q[a] += (r - self.Q[a]) / self.N[a]       # running mean of rewards


class UCB(EpsilonGreedy):
    def choose(self, t, rng):
        if (self.N == 0).any():
            return int(np.argmin(self.N))              # try every arm once
        bonus = np.sqrt(2 * np.log(t) / self.N)        # big when an arm is rarely tried
        return int(np.argmax(self.Q + bonus))


class Thompson:
    def __init__(self, k):
        self.a, self.b = np.ones(k), np.ones(k)        # Beta(1, 1): a uniform belief

    def choose(self, t, rng):
        return int(np.argmax(rng.beta(self.a, self.b)))  # sample a belief, act on it

    def update(self, a, r):
        self.a[a] += r                                 # count successes
        self.b[a] += 1 - r                             # and failures
import matplotlib.pyplot as plt

p = np.array([0.30, 0.45, 0.50, 0.55, 0.60])   # true payout rates, hidden from agents
T, runs = 2000, 50

def run(make_agent, seed):
    rng = np.random.default_rng(seed)
    agent, regret = make_agent(), np.zeros(T)
    for t in range(T):
        a = agent.choose(t, rng)
        r = float(rng.random() < p[a])               # pull the arm
        agent.update(a, r)
        regret[t] = p.max() - p[a]                   # what this choice cost us
    return regret.cumsum()

In industry, a bandit is an A/B test that shifts traffic towards the winner while it runs, so fewer users see the loser. Bandits pick headlines, ads, offers and recommendation slots; a contextual bandit predicts each action's reward from features of the user. The catch: adaptive allocation breaks the usual significance tests, so run a proper experiment when you need a clean causal estimate.

Markov decision processes

Most problems have many states, and actions change which comes next. A Markov decision process (MDP) has states, actions, transition probabilities \(P(s' \mid s, a)\), rewards \(R(s, a, s')\) and a discount \(\gamma\). "Markov" means the next state depends only on the current state and action, so the state must hold everything relevant. Lesson searched for plans in known, deterministic worlds; an MDP adds chance, and its solution is a policy, an action for every state.

Value functions and the Bellman equations

The value function \(V^\pi(s)\) is the expected return from \(s\) under policy \(\pi\). The Q-function \(Q^\pi(s, a)\) is the expected return from taking \(a\) in \(s\) and following \(\pi\) after; with it, acting is just \(\arg\max_a Q(s, a)\). Because \(G_t = r_{t+1} + \gamma G_{t+1}\), the best values obey the Bellman optimality equations:

\[ V^*(s) = \max_a \sum_{s'} P(s' \mid s, a)\,\big[R(s, a, s') + \gamma\, V^*(s')\big] \] \[ Q^*(s, a) = \sum_{s'} P(s' \mid s, a)\,\big[R(s, a, s') + \gamma \max_{a'} Q^*(s', a')\big] \]

In words: the value of where you are is the reward you expect next plus the discounted value of where you land. Every method in this lesson solves or approximates these equations.

Value iteration on FrozenLake

If you know \(P\), apply the Bellman equation as an update until nothing changes: value iteration. FrozenLake is a 4×4 grid of ice with holes; reaching the goal pays 1. The ice is slippery: you move the way you aim only a third of the time.

env = gym.make("FrozenLake-v1", is_slippery=True)
P = env.unwrapped.P          # P[s][a] = [(prob, next_state, reward, terminated), ...]
# from the square left of the goal (14), try to move right (action 2):
print([(round(prob, 3), s2, r, end) for prob, s2, r, end in P[14][2]])

def value_iteration(P, gamma=0.99, tol=1e-8):
    nS, nA = len(P), len(P[0])
    V = np.zeros(nS)
    while True:
        Q = np.zeros((nS, nA))
        for s in range(nS):
            for a in range(nA):
                Q[s, a] = sum(prob * (r + gamma * V[s2] * (not end))
                              for prob, s2, r, end in P[s][a])
        V_new = Q.max(axis=1)                      # the Bellman optimality backup
        if np.abs(V_new - V).max() < tol:
            return V_new, Q.argmax(axis=1)
        V = V_new

V, policy = value_iteration(P)

def success_rate(env, policy, episodes=1000):
    wins = 0.0
    for ep in range(episodes):
        s, _ = env.reset(seed=ep)
        done = False
        while not done:
            s, r, terminated, truncated, _ = env.step(int(policy[s]))
            done = terminated or truncated
        wins += r                                  # 1 only if we reached the goal
    return wins / episodes

Q-learning and SARSA

Usually nobody hands you \(P\). Temporal-difference (TD) learning replaces the sum over next states with one sampled transition. Q-learning nudges its estimate towards a one-step target:

\[ Q(s, a) \leftarrow Q(s, a) + \alpha \big[\, r + \gamma \max_{a'} Q(s', a') - Q(s, a) \,\big] \]

The bracket is the TD error. The target uses the current estimate of the next state, which is bootstrapping; it works because the reward in the target is real, and that real information flows back from the goal one step at a time. SARSA changes one term, using the action the agent will actually take next, \(Q(s', a')\), instead of the max. That makes Q-learning off-policy (it learns the greedy policy while behaving differently, so it can learn from any data) and SARSA on-policy (it learns the policy it runs, exploration included). CliffWalking, with a cliff along the bottom edge (−100 and back to the start for falling off), shows the difference.

def td_control(env, method, episodes=500, alpha=0.5, gamma=1.0, eps=0.1, seed=0):
    """Tabular Q-learning (method="q") or SARSA (method="sarsa")."""
    rng = np.random.default_rng(seed)
    Q = np.zeros((env.observation_space.n, env.action_space.n))

    def act(s):                                          # epsilon-greedy
        if rng.random() < eps:
            return int(rng.integers(env.action_space.n))
        return int(rng.choice(np.flatnonzero(Q[s] == Q[s].max())))  # random tie-break

    returns = []
    for ep in range(episodes):
        s, _ = env.reset(seed=seed + ep)
        a, done, G = act(s), False, 0.0
        while not done:
            s2, r, terminated, truncated, _ = env.step(a)
            a2 = act(s2)                                 # the action we will take next
            if method == "sarsa":
                target = r + gamma * Q[s2, a2] * (not terminated)    # on-policy
            else:
                target = r + gamma * Q[s2].max() * (not terminated)  # off-policy
            Q[s, a] += alpha * (target - Q[s, a])        # move towards the target
            s, a, G = s2, a2, G + r
            done = terminated or truncated
        returns.append(G)
    return Q, np.array(returns)

Q_s, ret_s = td_control(cliff, "sarsa")

Exploration is a dial: decay epsilon from about 1 to a floor such as 0.05, start Q optimistically high, or sample actions in proportion to \(e^{Q/\tau}\), the temperature sampling of lesson . Two common mistakes: decaying so fast the agent commits before it finds the goal, and judging an agent by training returns with exploration still on.

Deep reinforcement learning

Tables work for 16 states. CartPole's state is four real numbers, and Go has more positions than the observable universe has atoms. So replace the table with a neural network, \(Q_\theta(s, a)\) or \(\pi_\theta(a \mid s)\), that generalises to similar states. The price is stability: function approximation, bootstrapping and off-policy data together (Sutton and Barto's deadly triad) can make estimates diverge, because each update also moves the target you are chasing.

DQN

DeepMind's DQN (Mnih et al., Nature 2015) learned dozens of Atari games from pixels. It is Q-learning with a network, trained on

\[ L(\theta) = \Big( r + \gamma \max_{a'} Q_{\bar\theta}(s', a') - Q_\theta(s, a) \Big)^2 \]

plus two stabilisers. A replay buffer trains on random mini-batches of past transitions, breaking the correlation between consecutive steps and reusing data (allowed because Q-learning is off-policy). A target network \(Q_{\bar\theta}\), a copy synced only occasionally, computes the target so the label stops moving.

import random
from collections import deque
import torch
import torch.nn as nn
import torch.nn.functional as F

class ReplayBuffer:
    def __init__(self, capacity=10_000):
        self.memory = deque(maxlen=capacity)              # oldest transitions fall out

    def push(self, s, a, r, s2, done):
        self.memory.append((s, a, r, s2, done))

    def sample(self, n):
        s, a, r, s2, done = zip(*random.sample(self.memory, n))   # random: uncorrelated
        f = lambda x: torch.as_tensor(np.array(x), dtype=torch.float32)
        return f(s), torch.as_tensor(a), f(r), f(s2), f(done)

def dqn_loss(q_net, target_net, batch, gamma=0.99):
    s, a, r, s2, done = batch
    q = q_net(s).gather(1, a.unsqueeze(1)).squeeze(1)       # Q(s, a) for actions taken
    with torch.no_grad():                                   # the target is a fixed label
        target = r + gamma * target_net(s2).max(dim=1).values * (1 - done)
    return F.smooth_l1_loss(q, target)

random.seed(0); torch.manual_seed(0)
env = gym.make("CartPole-v1")
env.action_space.seed(0)
buffer = ReplayBuffer()
s, _ = env.reset(seed=0)
for _ in range(500):                                       # fill it with random play
    a = env.action_space.sample()
    s2, r, terminated, truncated, _ = env.step(a)
    buffer.push(s, a, r, s2, terminated)                   # terminated, not truncated
    s = env.reset()[0] if terminated or truncated else s2

q_net = nn.Sequential(nn.Linear(4, 64), nn.ReLU(), nn.Linear(64, 2))
target_net = nn.Sequential(nn.Linear(4, 64), nn.ReLU(), nn.Linear(64, 2))
target_net.load_state_dict(q_net.state_dict())            # a frozen copy, synced rarely
print(len(buffer.memory), "transitions; loss on one batch:",
      round(dqn_loss(q_net, target_net, buffer.sample(64)).item(), 4))
500 transitions; loss on one batch: 0.5713

The full loop adds epsilon-greedy acting, one gradient step per environment step and an occasional weight copy. The buffer stores terminated, not truncated: a time limit is not a real ending, and confusing the two is a classic DQN bug.

Policy gradients and REINFORCE

Policy-gradient methods skip the values: a network outputs action probabilities and training makes high-return actions more likely. This is the family that trains language models. To maximise expected return \(J(\theta)\), the log-derivative trick \(\nabla p = p\, \nabla \log p\) moves the gradient onto the policy's own probabilities, and the environment drops out:

\[ \nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta}\Big[ \sum_t \nabla_\theta \log \pi_\theta(a_t \mid s_t)\; G_t \Big] \]

Push up each action's log-probability in proportion to the return that followed. That is REINFORCE (Williams, 1992): cross-entropy on the agent's own actions, weighted by how well things went. The code rolls out an episode without gradients, then re-scores its states in one batch, the same pattern PPO and LLM training use.

def rollout(env, policy, seed):
    """Play one episode with the current policy and record it."""
    obs, _ = env.reset(seed=seed)
    states, actions, rewards, done = [], [], [], False
    while not done:
        with torch.no_grad():                          # acting needs no gradients
            probs = torch.softmax(policy(torch.as_tensor(obs)), dim=-1)
        a = int(torch.multinomial(probs, 1))           # sample, never argmax, in training
        states.append(obs)
        actions.append(a)
        obs, r, terminated, truncated, _ = env.step(a)
        rewards.append(r)
        done = terminated or truncated
    return torch.as_tensor(np.array(states)), torch.as_tensor(actions), rewards

def reinforce(seed=0, episodes=1000, lr=5e-3, gamma=0.99, verbose=True):
    torch.manual_seed(seed)
    env = gym.make("CartPole-v1")
    policy = nn.Sequential(nn.Linear(4, 64), nn.Tanh(), nn.Linear(64, 2))  # 2 logits
    opt = torch.optim.Adam(policy.parameters(), lr=lr)
    history = []
    for ep in range(episodes):
        S, A, rewards = rollout(env, policy, seed=1000 * seed + ep)       # 1. act
        G = torch.tensor(discounted_returns(rewards, gamma), dtype=torch.float32)
        G = (G - G.mean()) / (G.std() + 1e-8)        # normalise: a simple baseline
        logp = torch.distributions.Categorical(logits=policy(S)).log_prob(A)
        loss = -(logp * G).sum()                      # 2. push up log-prob x return
        opt.zero_grad(); loss.backward(); opt.step()
        history.append(sum(rewards))
        if verbose and ep % 50 == 0:
            mean50 = np.mean(history[-50:])
            print(f"episode {ep:4d}  mean return of last 50: {mean50:5.1f}")
        if len(history) >= 20 and np.mean(history[-20:]) >= 475:
            if verbose:
                print(f"solved at episode {ep}: mean of the last 20 returns >= 475")
            break
    return policy, history

def evaluate(policy, episodes=10):
    """Greedy actions on fresh seeds: how good is the learned policy?"""
    env, scores = gym.make("CartPole-v1"), []
    for i in range(episodes):
        obs, _ = env.reset(seed=10_000 + i)
        done, total = False, 0.0
        while not done:
            with torch.no_grad():
                a = int(policy(torch.as_tensor(obs)).argmax())
            obs, r, terminated, truncated, _ = env.step(a)
            total, done = total + r, terminated or truncated
        scores.append(total)
    return scores

REINFORCE bugs fail silently

Taking the argmax instead of sampling during training, flipping the sign of the loss, or a learning rate slightly too high all show up as "learns worse", not as errors. Doubling the learning rate to 0.01 solved four of our five seeds faster but needed 668 episodes on the fifth.

Baselines and actor-critic

REINFORCE is noisy: in a good episode every action gets the same large weight. Subtracting a baseline \(b(s_t)\) leaves the expected gradient unchanged (the expected score \(\mathbb{E}_{a \sim \pi}[\nabla \log \pi(a \mid s)]\) is zero) but can cut its variance. With \(b(s) = V(s)\) the weight becomes the advantage \(A_t = G_t - V(s_t)\): how much better the action turned out than average. An actor-critic learns both a policy (actor) and a value network (critic), and usually bootstraps \(A_t \approx r_{t+1} + \gamma V(s_{t+1}) - V(s_t)\); GAE blends the two estimates with a parameter \(\lambda\).

PPO: small, safe steps

One oversized policy update can wreck a policy, and a wrecked policy collects useless data. Proximal policy optimisation (PPO; Schulman et al., 2017) bounds each update. With the probability ratio \(\rho_t = \pi_\theta(a_t \mid s_t) / \pi_{\theta_\text{old}}(a_t \mid s_t)\) and advantage \(A_t\), it maximises

\[ L^{\text{CLIP}}(\theta) = \mathbb{E}_t\Big[ \min\big( \rho_t A_t,\ \operatorname{clip}(\rho_t, 1-\epsilon, 1+\epsilon)\, A_t \big) \Big] \]

with \(\epsilon\) around 0.2. For a good action (\(A_t > 0\)) raising its probability pays only until the ratio reaches \(1 + \epsilon\); beyond that the gradient is zero. For a bad one you may lower it only to \(1 - \epsilon\). The min keeps the bound pessimistic, so clipping never stops you undoing a move in the wrong direction. That is what makes it safe to take several gradient steps on each batch.

def ppo_clip_objective(logp_new, logp_old, adv, clip=0.2):
    ratio = torch.exp(logp_new - logp_old)                  # pi_new(a|s) / pi_old(a|s)
    clipped = torch.clamp(ratio, 1 - clip, 1 + clip)
    return torch.min(ratio * adv, clipped * adv).mean()     # maximise this

for adv in (1.0, -1.0):
    for ratio in (0.5, 0.9, 1.1, 1.5):
        logp_new = torch.tensor(np.log(ratio), requires_grad=True)
        obj = ppo_clip_objective(logp_new, torch.tensor(0.0), torch.tensor(adv))
        obj.backward()
        print(f"advantage {adv:+.0f}  ratio {ratio:.1f}  objective {obj.item():+.2f}"
              f"  gradient {logp_new.grad.item():+.2f}")

The gradient is zero exactly where the policy has already moved far enough in the helpful direction. A full PPO adds a critic, GAE and an entropy bonus; it was the algorithm behind classic RLHF.

All of this is model-free. Model-based RL learns the dynamics and plans or trains inside them, which saves real experience but invites the policy to exploit the model's errors. AlphaZero planned with tree search in games with known rules (lesson ), MuZero (Schrittwieser et al., 2020) learned the model too, and the Dreamer family trains an actor-critic inside a learned world model.

Reinforcement learning for language models

A chat model is a policy. The state is the prompt plus the tokens so far, an action is the next token, the policy is the softmax over the vocabulary, an episode is one response, and the reward usually arrives only at the end. Transitions are trivial (append the token), so all the difficulty is in the reward and in assigning credit across hundreds of tokens.

Reward models from preferences

"Be helpful" has no formula, so RLHF learns one from comparisons. A reward model \(r_\phi(x, y)\), usually a language model with a single-number head, is trained so that the chosen response \(y_w\) beats the rejected \(y_l\) under the Bradley-Terry model:

\[ L(\phi) = -\log \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big) \]

It is logistic regression on a difference of scores. Here it recovers a hidden preference over three made-up features:

torch.manual_seed(0)
n = 2000
true_w = torch.tensor([2.0, 1.0, -0.5])   # labellers like correct, clear, not rambling
xa, xb = torch.randn(n, 3), torch.randn(n, 3)       # features of two responses
prefer_a = torch.rand(n) < torch.sigmoid((xa - xb) @ true_w)  # noisy human choices
chosen = torch.where(prefer_a[:, None], xa, xb)
rejected = torch.where(prefer_a[:, None], xb, xa)

reward_model = nn.Linear(3, 1, bias=False)        # only differences matter: no bias
opt = torch.optim.Adam(reward_model.parameters(), lr=0.05)
for step in range(300):
    margin = (reward_model(chosen) - reward_model(rejected)).squeeze(1)
    loss = -F.logsigmoid(margin).mean()            # Bradley-Terry: P(chosen wins)
    opt.zero_grad(); loss.backward(); opt.step()

agreement = lambda m: round((m > 0).float().mean().item(), 3)
print("learned weights:", reward_model.weight.detach().squeeze().numpy().round(2))
print("learned model agrees with the labels:", agreement(margin))
print("true weights agree with the labels:  ", agreement((chosen - rejected) @ true_w))
learned weights: [ 1.9   0.9  -0.46]
learned model agrees with the labels: 0.842
true weights agree with the labels:   0.842

The weights come back close to the truth; only differences matter, hence no bias. Agreement is 84% because the labels are noisy, and the true weights do no better. Real reward models are also accurate only on responses like their training data, which is why optimising hard against them goes wrong.

PPO-based RLHF versus DPO

Classic RLHF maximises the reward model's score while staying close to the supervised model \(\pi_\text{ref}\):

\[ \max_\theta\ \mathbb{E}_{y \sim \pi_\theta}\big[ r_\phi(x, y) \big] - \beta\, D_\text{KL}\big(\pi_\theta \,\|\, \pi_\text{ref}\big) \]

optimised with PPO, which needs four large models in memory: policy, reference, reward model and critic. DPO uses the closed-form optimum of this objective to turn preferences directly into a loss on the policy, where the "reward" is \(\beta \log \pi_\theta(y \mid x) / \pi_\text{ref}(y \mid x)\). It is simpler and stable but offline, learning only from the dataset's responses; PPO is online, scoring fresh samples, so it can find and fix its own mistakes. Lesson runs both with real libraries.

GRPO and verifiable rewards

For maths and code you can often check the answer instead of learning a reward: compare with the known result, run the tests. This is RL with verifiable rewards (RLVR), and it is how reasoning models (lesson ) learn to think at length: only correct final answers are rewarded, and careful reasoning is what earns them.

GRPO, introduced in the DeepSeekMath paper (Shao et al., 2024) and later used for DeepSeek-R1, simplifies PPO for this setting. Sample a group of \(G\) answers per prompt, score them, and give every token of answer \(i\) the advantage

\[ A_i = \frac{r_i - \operatorname{mean}(r_1, \ldots, r_G)}{\operatorname{std}(r_1, \ldots, r_G)} \]

The group mean replaces the critic, saving a model's worth of memory. The rest is PPO's clipped objective plus a KL penalty to the reference, estimated per token as \(\frac{\pi_\text{ref}}{\pi_\theta} - \log\frac{\pi_\text{ref}}{\pi_\theta} - 1\), which is never negative. The KL term stops drift into text that games the reward and keeps outputs varied; too large a \(\beta\) and the model cannot move. Note that a group whose answers all score the same has zero advantage everywhere and teaches nothing.

A toy: teaching a policy to pass a verifier

The whole RLVR loop at readable scale. The "language model" is a tiny autoregressive network over ten digits and a junk token ?. Each prompt is a target from 0 to 18; a correct answer is two digits that add up to it. Nothing tells the model how to add.

import copy

VOCAB = list("0123456789?")                    # ten digits and one junk token
START, LENGTH, N_PROMPTS = len(VOCAB), 2, 19   # prompt t: "two digits that sum to t"

class TinyLM(nn.Module):
    """Autoregressive: next-token logits from (prompt, previous token, position)."""
    def __init__(self, hidden=64):
        super().__init__()
        self.prompt = nn.Embedding(N_PROMPTS, hidden)
        self.token = nn.Embedding(len(VOCAB) + 1, hidden)    # +1 for the start token
        self.pos = nn.Embedding(LENGTH, hidden)
        self.head = nn.Sequential(nn.Tanh(), nn.Linear(hidden, len(VOCAB)))

    def logits(self, prompts, prev, pos):
        return self.head(self.prompt(prompts) + self.token(prev) + self.pos(pos))

def generate(model, prompts):
    """Sample one answer per prompt, token by token: the policy acting."""
    prev, out = torch.full_like(prompts, START), []
    for pos in range(LENGTH):
        logits = model.logits(prompts, prev, torch.full_like(prompts, pos))
        prev = torch.multinomial(torch.softmax(logits, -1), 1).squeeze(1)
        out.append(prev)
    return torch.stack(out, 1)                                # (batch, LENGTH)

def token_logprobs(model, prompts, tokens):
    """Log-probability of every sampled token, all positions in one pass."""
    prev = torch.cat([torch.full_like(tokens[:, :1], START), tokens[:, :-1]], 1)
    pos = torch.arange(LENGTH).expand_as(tokens)
    logits = model.logits(prompts[:, None], prev, pos)        # (batch, LENGTH, vocab)
    return torch.log_softmax(logits, -1).gather(2, tokens[..., None]).squeeze(2)

def decode(tokens):
    return "".join(VOCAB[t] for t in tokens)

def verify(target, text):
    """The checker: two digits that add up to the target."""
    return float(text.isdigit() and int(text[0]) + int(text[1]) == target)

torch.manual_seed(0)
with torch.no_grad():
    print([decode(t) for t in generate(TinyLM(), torch.arange(8)).tolist()])
['83', '58', '37', '12', '50', '4?', '82', '86']

Now GRPO, reusing ppo_clip_objective from session 3. The check column is an independent score from the honest verifier.

def grpo(verifier, steps=300, group=8, n_prompts=32, beta=0.02, lr=5e-3, seed=0,
         log_every=50):
    torch.manual_seed(seed)
    policy = TinyLM()
    reference = copy.deepcopy(policy).requires_grad_(False)   # frozen starting point
    opt = torch.optim.Adam(policy.parameters(), lr=lr)
    for step in range(steps + 1):
        # 1. sample a group of answers for each prompt, and score them
        prompts = torch.randint(0, N_PROMPTS, (n_prompts,)).repeat_interleave(group)
        with torch.no_grad():
            tokens = generate(policy, prompts)
            logp_old = token_logprobs(policy, prompts, tokens)
            logp_ref = token_logprobs(reference, prompts, tokens)
        texts = [decode(t) for t in tokens.tolist()]
        targets = prompts.tolist()
        rewards = torch.tensor([verifier(t, s) for t, s in zip(targets, texts)])
        # 2. group-relative advantage: better or worse than my other attempts?
        r = rewards.view(-1, group)
        adv = (r - r.mean(1, keepdim=True)) / (r.std(1, keepdim=True) + 1e-4)
        adv = adv.view(-1, 1)                                 # same for every token
        # 3. two clipped PPO-style steps on this batch, anchored by a KL penalty
        for _ in range(2):
            logp = token_logprobs(policy, prompts, tokens)
            log_ratio = logp_ref - logp
            kl = (torch.exp(log_ratio) - log_ratio - 1).mean()   # always >= 0
            loss = -ppo_clip_objective(logp, logp_old, adv) + beta * kl
            opt.zero_grad(); loss.backward(); opt.step()
        if step % log_every == 0:
            check = np.mean([verify(t, s) for t, s in zip(targets, texts)])
            stuck = (r.std(1) == 0).float().mean().item()     # groups with no signal
            print(f"step {step:3d}  reward {rewards.mean():.2f}  check {check:.2f}  "
                  f"KL {kl.item():.2f}  no-signal groups {stuck:.2f}")
    return policy

def pass_rate(model, tries=20):
    with torch.no_grad():
        test = torch.arange(N_PROMPTS).repeat_interleave(tries)   # every target
        texts = [decode(t) for t in generate(model, test).tolist()]
    return np.mean([verify(t, s) for t, s in zip(test.tolist(), texts)]), texts

policy = grpo(verify)
rate, texts = pass_rate(policy)
print(f"pass rate over all 19 targets: {rate:.3f}")
print({t: texts[20 * t] for t in range(0, 19, 3)})

Reward hacking

An agent optimises the reward you wrote, not the goal you meant. Reward hacking, or specification gaming, is Goodhart's law in algorithmic form. In OpenAI's 2016 CoastRunners experiment, a boat-racing agent scored more by circling a lagoon to hit the same targets than by finishing the race. Chat reward models tend to favour long, confident, agreeable answers, so optimising hard against them yields verbosity and sycophancy (Sharma et al., 2023). Coding models trained against unit tests have been reported to special-case expected outputs or edit the tests. Defences: robust checkers that fail closed, the KL anchor, evaluations the policy never trains on (lesson ), and reading samples whenever the reward jumps.

Within 50 steps the reward reached 0.98 while the honest check fell to 0.00: the model put the junk token in every answer ('1?', '?0'), because unparsable answers are never marked wrong, and that is far easier to find than addition. Where RL is used, and when not to use it

RL shines where experience is cheap to simulate or the reward is easy to check: games (TD-Gammon, Atari, AlphaGo and AlphaZero, Dota 2, StarCraft II), robot policies trained in simulation, controlling plasma in a fusion reactor (Degrave et al., Nature 2022), bandits for recommendation and ads, chip floorplanning (Mirhoseini et al., Nature 2021, a result whose comparison with established tools has been publicly disputed) and, now routinely, LLM post-training.

SituationUse instead of RL
You have labelsSupervised learning
Decisions do not change what comes nextA contextual bandit, or prediction plus a decision rule
You know the rulesSearch and planning (lesson ) or a solver
You want an LLM to behave differentlyPrompting, retrieval, SFT or DPO first (lessons , , )

RL is sample-hungry, sensitive to seeds and hard to debug. Use it when the problem really is sequential decision-making with a reward you trust.

Check yourself

Why can a purely greedy bandit agent (epsilon = 0) suffer linearly growing regret?

  • It updates its estimates too quickly
  • It can lock onto an early arm and never gather evidence that another is better
  • Regret always grows linearly
  • It pulls arms at random

Without exploration a bad early choice is never corrected, so every pull pays the same gap.

On CliffWalking with epsilon = 0.1, why does SARSA learn a safer route than Q-learning?

  • It uses a larger learning rate
  • Q-learning ignores negative rewards
  • Its target uses the action it will actually take next, so it learns the value of its own exploring policy
  • It has a model of the environment

SARSA is on-policy: occasional random steps near the cliff lower the value of the edge.

In PPO with clip 0.2, an action has positive advantage and a ratio of 1.3. What does it add to the gradient?

  • Nothing: above 1.2 the clipped objective is flat
  • A large push upwards
  • A push back towards a ratio of 1
  • Only a KL term

Clipping removes the incentive to move further in a direction that has already helped.

In GRPO, all eight answers to a prompt pass the verifier. What does that prompt contribute?

  • A strong positive signal
  • Nothing apart from the KL term: every advantage is zero
  • A negative signal for diversity
  • Training data for the value network

Advantages are relative to the group, so always-solved and never-solved prompts carry no signal.

During RLHF the reward model's score keeps rising but held-out human ratings fall. Most likely?

  • The learning rate is too low
  • The raters became harsher
  • The policy is exploiting the reward model's errors (reward hacking)
  • The KL penalty is too large

A reward model is a proxy that is accurate only near its training data; stronger KL, a better reward model and early stopping on independent evaluations help.

Key takeaways

  • RL maximises discounted return from rewards, not labels. The hard parts are credit assignment, exploration and data that depends on the policy.
  • Bandits isolate exploration; epsilon-greedy, UCB and Thompson sampling trade it off differently, measured by regret.
  • Bellman equations: value is reward plus discounted next value. Value iteration solves them with a model; Q-learning (off-policy) and SARSA (on-policy) learn them from samples.
  • Deep RL swaps tables for networks: DQN adds replay and a target network; policy gradients weight log-probabilities by advantage; baselines cut variance; PPO clips each step.
  • An LLM is a policy over tokens. RLHF uses a reward model, PPO and a KL penalty; DPO is the offline shortcut; GRPO uses group-relative advantages with verifiable rewards. Every reward gets hacked if it can be, so keep an independent check.
