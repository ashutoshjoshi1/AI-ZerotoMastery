The other half of AI

Everything in this course so far has been learned from data. The field did not start there. For its first thirty years, AI mostly meant programs that search through possibilities and reason with knowledge written down by people.

That half never went away. Route planners, chess engines, airline crew schedulers and package-version resolvers are classical AI, and so is the inner loop of the most impressive learned systems: AlphaZero is a neural network wrapped in a tree search, and a reliable LLM agent is a model wrapped in planning, search and verification. This lesson builds the core algorithms in a few dozen lines each.

A short history of AI

Each era had one big idea, promised too much, and left behind something that still works.

You have studied learning. This lesson is about search, and how the two combine.

Problems as search

Mazes, routes, puzzles and plans share one shape, and once a problem has it, any search algorithm can solve it. You need a state (a maze cell, a town, a board), an initial state, the actions available in each state and where they lead, a goal test, and a path cost that adds up the step costs. In code, actions and their results become one successor function:

MAZE = """\
S.......#.
.######.#.
......#...
.####.#.#.
.#G...#.#.
.######.#.
..........
"""

def find(grid, ch):
    return next((r, c) for r, row in enumerate(grid)
                for c, x in enumerate(row) if x == ch)

def neighbours(state, grid):
    """Successor function: yield (next_state, step_cost) for every legal move."""
    r, c = state
    for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:      # up, down, left, right
        nr, nc = r + dr, c + dc
        if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]) and grid[nr][nc] != "#":
            yield (nr, nc), 1

def show(grid, path):
    rows = [list(row) for row in grid]
    for r, c in path[1:-1]:
        rows[r][c] = "*"
    print("\n".join("".join(row) for row in rows))

grid = MAZE.splitlines()
start, goal = find(grid, "S"), find(grid, "G")
print("start", start, "goal", goal)
print("moves from start:", list(neighbours(start, grid)))

moves from start: [((1, 0), 1), ((0, 1), 1)]

A search grows a tree of paths from the start. The frontier holds states that have been generated but not yet expanded, that is, had their successors generated. Every algorithm in this lesson runs that loop and differs only in which frontier state it expands next.

Breadth-first and depth-first search

Breadth-first search (BFS) takes states from the front of a queue, so it finishes each distance from the start before the next and finds the path with the fewest steps. Depth-first search (DFS) takes them from the back, diving down one path until it hits a dead end. The difference is one line:

from collections import deque

def reconstruct(parent, s):
    path = []
    while s is not None:
        path.append(s)
        s = parent[s]
    return path[::-1]

def uninformed_search(start, is_goal, successors, kind="bfs"):
    frontier = deque([start])
    parent = {start: None}                # also the set of states already reached
    expanded = 0
    while frontier:
        s = frontier.popleft() if kind == "bfs" else frontier.pop()   # FIFO or LIFO
        expanded += 1
        if is_goal(s):
            return reconstruct(parent, s), expanded
        for s2, _ in successors(s):
            if s2 not in parent:
                parent[s2] = s
                frontier.append(s2)
    return None, expanded

moves = lambda s: neighbours(s, grid)
for kind in ["bfs", "dfs"]:
    path, n = uninformed_search(start, lambda s: s == goal, moves, kind)
    print(f"{kind}: {len(path) - 1} steps, {n} states expanded")
    show(grid, path)

Iterative deepening, DFS with a depth limit of 0, then 1, then 2 and so on, gets BFS's shortest paths with DFS's small memory.

Uniform-cost search (Dijkstra's algorithm)

When steps have different costs, the fewest steps is the wrong target. Uniform-cost search (UCS) expands the frontier state with the lowest path cost so far, \(g(n)\), using a priority queue. It is Dijkstra's algorithm, stopped at the goal. Here it is on a map of field sites:

import heapq, math

# Field sites with their (x, y) position in km, and roads with their length in km

         "lake": (22, 8), "airfield": (8, 18), "observatory": (24, 19)}

         ("harbour", "lake", 12), ("harbour", "ridge", 11), ("mill", "ridge", 11),
         ("mill", "airfield", 10), ("ridge", "observatory", 12),
         ("lake", "observatory", 12), ("airfield", "observatory", 17)]
graph = {s: [] for s in SITES}
for a, b, km in ROADS:
    graph[a].append((b, km))
    graph[b].append((a, km))

def uniform_cost_search(start, is_goal, successors):
    frontier = [(0, start)]               # a priority queue ordered by path cost g
    parent, g = {start: None}, {start: 0}
    expanded = 0
    while frontier:
        cost, s = heapq.heappop(frontier)
        if cost > g[s]:
            continue                      # stale: a cheaper route was found later
        expanded += 1
        if is_goal(s):                    # test when expanded, not when generated
            return reconstruct(parent, s), cost, expanded
        for s2, step in successors(s):
            new = cost + step
            if s2 not in g or new < g[s2]:
                g[s2], parent[s2] = new, s
                heapq.heappush(frontier, (new, s2))
    return None, math.inf, expanded

Test for the goal when you expand, not when you generate

The first route to reach the goal may not be the cheapest; a better one can still be in the queue. Only when the goal is popped as the cheapest frontier item is its cost guaranteed. The same holds for A*. This bug fails silently: you still get a path, just not the best one.

Informed search

UCS spreads out evenly, like a ripple, because it knows nothing about where the goal is. A heuristic \(h(n)\) adds that knowledge: an estimate of the cost from \(n\) to the goal. It is admissible if it never overestimates the true cost \(h^*(n)\), and consistent if \(h(n) \le c(n, n') + h(n')\) for every step to a successor \(n'\). Every consistent heuristic is also admissible.

The reliable way to invent one is to relax the problem and solve the easier version exactly. Delete the maze walls and you get the Manhattan distance; ignore the roads and you get the straight-line distance. A relaxed problem is never harder, so its cost never overestimates.

A*, greedy and weighted A*

A* (Hart, Nilsson and Raphael, 1968) expands the frontier state with the lowest

\[ f(n) = g(n) + h(n), \]

its best guess at the total cost of a solution through \(n\). With an admissible heuristic, the path it returns is optimal. Greedy best-first search uses \(f = h\) and ignores what it has spent. Weighted A* uses \(f = g + w\,h\) with \(w > 1\), and its path costs at most \(w\) times the optimum. One function covers them all:

def best_first(start, is_goal, successors, h=lambda s: 0, wg=1, wh=1):
    """Expand the node with the lowest f = wg*g + wh*h.
    wh=0 is uniform-cost search, wg=wh=1 is A*, wg=0 is greedy best-first."""
    frontier = [(wh * h(start), 0, start)]
    parent, g = {start: None}, {start: 0}
    expanded = 0
    while frontier:
        _, cost, s = heapq.heappop(frontier)
        if cost > g[s]:
            continue
        expanded += 1
        if is_goal(s):
            return reconstruct(parent, s), cost, expanded
        for s2, step in successors(s):
            new = cost + step
            if s2 not in g or new < g[s2]:
                g[s2], parent[s2] = new, s
                heapq.heappush(frontier, (wg * new + wh * h(s2), new, s2))
    return None, math.inf, expanded

Heuristics that quietly overestimate

Manhattan distance overestimates when diagonal moves cost 1 (use the larger of the two coordinate differences instead). A distance used with travel-time costs must be divided by the top speed. Either mistake makes A* return longer paths without any error.

Constraint satisfaction

For a timetable, a rota or a Sudoku, only the final arrangement matters. These are constraint satisfaction problems (CSPs): variables, a domain of values for each, and constraints on which combinations are allowed. Backtracking assigns one variable at a time and undoes the latest choice when a constraint breaks. Two additions make it practical. Forward checking removes newly impossible values from neighbouring domains and backs up as soon as one is empty. Minimum remaining values (MRV) assigns the variable with the fewest values left first, so failures come early.

Here is a week of maintenance visits: one job per technician per day, the new belt before calibration, firmware before optics, one site open only on Wednesday, and two jobs sharing a van.

def forward_check(var, a, assignment, domains, cons):
    """Remove values that clash with var=a from unassigned neighbours' domains."""
    pruned = dict(domains)
    for y, ok in cons[var]:
        if y not in assignment:
            pruned[y] = [b for b in domains[y] if ok(a, b)]
            if not pruned[y]:
                return None               # a neighbour has no value left: dead end
    return pruned

def backtrack(domains, cons, assignment=None, fc=True, stats=None):
    assignment = {} if assignment is None else assignment
    if len(assignment) == len(domains):
        return dict(assignment)
    # Most constrained variable first: the one with the fewest values left (MRV)
    unassigned = [v for v in domains if v not in assignment]
    var = min(unassigned, key=lambda v: len(domains[v]))
    for a in domains[var]:
        if all(ok(a, assignment[y]) for y, ok in cons[var] if y in assignment):
            stats["assignments"] += 1
            assignment[var] = a
            pruned = domains
            if fc:
                pruned = forward_check(var, a, assignment, domains, cons)
            if pruned is not None:
                result = backtrack(pruned, cons, assignment, fc, stats)
                if result:
                    return result
            del assignment[var]           # undo, then try the next value
    return None

The industrial versions

Real problems go to mature solvers, and your job is to model them. SAT solvers handle huge true/false formulas in chip and software verification; SMT solvers such as Z3 add arithmetic; constraint and integer programming solvers, such as CP-SAT in Google's open-source OR-Tools, build rosters and delivery routes. This suits LLMs well: the model turns a messy request into a constraint model, and the solver guarantees that the answer satisfies it.

Adversarial search: playing games

In a two-player, zero-sum game such as chess or tic-tac-toe, an opponent picks every other move, and the search has to allow for their replies.

Minimax and alpha-beta pruning

Minimax assumes the opponent always replies with the move that is worst for you, and picks the move whose worst case is best. A finished game is worth +1, 0 or -1 to player X, and every other position takes its value from its children:

\[ V(s) = \max_a V(\text{result}(s, a)) \ \text{if X is to move}, \qquad V(s) = \min_a V(\text{result}(s, a)) \ \text{if O is to move} \]

Alpha-beta pruning tracks \(\alpha\), the score X can already guarantee, and \(\beta\), the score O can already hold X to. Once \(\alpha \ge \beta\), one player will never let the game reach this position, so its remaining moves are skipped. The answer does not change.

from functools import lru_cache

LINES = [(0, 1, 2), (3, 4, 5), (6, 7, 8), (0, 3, 6),
         (1, 4, 7), (2, 5, 8), (0, 4, 8), (2, 4, 6)]

def winner(b):
    for i, j, k in LINES:
        if b[i] != "." and b[i] == b[j] == b[k]:
            return b[i]
    return None

def legal(b):      return [i for i, v in enumerate(b) if v == "."]
def play(b, i, p): return b[:i] + p + b[i + 1:]
def other(p):      return "O" if p == "X" else "X"

def minimax(b, player, alpha=-2, beta=2, prune=True, stats=None):
    """Value of board b for X (+1 win, 0 draw, -1 loss) with `player` to move."""
    stats["nodes"] += 1
    w = winner(b)
    if w or "." not in b:
        return {"X": 1, "O": -1, None: 0}[w]
    values = []
    for i in legal(b):
        v = minimax(play(b, i, player), other(player), alpha, beta, prune, stats)
        values.append(v)
        if player == "X":
            alpha = max(alpha, v)         # X can already guarantee at least alpha
        else:
            beta = min(beta, v)           # O can already hold X to at most beta
        if prune and alpha >= beta:
            break                 # the opponent will never allow this line
    return max(values) if player == "X" else min(values)

for prune in [False, True]:
    stats = {"nodes": 0}
    v = minimax("." * 9, "X", prune=prune, stats=stats)
    print(f"alpha-beta={prune!s:5}  value={v}  nodes searched={stats['nodes']:,}")

# A transposition table: lru_cache solves each distinct position only once
@lru_cache(maxsize=None)
def value(b, player):
    w = winner(b)
    if w or "." not in b:
        return {"X": 1, "O": -1, None: 0}[w]
    vals = [value(play(b, i, player), other(player)) for i in legal(b)]
    return max(vals) if player == "X" else min(vals)

def perfect_move(b, player):
    pick = max if player == "X" else min
    return pick(legal(b), key=lambda i: value(play(b, i, player), other(player)))

Monte Carlo tree search

Go, with around 250 moves per position and no good hand-written evaluation, resisted alpha-beta for decades. Monte Carlo tree search (MCTS) estimates a move's value by playing many fast random games from it, and spends more of them on moves that look promising.

Choosing a child is a multi-armed bandit problem: each move is a slot machine with an unknown payout. UCT (Kocsis and Szepesvári, 2006) picks the child with the highest

\[ \frac{W_i}{N_i} + c\sqrt{\frac{\ln N}{N_i}}, \]

its average result so far (exploitation) plus a bonus for children tried rarely compared with the parent's \(N\) visits (exploration). Lesson returns to this trade-off.

import random

class Node:
    def __init__(self, board, player, parent=None, move=None):
        self.board, self.player, self.parent, self.move = board, player, parent, move
        self.children = []
        self.untried = [] if winner(board) else legal(board)
        # score is from the point of view of the player who moved INTO this node
        self.visits, self.score = 0, 0.0

def uct(child, parent_visits, c):
    return (child.score / child.visits
            + c * math.sqrt(math.log(parent_visits) / child.visits))

def mcts(board, player, iterations=500, c=1.4, rng=random):
    root = Node(board, player)
    for _ in range(iterations):
        node = root
        # 1. Selection: descend through fully expanded nodes by the UCT score
        while not node.untried and node.children:
            node = max(node.children, key=lambda ch: uct(ch, node.visits, c))
        # 2. Expansion: add one untried move as a new child
        if node.untried:
            i = node.untried.pop(rng.randrange(len(node.untried)))
            board = play(node.board, i, node.player)
            child = Node(board, other(node.player), node, i)
            node.children.append(child)
            node = child
        # 3. Simulation: play random moves to the end of the game
        b, p = node.board, node.player
        while not winner(b) and "." in b:
            b, p = play(b, rng.choice(legal(b)), p), other(p)
        w = winner(b)
        # 4. Backpropagation: update every node on the path back to the root
        while node:
            node.visits += 1
            mover = other(node.player)
            node.score += 1.0 if w == mover else 0.5 if w is None else 0.0
            node = node.parent
    return max(root.children, key=lambda ch: ch.visits).move   # the most visited move

def match(x_player, o_player, games, seed=0):
    rng, tally = random.Random(seed), {"X": 0, "O": 0, None: 0}
    for _ in range(games):
        b, p = "." * 9, "X"
        while not winner(b) and "." in b:
            move = (x_player if p == "X" else o_player)(b, p, rng)
            b, p = play(b, move, p), other(p)
        tally[winner(b)] += 1
    return {"X wins": tally["X"], "O wins": tally["O"], "draws": tally[None]}

randomly = lambda b, p, rng: rng.choice(legal(b))
perfectly = lambda b, p, rng: perfect_move(b, p)
for n in [20, 200, 1000]:
    player = lambda b, p, rng, n=n: mcts(b, p, n, rng=rng)
    print(f"perfect X vs MCTS({n:4}) as O:", match(perfectly, player, 20))
player = lambda b, p, rng: mcts(b, p, 200, rng=rng)
print("MCTS( 200) as X vs random O: ", match(player, randomly, 20))

With 1,000 simulations per move MCTS never loses, without knowing anything about strategy, and you can stop it at any time and still get a move.

Whose point of view?

Score each node for the player who moved into it, which is what its parent needs when choosing. Get the perspective wrong and the tree diligently finds the opponent's best moves.

AlphaGo and AlphaZero

AlphaGo, which beat Lee Sedol in 2016, added two neural networks to MCTS: a policy network that suggests moves, first trained on human games, and a value network that estimates who is winning. AlphaZero (Silver et al., 2017) learned from self-play alone and mastered Go, chess and shogi with one algorithm. The policy's prior \(P(s, a)\) steers selection,

\[ a^* = \arg\max_a \left[ Q(s, a) + c\,P(s, a)\,\frac{\sqrt{N(s)}}{1 + N(s, a)} \right], \]

and the value network scores each new leaf in place of a random playout. Training closes the loop: the visit counts from a search are a better policy than the raw network, so the network learns to imitate them and to predict each game's result. Search improves the network, and the network improves the next search. Fast learned intuition plus slow, deliberate search is one of the most important ideas in modern AI, and a close cousin of the extra thinking time that reasoning models spend at inference (lesson ).

Knowledge and logic

Logic writes down what you know so a program can draw conclusions. In propositional logic, facts are symbols that are true or false, and rules combine them. Forward chaining fires every rule whose premises hold and adds its conclusion, until nothing new appears. It was the inference engine of 1980s expert systems.

RULES = [
    ({"no_data", "battery_low"}, "power_fault"),
    ({"no_data", "battery_ok"}, "comms_fault"),
    ({"comms_fault", "modem_light_off"}, "replace_modem"),
    ({"power_fault", "panel_dirty"}, "clean_panel"),
    ({"power_fault"}, "send_spare_battery"),
]

def forward_chain(facts, rules):
    facts = set(facts)
    changed = True
    while changed:                 # fire rules until nothing new appears
        changed = False
        for premises, conclusion in rules:
            if premises <= facts and conclusion not in facts:
                facts.add(conclusion)
                changed = True
                print("  ", " and ".join(sorted(premises)), "=>", conclusion)
    return facts

cases = [{"no_data", "battery_ok", "modem_light_off"},
         {"no_data", "battery_low", "panel_dirty"},
         {"no_data", "modem_light_flashing"}]
for facts in cases:
    print(sorted(facts))
    derived = forward_chain(facts, RULES) - facts
    print("   conclusions:", sorted(derived) or "none")

Every conclusion comes with a reason you can audit, but the third case shows the weakness: nobody anticipated a flashing modem light, so the system says nothing. Rules cannot say "usually" either (MYCIN bolted on "certainty factors" for this), and thousands of them contradict each other and resist maintenance. Use rules where the logic is crisp and must be audited: tax and eligibility calculations, compliance checks, guardrails around a model (lesson ).

Reasoning under uncertainty

Probability is the fix for "usually". Bayes' rule (lesson ) updates a belief with evidence:

\[ P(\text{cause} \mid \text{evidence}) = \frac{P(\text{evidence} \mid \text{cause})\,P(\text{cause})}{P(\text{evidence})} \]

The trouble is scale: a full joint distribution over \(n\) true/false variables needs \(2^n - 1\) numbers.

Bayesian networks

A Bayesian network is a directed graph in which each variable depends only on its parents, so the joint distribution splits into small tables:

\[ P(x_1, \ldots, x_n) = \prod_{i=1}^{n} P\big(x_i \mid \text{parents}(x_i)\big) \]

Here a storm or a hardware fault can silence a station, and a storm also tends to knock out its neighbour: eight numbers instead of fifteen. Inference by enumeration sums the joint over every world consistent with the evidence:

from itertools import product

# node: (parents, P(node is True | each combination of parent values))
NET = {
    "storm":     ((), {(): 0.10}),
    "fault":     ((), {(): 0.02}),
    "outage":    (("storm", "fault"), {(True, True): 0.95, (True, False): 0.30,
                                       (False, True): 0.90, (False, False): 0.01}),
    "neighbour": (("storm",), {(True,): 0.70, (False,): 0.05}),
}

def joint(world):
    """P(world) as the product of each node's probability given its parents."""
    p = 1.0
    for var, (parents, cpt) in NET.items():
        p_true = cpt[tuple(world[q] for q in parents)]
        p *= p_true if world[var] else 1 - p_true
    return p

def query(var, evidence):
    """P(var is True | evidence), by summing the joint over every possible world."""
    totals = {True: 0.0, False: 0.0}
    for values in product([True, False], repeat=len(NET)):
        world = dict(zip(NET, values))
        if all(world[k] == v for k, v in evidence.items()):
            totals[world[var]] += joint(world)
    return totals[True] / (totals[True] + totals[False])

outage = {"outage": True}
cases = {"P(fault)": {},
         "P(fault | outage)": outage,
         "P(fault | outage, neighbour offline)": {**outage, "neighbour": True},
         "P(fault | outage, neighbour online)": {**outage, "neighbour": False}}
for label, evidence in cases.items():
    print(f"{label:36} = {query('fault', evidence):.3f}")
P(fault)                             = 0.020
P(fault | outage)                    = 0.321
P(fault | outage, neighbour offline) = 0.092
P(fault | outage, neighbour online)  = 0.481

The outage lifts the fault probability from 2% to 32%. If the neighbour is down too, a storm explains everything and it falls to 9%; if the neighbour is fine, it rises to 48%. That is explaining away, which if-then rules cannot do. Enumeration is exponential, so real systems use variable elimination or sampling, and tools such as Stan and PyMC run the inference for you.

Naive Bayes

Naive Bayes is the simplest useful Bayesian network: the class is the only parent, and each word depends only on the class. That independence assumption is false and works surprisingly well. Pick the class with the highest score

\[ \log P(c) + \sum_{i} \log P(w_i \mid c), \qquad P(w \mid c) = \frac{\text{count}(w, c) + \alpha}{\sum_{w'} \text{count}(w', c) + \alpha\,|V|} \]

where \(|V|\) is the vocabulary size and \(\alpha\) is Laplace smoothing. From scratch, on 24 hand-written tickets:

import re

    ("temperature sensor spikes every hour", "sensor"),

def tokens(text):
    return re.findall(r"\b\w\w+\b", text.lower())   # the same rule scikit-learn uses

class NaiveBayes:
    def fit(self, texts, labels, alpha=1.0):
        self.classes = sorted(set(labels))
        self.vocab = {w for t in texts for w in tokens(t)}
        self.log_prior, self.log_lik = {}, {}
        for c in self.classes:
            docs = [t for t, y in zip(texts, labels) if y == c]
            counts = Counter(w for t in docs for w in tokens(t))
            self.log_prior[c] = np.log(len(docs) / len(texts))
            # Laplace smoothing: pretend every word was seen alpha extra times
            denom = sum(counts.values()) + alpha * len(self.vocab)
            self.log_lik[c] = {w: np.log((counts[w] + alpha) / denom)
                               for w in self.vocab}
        return self

    def scores(self, text):
        """log P(class) + sum of log P(word | class), skipping words never seen."""
        words = [w for w in tokens(text) if w in self.vocab]
        return {c: self.log_prior[c] + sum(self.log_lik[c][w] for w in words)
                for c in self.classes}

    def predict(self, text):
        s = self.scores(text)
        return max(s, key=s.get)

texts, labels = zip(*TRAIN)
nb = NaiveBayes().fit(texts, labels)
preds = [nb.predict(t) for t, _ in TEST]
accuracy = np.mean([p == y for p, (_, y) in zip(preds, TEST)])
print("from scratch accuracy:", round(accuracy, 2))
for (text, y), p in zip(TEST, preds):

for c in nb.classes:          # words much more likely in this class than in any other

            for w in sorted(nb.vocab)}

Planning

In STRIPS (Fikes and Nilsson, 1971, built for Shakey), a state is the set of facts that are true, and an action has preconditions, an add list and a delete list. The planner is the BFS from session 1, unchanged:

from typing import NamedTuple

class Action(NamedTuple):
    name: str
    pre: frozenset                        # facts that must be true beforehand
    add: frozenset                        # facts the action makes true
    delete: frozenset                     # facts the action makes false

def act(name, pre, add, delete=()):
    return Action(name, frozenset(pre), frozenset(add), frozenset(delete))

ACTIONS = [
    act("load spare part", {"at_depot"}, {"have_part"}),
    act("drive to site", {"at_depot"}, {"at_site"}, {"at_depot"}),
    act("drive to depot", {"at_site"}, {"at_depot"}, {"at_site"}),
    act("power down", {"at_site", "powered"}, {"unpowered"}, {"powered"}),
    act("power up", {"at_site", "unpowered"}, {"powered"}, {"unpowered"}),
    act("fit part", {"at_site", "have_part", "unpowered"}, {"part_fitted"},
        {"have_part"}),
    act("calibrate", {"at_site", "powered", "part_fitted"}, {"calibrated"}),
]

def applicable(state):
    for a in ACTIONS:
        if a.pre <= state:
            yield (state - a.delete) | a.add, a.name

def plan(initial, goal):
    """Breadth-first search over sets of facts, with session 1's search code."""
    succ = lambda s: [(s2, 1) for s2, _ in applicable(s)]
    path, expanded = uninformed_search(frozenset(initial), lambda s: goal <= s, succ)
    # Recover the action that links each pair of consecutive states
    names = [next(n for s2, n in applicable(s) if s2 == t)
             for s, t in zip(path, path[1:])]
    return names, expanded

steps, n = plan({"at_depot", "powered"}, {"part_fitted", "calibrated", "at_depot"})
for i, step in enumerate(steps, 1):
    print(i, step)
print(n, "states expanded")
1 load spare part
2 drive to site
3 power down
4 fit part
5 power up
6 calibrate
7 drive to depot
17 states expanded

Nobody wrote that sequence down; the planner derived it, including powering down before fitting the part. With \(k\) facts there are up to \(2^k\) states, so real planners compute heuristics automatically, for example by ignoring delete lists: the same relaxation trick that gave you Manhattan distance. The standard language today is PDDL, read by planners such as Fast Downward.

Classical AI inside LLM agents

An LLM agent (lesson ) has the strengths classical AI lacked, language and common sense, and the opposite weaknesses: it guesses, it is not exhaustive and it guarantees nothing. Strong systems pair the two.

  • The LLM models, a solver solves. The model writes the constraint model, PDDL problem or SQL, and a solver returns an answer that is correct by construction. LLM+P (2023) did this for planning.
  • Search over the model's outputs. Tree of Thoughts (Yao et al., 2023) runs BFS or DFS over partial solutions, with the LLM as successor function and heuristic. Best-of-\(n\) sampling with a scorer is the simplest case.
  • Generate, then verify. Tests for code, schemas for structured output, proof checkers for maths. AlphaGeometry (2024) paired a language model with a symbolic deduction engine.
  • Plan, act, check, replan. Check each step's preconditions before acting, and replan when an observation contradicts the plan.

It is the AlphaZero split again: a learned model proposes, and search and verification make the result reliable.

Hands-on: check a plan before you run it

  1. Write validate(initial, goal, steps). It applies the named actions one at a time and returns (True, "goal reached"), or False with the first step whose preconditions fail and the missing facts.
  2. Validate the planner's plan, then this one, as if an LLM had proposed it: ["load spare part", "drive to site", "fit part", "calibrate", "drive to depot"].
  3. Add an action log visit that needs at_depot and calibrated and adds logged. Add logged to the goal, replan and validate.

You are done when the proposed plan fails at step 3 because unpowered is missing, and the new plan has eight steps.

Show what you should find

Before each step compute a.pre - state; if it is empty, apply the delete and add lists. The solutions notebook prints:

Check yourself

You need the shortest drive across a map whose roads have different lengths. Why is BFS the wrong tool?

  • It cannot handle maps with loops
  • It finds the route with the fewest roads, which need not be the shortest in kilometres
  • It always runs out of memory on maps
  • It only works on grids

BFS is optimal only when every step costs the same. UCS and A* order the frontier by path cost.

What does an admissible heuristic guarantee when used with A*?

  • Fewer expansions than greedy search
  • That the heuristic equals the true remaining cost
  • An optimal path, because the heuristic never overestimates
  • That no priority queue is needed

A state on the best path never has \(f\) above the optimal cost, so A* cannot pop the goal by a worse route first.

Compared with plain minimax, what does alpha-beta pruning change?

  • It returns the same value while skipping branches that cannot affect the decision
  • It returns an approximate value
  • It only works for games with dice
  • It needs a learned evaluation function

Pruning is exact: 18,297 nodes instead of 549,946, and still a draw.

In AlphaZero, what replaces the random playouts of classic MCTS?

  • Many more random playouts
  • Alpha-beta search to the end of the game
  • A database of human expert games
  • A value network that scores the new leaf, with a policy network guiding selection

The value head evaluates leaves and the policy head supplies priors. Self-play trains both on the results of search.

A hand-written Naive Bayes classifier gives "power" a probability of exactly zero for a ticket about batteries, because one of its words never appeared in a power ticket. What fixes it?

  • Removing the class prior
  • Laplace smoothing: add a small count \(\alpha\) for every word in every class
  • Multiplying probabilities instead of adding logs
  • Training on fewer examples

Without smoothing, one unseen word has \(P(w \mid c) = 0\), which wipes out the whole product.

Key takeaways

  • Write a problem as states, actions, a goal test and path costs, and BFS, DFS, UCS and A* all apply; they differ only in which frontier state they expand next.
  • UCS is optimal for non-negative costs; A* adds an admissible heuristic, \(f = g + h\), to stay optimal while expanding far fewer states. Test for the goal on expansion.
  • Backtracking with forward checking and MRV solves small CSPs; in production, model the problem for a solver such as OR-Tools.
  • Alpha-beta is exact and far cheaper than minimax. MCTS replaces evaluation with simulation, and AlphaZero replaces simulation with policy and value networks.
  • Rules are auditable but brittle; Bayesian networks handle uncertainty and explaining away; Naive Bayes is a fast text baseline.
  • Strong LLM systems use the AlphaZero split: a learned model proposes, and search, solvers and verifiers make the result reliable.
