What a generative model is

A classifier learns \(p(y \mid x)\): given an image, which digit is it? A generative model learns \(p(x)\) itself: what do images of digits look like at all? Once you have a good model of \(p(x)\), you can do two different jobs with it.

  • Density estimation: score how plausible a given example is. This is useful for anomaly detection, compression and comparing models.
  • Sampling: draw new examples that look like the training data. This is what people usually mean by "generative AI".

Some models do both jobs. An LLM is one: it gives the exact probability of any text, token by token, and samples new text the same way (lesson ). Others can only sample. A GAN can draw a convincing face but cannot tell you how probable a given face is. Models that can compute \(p(x)\) have an explicit likelihood; models that can only sample define it implicitly.

Models with an explicit likelihood are usually trained by maximum likelihood: choose parameters \(\theta\) that make the training data as probable as possible,

\[ \theta^\star = \arg\max_\theta \sum_{i} \log p_\theta(x_i), \]

which is the same as minimising the KL divergence from the data distribution to the model (lesson ). The simplest model that does both jobs is one you have met already: a Gaussian mixture.

import numpy as np
from sklearn.datasets import make_moons
from sklearn.mixture import GaussianMixture

moons, _ = make_moons(2000, noise=0.05, random_state=0)
gmm = GaussianMixture(n_components=8, random_state=0).fit(moons[:1500])

# job 1, density: log p(x) for a point on a moon and a point far away
print(gmm.score_samples([[0.0, 1.0], [0.0, 3.0]]).round(1))
print(round(gmm.score(moons[1500:]), 3))   # mean log p(x) on held-out points

# job 2, sampling: new points that look like the data
new_points, _ = gmm.sample(3)
print(new_points.round(2))

-0.437
[[ 1.1  -0.55]

A point on a moon scores \(\log p(x) = -0.2\); a point far from the data scores −69.6, a probability density of about \(e^{-70}\). The held-out average, −0.437 nats per point, is a number to beat in session 3. Mixtures stop working when the data has thousands of dimensions with intricate structure, such as images and audio. Deep generative models learn \(p_\theta(x)\) with neural networks instead, and the families differ mainly in how they make that learning tractable.

The map of model families

In practice the families are combined. A latent diffusion model is a VAE whose latents are modelled by diffusion, and its decoder is usually trained with a GAN loss. An image or audio tokenizer is a vector-quantised autoencoder whose tokens an autoregressive transformer then models. This lesson builds one of each (except energy-based models) at toy scale, so you can see what each piece contributes.

Autoencoders

Compress and reconstruct

An autoencoder has two halves. The encoder \(f\) squeezes an input \(x\) into a short code \(z = f(x)\); the decoder \(g\) rebuilds the input from the code. Training minimises the reconstruction error \(\lVert x - g(f(x)) \rVert^2\). The narrow code, the bottleneck, is what makes this useful: the network cannot copy pixels through, so it must learn the structure that lets it describe a digit in a few numbers.

An autoencoder is not yet a generative model, because nothing in it defines \(p(x)\). It is the building block for two that are: the VAE in session 2 and latent diffusion in session 3. We will use scikit-learn's bundled 8×8 digits throughout, plus a digit classifier as a rough judge of generated images. A classifier's confidence on samples is a crude quality signal; session 3 refines this idea into FID.

import torch
import torch.nn as nn
import torch.nn.functional as F

from sklearn.model_selection import train_test_split

digits = load_digits()
X = digits.data / 16.0       # 1,797 images of 8x8 pixels, scaled to [0, 1]
X_tr, X_te, y_tr, y_te = train_test_split(
    X, digits.target, test_size=0.25, random_state=0, stratify=digits.target)
Xtr = torch.tensor(X_tr, dtype=torch.float32)
Xte = torch.tensor(X_te, dtype=torch.float32)

# a classifier that will act as a judge of generated digits
judge = LogisticRegression(max_iter=2000).fit(X_tr, y_tr)

def judge_report(images):
    """Mean confidence of the judge, and how many images it calls each digit."""
    p = judge.predict_proba(np.clip(images, 0, 1))
    counts = np.bincount(p.argmax(1), minlength=10)
    return round(float(p.max(1).mean()), 2), counts.tolist()

print(round(judge.score(X_te, y_te), 3))
print(judge_report(X_te))

(0.9, [45, 52, 43, 45, 43, 47, 43, 47, 41, 44])

The judge gets 96.9% of real test digits right, with an average confidence of 0.9, and the test set holds 41 to 52 of each digit. That is what "looks like a real digit" means in numbers. Now the autoencoder, with a two-number code so we can look at it.

class AutoEncoder(nn.Module):
    def __init__(self, d_latent=2):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(64, 128), nn.ReLU(),
                                     nn.Linear(128, d_latent))
        self.decoder = nn.Sequential(nn.Linear(d_latent, 128), nn.ReLU(),
                                     nn.Linear(128, 64), nn.Sigmoid())

    def forward(self, x):
        return self.decoder(self.encoder(x))

def fit(model, loss_fn, epochs=100, lr=2e-3, batch=128):
    """Minibatch training on the digit images; loss_fn(model, x) -> loss."""
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    for epoch in range(epochs):
        for idx in torch.randperm(len(Xtr)).split(batch):
            loss = loss_fn(model, Xtr[idx])
            opt.zero_grad(); loss.backward(); opt.step()
    return model

torch.manual_seed(0)
ae = fit(AutoEncoder(), lambda m, x: F.mse_loss(m(x), x))

from sklearn.decomposition import PCA
pca = PCA(n_components=2).fit(X_tr)           # the linear baseline
pca_recon = pca.inverse_transform(pca.transform(X_te))
with torch.no_grad():
    print("autoencoder", round(F.mse_loss(ae(Xte), Xte).item(), 4))
print("PCA        ", round(((pca_recon - X_te) ** 2).mean(), 4))

PCA is a linear autoencoder: with squared error, the best linear encoder and decoder span the same subspace as the top principal components (lesson ). With the same two numbers per image, the non-linear autoencoder reconstructs with error 0.038 against PCA's 0.053.

The latent space

The codes live in a latent space. Plot them (the notebook does) and you see a cluster for each digit, with gaps between. Can we generate by decoding random codes?

Mostly no. Training put the codes wherever was convenient, centred near (1.75, −0.93) with a spread of about 3, so a standard normal only samples a small patch in the middle. The judge's confidence drops to 0.62, and out of 1,000 samples it finds 1 four, 0 sevens and 9 nines. A plain autoencoder gives you a decoder but no distribution over codes to sample from, and decoding a code from a region it never saw produces a smudge. The VAE fixes exactly this.

Reconstructions flatter a generator

Reconstructions always look good, because the encoder picked the code. The only fair test of a generator is to decode codes drawn from the distribution you will actually sample from.

Denoising autoencoders

A denoising autoencoder is given a corrupted input and trained to output the clean original. It can no longer get away with copying; it has to learn which way is "back towards real data" from any nearby point.

def denoising_loss(model, x, noise=0.3):
    noisy = x + noise * torch.randn_like(x)    # corrupt the input...
    return F.mse_loss(model(noisy), x)         # ...but score against the clean x

torch.manual_seed(0)
plain = fit(AutoEncoder(d_latent=16), lambda m, x: F.mse_loss(m(x), x))
dae = fit(AutoEncoder(d_latent=16), denoising_loss)

torch.manual_seed(2)
noisy_te = Xte + 0.3 * torch.randn_like(Xte)
with torch.no_grad():
    for name, m in [("plain", plain), ("denoising", dae)]:
        print(f"{name:9s} clean in: {F.mse_loss(m(Xte), Xte).item():.4f}  "
              f"noisy in: {F.mse_loss(m(noisy_te), Xte).item():.4f}")
plain     clean in: 0.0070  noisy in: 0.0404
denoising clean in: 0.0112  noisy in: 0.0197

The denoiser is a little worse on clean inputs (0.0112 against 0.0070) and halves the error on noisy ones (0.0197 against 0.0404). Knowing which way leads back to the data is knowledge about the shape of \(p(x)\), and Pascal Vincent showed in 2011 that training a denoiser is closely related to estimating the gradient of \(\log p(x)\). Train one network to denoise at every noise level, from a light sprinkle to pure static, and you have a diffusion model. That is session 3.

Variational autoencoders

A latent-variable model

A variational autoencoder (Kingma and Welling, 2013) starts from a story about how the data was made: first pick a code \(z\) from a simple prior \(p(z) = \mathcal{N}(0, I)\), then generate \(x\) from \(p_\theta(x \mid z)\), a decoder network. The probability of an image is then an average over all codes that could have produced it:

\[ p_\theta(x) = \int p_\theta(x \mid z)\, p(z)\, dz . \]

Sampling is easy: draw \(z\), decode. Training by maximum likelihood is not, because the integral runs over every possible \(z\), and for any particular image almost every random \(z\) explains it terribly. The fix is a second network, the encoder \(q_\phi(z \mid x)\), which proposes the codes that are likely for a given \(x\). It outputs a mean \(\mu\) and a standard deviation \(\sigma\) for each latent dimension.

The ELBO, gently

Multiply and divide inside the integral by \(q_\phi(z \mid x)\), so it becomes an average over codes drawn from the encoder, then use Jensen's inequality (the log of an average is at least the average of the logs):

\[ \log p_\theta(x) = \log \mathbb{E}_{q_\phi(z\mid x)}\!\left[\frac{p_\theta(x \mid z)\,p(z)}{q_\phi(z \mid x)}\right] \;\ge\; \underbrace{\mathbb{E}_{q_\phi(z\mid x)}\big[\log p_\theta(x \mid z)\big]}_{\text{reconstruction}} \;-\; \underbrace{D_{\mathrm{KL}}\big(q_\phi(z \mid x)\,\|\,p(z)\big)}_{\text{stay near the prior}} . \]

The right-hand side is the evidence lower bound, or ELBO. The gap between it and the true log-likelihood is exactly \(D_{\mathrm{KL}}(q_\phi(z \mid x)\,\|\,p_\theta(z \mid x))\), so raising the ELBO both improves the model and makes the encoder a better guess at the true posterior. Read the two terms as opposing forces. Reconstruction wants each code to pin down its image precisely. The KL term wants every code distribution to look like \(\mathcal{N}(0, I)\), which packs the codes together around the origin with no gaps. That second force is what was missing from the plain autoencoder. For a Gaussian encoder the KL term has a closed form:

\[ D_{\mathrm{KL}} = \tfrac{1}{2}\sum_j \left(\mu_j^2 + \sigma_j^2 - \log \sigma_j^2 - 1\right). \]

The reparameterisation trick

There is one obstacle. Backpropagation cannot pass through "draw \(z\) from \(\mathcal{N}(\mu, \sigma^2)\)", because a random draw has no derivative with respect to \(\mu\). The reparameterisation trick rewrites the draw as \(z = \mu + \sigma \odot \varepsilon\) with \(\varepsilon \sim \mathcal{N}(0, I)\). The randomness becomes an input, and \(z\) is an ordinary differentiable function of \(\mu\) and \(\sigma\).

class VAE(nn.Module):
    def __init__(self, d_latent=2):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(64, 128), nn.ReLU(),
                                     nn.Linear(128, 2 * d_latent))  # mu, log var
        self.decoder = nn.Sequential(nn.Linear(d_latent, 128), nn.ReLU(),
                                     nn.Linear(128, 64))            # pixel logits

    def encode(self, x):
        mu, logvar = self.encoder(x).chunk(2, dim=1)
        return mu, logvar

    def forward(self, x):
        mu, logvar = self.encode(x)
        eps = torch.randn_like(mu)
        z = mu + torch.exp(0.5 * logvar) * eps     # the reparameterisation trick
        return self.decoder(z), mu, logvar

def elbo_terms(model, x):
    logits, mu, logvar = model(x)
    # reconstruction: -log p(x|z) under a Bernoulli per pixel, summed over pixels
    recon = F.binary_cross_entropy_with_logits(logits, x, reduction="sum")
    # KL(q(z|x) || N(0, I)) in closed form, summed over latent dimensions
    kl = 0.5 * (mu ** 2 + logvar.exp() - logvar - 1).sum()
    return recon / len(x), kl / len(x)          # both per image

def vae_loss(model, x, beta=1.0):
    recon, kl = elbo_terms(model, x)
    return recon + beta * kl                    # the negative ELBO when beta = 1

Three details here prevent the most common VAE bugs. The encoder predicts \(\log \sigma^2\) rather than \(\sigma\), so any real output is valid. The decoder returns logits and the loss applies the sigmoid itself, as in lesson . And both terms are summed over their dimensions before averaging over the batch: if you average the reconstruction over 64 pixels but sum the KL, the KL is effectively 64 times too strong and the model learns to ignore its codes.

The KL term pulled the codes onto the prior: their mean is now about 0 and their spread about 1, so codes drawn from \(\mathcal{N}(0, I)\) land where the decoder was trained. Every digit appears among the samples, from 32 ones up to 127 fours, where the autoencoder produced almost no fours or sevens. Notice what did not improve: the judge's confidence, 0.63, is no higher than before. VAE samples are blurry. Each code carries at most about 2.2 nats (3 bits) of information about its image, and the decoder scores every pixel independently, so it hedges with averaged strokes.

Because the latent space has no gaps, you can walk through it. Take the codes of a test 0 and a test 6 and decode points on the straight line between them:

i, j = np.where(y_te == 0)[0][0], np.where(y_te == 6)[0][0]

    mu, _ = vae.encode(Xte[[i, j]])
    path = torch.stack([(1 - a) * mu[0] + a * mu[1]
                        for a in torch.linspace(0, 1, 8)])

β-VAE and disentanglement

Weighting the KL term by a factor \(\beta\) gives the β-VAE (Higgins et al., 2017). With \(\beta > 1\), the stronger pull towards an independent Gaussian prior can make individual latent dimensions line up with separate factors of variation, such as slant or stroke thickness. This is called disentanglement. It costs reconstruction quality, and later work showed it cannot be guaranteed without extra assumptions or supervision. Push \(\beta\) too far and the KL term wins outright: train fit(VAE(), lambda m, x: vae_loss(m, x, beta=4.0)) and the KL falls to 0.00, the decoder ignores \(z\), and all 1,000 samples are the same average blob, which the judge calls an 8. This failure is posterior collapse. Going the other way, the autoencoders inside latent diffusion models use a very small KL weight, because a diffusion model, not the Gaussian prior, will model their latents.

VQ-VAE: discrete latents

The VQ-VAE (van den Oord et al., 2017) replaces the Gaussian code with a lookup table. The encoder outputs a grid of vectors, and each vector is snapped to the nearest of \(K\) learnt codebook vectors. The image becomes a grid of integers, one codebook index per position. Snapping has no useful gradient, so the straight-through estimator passes the decoder's gradient to the encoder as if the snap were not there. Two extra losses move the codebook towards the encoder outputs and keep the encoder committed to its codes.

def quantise(z, codebook):
    """Snap each row of z to its nearest codebook vector, as in a VQ-VAE."""
    idx = torch.cdist(z, codebook).argmin(dim=1)   # one integer token per row
    z_q = codebook[idx]
    vq_loss = (F.mse_loss(z_q, z.detach())            # move codes to the encoder
               + 0.25 * F.mse_loss(z, z_q.detach()))  # keep encoder near its code
    z_st = z + (z_q - z).detach()   # straight-through: forward z_q, gradient to z
    return z_st, idx, vq_loss

torch.manual_seed(0)
codebook = torch.randn(16, 4, requires_grad=True)   # K = 16 codes of size 4
z = torch.randn(6, 4, requires_grad=True)           # six encoder outputs
z_q, idx, vq_loss = quantise(z, codebook)
print(idx)                     # the "image" is now six integer tokens
z_q.sum().backward()
print(z.grad[0])               # ones: the gradient passed straight through
tensor([12, 10,  9,  7,  4,  2])
tensor([1., 1., 1., 1.])

Discrete latents matter because once an image or a sound is a sequence of integers, a transformer can model it exactly like text, with next-token prediction (lesson ). Neural audio codecs such as SoundStream and EnCodec turn audio into tokens with residual vector quantisation (several codebooks, each quantising what the previous one missed), and speech and music generators predict those tokens. VQGAN-style tokenizers do the same for images. The tokenizer is a generative model in its own right, and the quality of its decoder caps the quality of everything built on top.

Generative adversarial networks

The game

A GAN (Goodfellow et al., 2014) gives up on likelihood altogether. A generator \(G\) turns noise \(z\) into a sample. A discriminator \(D\) looks at a sample and outputs the probability that it is real. They play a game: \(D\) is trained to tell real from fake, and \(G\) is trained to fool \(D\). Think of a counterfeiter and an inspector, each improving because the other does.

\[ \min_G \max_D \;\; \mathbb{E}_{x \sim p_{\text{data}}}\big[\log D(x)\big] + \mathbb{E}_{z \sim p(z)}\big[\log\big(1 - D(G(z))\big)\big] \]

The original paper shows that for a fixed generator the best discriminator is \(D^\star(x) = p_{\text{data}}(x) / (p_{\text{data}}(x) + p_G(x))\), and against that discriminator the generator is minimising the Jensen-Shannon divergence between the data and its own distribution. The same paper points out a practical problem. Early in training \(D\) rejects fakes easily, \(\log(1 - D(G(z)))\) is flat near \(D = 0\), and \(G\) gets almost no gradient. The fix is the non-saturating loss: train \(G\) to maximise \(\log D(G(z))\) instead. It has the same goal but strong gradients exactly when the generator is bad. In code, that means scoring the fakes against the "real" label.

A GAN on eight Gaussians

Images make GAN failures hard to see, so we use a classic 2-D test: eight tight Gaussian blobs on a ring. A helper counts how many of the eight modes a model's samples reach, and what share of samples land within three standard deviations of some mode. We will reuse it for diffusion and flow matching.

angles = torch.arange(8) * 2 * torch.pi / 8
CENTRES = 2.0 * torch.stack([angles.cos(), angles.sin()], dim=1)   # (8, 2)

def sample_ring(n, std=0.05):
    return CENTRES[torch.randint(0, 8, (n,))] + std * torch.randn(n, 2)

def mode_report(x, std=0.05):
    """Modes that get at least 1% of samples, and the share of good samples."""
    d = torch.cdist(x, CENTRES)                  # distance to every centre
    good = d.min(1).values < 3 * std             # within 3 std of some mode
    counts = torch.bincount(d.argmin(1)[good], minlength=8)
    return int((counts >= 0.01 * len(x)).sum()), round(good.float().mean().item(), 2)

def mlp(n_in, n_out, hidden=128, depth=2):
    layers, d = [], n_in
    for _ in range(depth):
        layers += [nn.Linear(d, hidden), nn.ReLU()]
        d = hidden
    return nn.Sequential(*layers, nn.Linear(d, n_out))

torch.manual_seed(0)
print(mode_report(sample_ring(1000)))   # real data: all 8 modes, 99% good
(8, 0.99)
def train_gan(steps=3000, batch=256, lr=1e-3, betas=(0.9, 0.999)):
    G, D = mlp(2, 2), mlp(2, 1)      # D returns a logit: "how real is this?"
    opt_g = torch.optim.Adam(G.parameters(), lr=lr, betas=betas)
    opt_d = torch.optim.Adam(D.parameters(), lr=lr, betas=betas)
    bce = nn.BCEWithLogitsLoss()
    real_label, fake_label = torch.ones(batch, 1), torch.zeros(batch, 1)
    for step in range(1, steps + 1):
        real, fake = sample_ring(batch), G(torch.randn(batch, 2))
        # 1. discriminator: push D(real) towards 1 and D(fake) towards 0
        d_loss = bce(D(real), real_label) + bce(D(fake.detach()), fake_label)
        opt_d.zero_grad(); d_loss.backward(); opt_d.step()
        # 2. generator (non-saturating loss): make D call the fakes real
        g_loss = bce(D(fake), real_label)
        opt_g.zero_grad(); g_loss.backward(); opt_g.step()
        if step % 500 == 0:
            with torch.no_grad():
                print(step, mode_report(G(torch.randn(1000, 2))))
    return G

torch.manual_seed(8)

Read the log line by line. At step 500 the samples crowd onto one side of the ring and almost none land on a mode; at 1,000 they have spread out but still sit between the modes. By the end the samples are sharp (73% land on a mode) but cover only five of the eight modes, and the notebook's plot shows the shape of the failure: about four in five samples pile up near two modes, while the mode between them gets none. That is mode collapse, here in its partial form. The generator is rewarded for fooling the current discriminator, not for covering the data. If one region fools \(D\) best, \(G\) moves its samples there; \(D\) learns to reject that region; \(G\) hops elsewhere. Nothing in the loss directly rewards diversity. Rerun with a different seed and the details change, sometimes eight modes, sometimes one. That sensitivity is the practical problem with GANs.

Making GANs train

A decade of practice produced a toolbox of fixes:

  • The non-saturating generator loss, already used above.
  • Lower momentum in Adam: the DCGAN paper (Radford et al., 2015) found the default \(\beta_1 = 0.9\) caused oscillation and recommended 0.5.
  • Spectral normalisation (Miyato et al., 2018) rescales each discriminator weight matrix so the discriminator cannot change too sharply, which keeps its gradients informative. In PyTorch it is one wrapper, nn.utils.parametrizations.spectral_norm.
  • Wasserstein GANs (Arjovsky et al., 2017) replace the discriminator with a critic that estimates the Wasserstein distance, which still gives useful gradients when the real and fake distributions do not overlap. The gradient penalty version, WGAN-GP (Gulrajani et al., 2017), keeps the critic smooth by penalising gradient norms away from 1.
  • Separate learning rates for the two players (the two time-scale update rule, Heusel et al., 2017, the paper that also introduced FID).

Watch samples, not losses

GAN losses do not fall steadily as the generator improves, because each player's loss depends on the other. Log a sample-based metric, as mode_report does here, and look at pictures.

Where GANs still win

Diffusion models overtook GANs for image synthesis around 2021 (Dhariwal and Nichol's paper is titled "Diffusion Models Beat GANs on Image Synthesis"), mainly on diversity and training stability. GANs remain the right tool when you need an output in a single network call: real-time synthesis, video-game textures, and super-resolution, where models such as ESRGAN sharpen images. The adversarial loss also lives on inside other models. The autoencoders of latent diffusion are trained with a GAN loss so their decoders produce crisp detail, and SD-Turbo, the one-step generator from lesson , was distilled from a diffusion model with an adversarial loss.

Normalising flows

The change of variables formula

A normalising flow builds a complicated density by warping a simple one with an invertible function. Take a one-dimensional example first: if a function doubles every number, the probability mass spreads over twice the length, so the density halves everywhere. In general, if an invertible function \(f\) maps data \(x\) to noise \(z = f(x)\) with \(z \sim \mathcal{N}(0, I)\), then

\[ \log p_X(x) = \log p_Z\big(f(x)\big) + \log \left| \det \frac{\partial f(x)}{\partial x} \right| . \]

The first term asks how likely the noise is; the second corrects for how much \(f\) stretches or squeezes space around \(x\). Train \(f\) by maximum likelihood with this exact formula, then sample by drawing \(z\) and running \(f\) backwards. The design problem is that \(f\) must be invertible and its Jacobian determinant must be cheap: for a general \(D \times D\) matrix the determinant costs on the order of \(D^3\) operations.

An affine coupling layer

The coupling layer from RealNVP (Dinh et al., 2016) solves both problems with a trick. Split \(x\) into two halves \((a, b)\). Leave \(a\) alone, and scale and shift \(b\) by amounts computed from \(a\):

\[ z_a = a, \qquad z_b = b \odot e^{s(a)} + t(a), \qquad \log\left|\det J\right| = \textstyle\sum s(a). \]

Inverting it needs no inverse of \(s\) or \(t\): \(b = (z_b - t(a)) \odot e^{-s(a)}\). The Jacobian is triangular, so its log-determinant is just the sum of the log-scales. Because \(s\) and \(t\) are never inverted, they can be any neural network. Stack several layers, alternating which half is changed, and the flow can bend space in both directions.

class Coupling(nn.Module):
    """Affine coupling: keep one coordinate, scale and shift the other."""
    def __init__(self, flip):
        super().__init__()
        self.flip = flip
        self.net = mlp(1, 2, hidden=64)      # outputs log-scale s and shift t

    def split(self, x):
        a, b = x[:, :1], x[:, 1:]
        return (b, a) if self.flip else (a, b)

    def join(self, a, b):
        return torch.cat([b, a] if self.flip else [a, b], dim=1)

    def forward(self, x):                    # data -> noise, with log|det J|
        a, b = self.split(x)
        s, t = self.net(a).chunk(2, dim=1)
        s = torch.tanh(s)                    # keep the scale factors tame
        return self.join(a, b * torch.exp(s) + t), s.squeeze(1)

    def inverse(self, z):                    # noise -> data
        a, b = self.split(z)
        s, t = self.net(a).chunk(2, dim=1)
        s = torch.tanh(s)
        return self.join(a, (b - t) * torch.exp(-s))

class Flow(nn.Module):
    def __init__(self, n_layers=8):
        super().__init__()
        self.layers = nn.ModuleList(Coupling(flip=i % 2 == 1)
                                    for i in range(n_layers))

    def forward(self, x):                    # data -> noise, summing log|det J|
        log_det = torch.zeros(len(x))
        for layer in self.layers:
            x, ld = layer(x)
            log_det = log_det + ld
        return x, log_det

    def inverse(self, z):                    # noise -> data
        for layer in reversed(self.layers):
            z = layer.inverse(z)
        return z

    def log_prob(self, x):                   # the change of variables formula
        z, log_det = self(x)
        return -0.5 * (z ** 2).sum(1) - np.log(2 * np.pi) + log_det

Diffusion from scratch

Lesson gave the intuition and the forward process: mix data with noise according to a schedule, \(x_t = \sqrt{\bar\alpha_t}\,x_0 + \sqrt{1-\bar\alpha_t}\,\varepsilon\), and train a network \(\varepsilon_\theta(x_t, t)\) to predict the noise with the loss \(\lVert \varepsilon - \varepsilon_\theta(x_t, t)\rVert^2\). Here is the whole loop, on the ring that defeated the GAN. Generation, called ancestral sampling, starts from pure noise and takes \(T\) small denoising steps (Ho et al., 2020):

\[ x_{t-1} = \frac{1}{\sqrt{\alpha_t}}\left(x_t - \frac{\beta_t}{\sqrt{1-\bar\alpha_t}}\,\varepsilon_\theta(x_t, t)\right) + \sigma_t\, \mathbf{n}, \qquad \mathbf{n} \sim \mathcal{N}(0, I), \]

where \(\alpha_t = 1 - \beta_t\). The added noise \(\sigma_t\) can be \(\sqrt{\beta_t}\) or the variance of the true reverse step, \(\tilde\beta_t = \beta_t(1-\bar\alpha_{t-1})/(1-\bar\alpha_t)\). The DDPM paper found the two similar on images; on this tiny dataset \(\tilde\beta_t\) gives noticeably sharper samples, so we use it.

T = 100
betas = torch.linspace(1e-4, 0.2, T)   # linear schedule, rescaled for 100 steps
alphas = 1 - betas
alpha_bar = torch.cumprod(alphas, dim=0)
alpha_bar_prev = torch.cat([torch.ones(1), alpha_bar[:-1]])
sigma2 = betas * (1 - alpha_bar_prev) / (1 - alpha_bar)    # posterior variance

torch.manual_seed(0)
eps_model = mlp(3, 2, depth=3)          # input: (x_t, t/T), output: predicted noise
opt = torch.optim.Adam(eps_model.parameters(), lr=1e-3)
for step in range(4000):
    x0 = sample_ring(256)
    t = torch.randint(0, T, (256,))
    eps = torch.randn_like(x0)
    ab = alpha_bar[t].unsqueeze(1)
    xt = ab.sqrt() * x0 + (1 - ab).sqrt() * eps            # forward process
    pred = eps_model(torch.cat([xt, t.unsqueeze(1) / T], dim=1))
    loss = F.mse_loss(pred, eps)
    opt.zero_grad(); loss.backward(); opt.step()

@torch.no_grad()
def ddpm_sample(n):
    x = torch.randn(n, 2)                                   # start from pure noise
    for t in reversed(range(T)):
        eps = eps_model(torch.cat([x, torch.full((n, 1), t / T)], dim=1))
        x = (x - betas[t] / (1 - alpha_bar[t]).sqrt() * eps) / alphas[t].sqrt()
        if t > 0:
            x = x + sigma2[t].sqrt() * torch.randn_like(x)  # fresh noise
    return x

torch.manual_seed(1)
print(mode_report(ddpm_sample(1000)))
(8, 0.85)

All eight modes, 85% of samples on a mode, with no adversary, no tricks and a plain regression loss that falls steadily. The DDPM loss is a reweighted form of the ELBO, so like any likelihood-based objective it is penalised for missing part of the data, whereas the GAN was only penalised for being caught. The price is paid at sampling time: 100 network calls per sample against the GAN's one. Two details matter in this code. The network is told the time step, here simply as \(t/T\), because the right correction depends on how noisy the input is. And the final step adds no noise.

Flow matching and rectified flow

Flow matching (Lipman et al., 2022) and the closely related rectified flow (Liu et al., 2022) keep the recipe "corrupt the data, regress a simple target" and strip out the noise schedule. Draw noise \(x_0 \sim \mathcal{N}(0, I)\), a data point \(x_1\) and a time \(t \in [0, 1]\). Take the point on the straight line between them, and train a network to predict the velocity along that line:

\[ x_t = (1 - t)\,x_0 + t\,x_1, \qquad \mathcal{L} = \big\lVert v_\theta(x_t, t) - (x_1 - x_0) \big\rVert^2 . \]

Many lines pass through any given point, so the network learns their average direction there. That averaged velocity field defines a flow whose paths never cross and which carries the noise distribution onto the data distribution. To generate, start from noise and integrate \(dx/dt = v_\theta(x, t)\) from \(t = 0\) to \(t = 1\), here with simple Euler steps.

torch.manual_seed(0)
v_model = mlp(3, 2, depth=3)            # input: (x_t, t), output: velocity
opt = torch.optim.Adam(v_model.parameters(), lr=1e-3)
for step in range(4000):
    x1 = sample_ring(256)                        # data
    x0 = torch.randn_like(x1)                    # noise
    t = torch.rand(256, 1)
    xt = (1 - t) * x0 + t * x1                   # a point on the straight line
    loss = F.mse_loss(v_model(torch.cat([xt, t], dim=1)), x1 - x0)
    opt.zero_grad(); loss.backward(); opt.step()

@torch.no_grad()
def fm_sample(n, n_steps):
    x = torch.randn(n, 2)
    for i in range(n_steps):                     # Euler steps from t=0 to t=1
        t = torch.full((n, 1), i / n_steps)
        x = x + v_model(torch.cat([x, t], dim=1)) / n_steps
    return x

torch.manual_seed(1)
for n_steps in [1, 5, 20, 100]:
    print(n_steps, mode_report(fm_sample(1000, n_steps)))

With one step, every sample lands in the empty centre of the ring: at \(t = 0\) the best guess of the velocity points from the noise to the average data point, which is the middle. Five steps reach all eight modes, and twenty are as good as a hundred. The sampler is deterministic, the paths are nearly straight so few steps are needed, and there is no \(\bar\alpha_t\) bookkeeping. Many recent image and video generators are trained this way; Stable Diffusion 3, for example, uses rectified flow. Distillation methods attack the remaining cost by teaching a student to cover many steps in one.

Latent diffusion and autoregressive models

Latent diffusion (Rombach et al., 2022) combines the pieces of this lesson. An autoencoder compresses each image into a smaller grid of latents, typically eight times smaller on each side, trained with a small KL term, a perceptual loss and a GAN loss. The diffusion or flow-matching model then works entirely in that latent space, which makes it far cheaper, and the decoder turns its output back into pixels. The last exercise builds a tiny version.

Autoregressive models belong on the same map. The chain rule of probability, \(p(x) = \prod_i p(x_i \mid x_{<i})\), turns any sequence model into a generative model with an exact likelihood, and sampling one token at a time from it is ancestral sampling, just as in an LLM (lesson ). PixelCNN applied this to raw pixels; modern systems apply it to VQ tokens. Autoregressive models dominate text, diffusion and flow matching dominate images and video, and both are used for audio. The main cost of autoregression is sequential sampling, one network call per token.

Evaluating generative models

A generator can fail in three ways: its samples can be unrealistic, they can lack variety, or they can be copies of the training data. No single number catches all three.

  • Likelihood on held-out data, often reported in bits per dimension, is the natural score for explicit models, as for our flow. It cannot be computed for GANs, and Theis et al. (2016) showed that likelihood and sample quality can disagree: a model can have excellent likelihood and poor samples, or the reverse.
  • FID (Heusel et al., 2017) passes real and generated images through an Inception network trained on ImageNet, fits a Gaussian to each set of features, and computes the Fréchet distance between the two Gaussians: \(\lVert \mu_r - \mu_g \rVert^2 + \operatorname{Tr}\big(\Sigma_r + \Sigma_g - 2(\Sigma_r \Sigma_g)^{1/2}\big)\). Lower is better.
  • Precision and recall for generative models (Sajjadi et al., 2018; Kynkäänniemi et al., 2019) split quality into two numbers. Precision is the share of generated samples that fall near real data; recall is the share of real data that falls near some generated sample.

Here are both metrics on our models: a Fréchet distance on digits, using features from a small classifier in place of Inception, and k-nearest-neighbour precision and recall on the ring.

from scipy import linalg
from sklearn.neighbors import NearestNeighbors
from sklearn.neural_network import MLPClassifier

# 1. a Frechet distance on digits, with features from a small classifier
feat_net = MLPClassifier((64,), max_iter=1000, random_state=0).fit(X_tr, y_tr)
def features(x):
    return np.maximum(0, x @ feat_net.coefs_[0] + feat_net.intercepts_[0])

def frechet(a, b):
    fa, fb = features(a), features(b)
    mu_a, mu_b = fa.mean(0), fb.mean(0)
    eps = 1e-6 * np.eye(fa.shape[1])           # keeps sqrtm numerically stable
    cov_a = np.cov(fa, rowvar=False) + eps
    cov_b = np.cov(fb, rowvar=False) + eps
    covmean = linalg.sqrtm(cov_a @ cov_b).real
    return ((mu_a - mu_b) ** 2).sum() + np.trace(cov_a + cov_b - 2 * covmean)

print("real vs real    ", round(frechet(X_te, X_tr), 2))
print("VAE samples     ", round(frechet(X_te, samples), 2))
print("AE, N(0,I) codes", round(frechet(X_te, fake), 2))
print("real, only 50   ", round(frechet(X_te[:50], X_tr[:50]), 2))

# 2. precision and recall on the ring (k-nearest-neighbour balls)
def precision_recall(real, fake, k=5):
    def radii(a):          # distance from each point to its k-th neighbour
        return NearestNeighbors(n_neighbors=k + 1).fit(a).kneighbors(a)[0][:, -1]
    def inside(a, b):      # share of a that falls in some ball around b
        return (torch.cdist(a, b) <= torch.tensor(radii(b))).any(1).float().mean()
    return round(inside(fake, real).item(), 2), round(inside(real, fake).item(), 2)

The other well-known pitfalls: scores from different implementations or resizing methods are not comparable (Parmar et al., 2022); ImageNet features may not reflect what matters in your domain, such as medical scans; and one number mixes realism and variety. Human evaluation remains the final word for text-to-image, speech and music: side-by-side preference tests with clear instructions and enough raters, designed like the evaluations in lesson . It is slow and costly, so automatic metrics serve for day-to-day development.

Generators can memorise their training data

Carlini et al. (2023) extracted near-copies of individual training images from Stable Diffusion and Imagen, and images duplicated many times in the training set were the most at risk. A model trained on private photos, medical records or customer data can leak them. Deduplicate training data, check the nearest training example for a sample of your outputs, and treat a generator trained on sensitive data as sensitive itself (lesson ).

Check yourself

What can you do with a model that has an explicit likelihood, such as a normalising flow, that you cannot do with a GAN?

  • Generate new samples
  • Compute how probable a given example is under the model
  • Train it with gradient descent
  • Condition it on a text prompt

Both can sample. Only explicit models give \(p(x)\), which you need for density estimation, anomaly scores and likelihood-based comparison.

Why does a VAE use the reparameterisation trick \(z = \mu + \sigma \odot \varepsilon\)?

  • To make the codes discrete
  • To make the KL term zero
  • So that gradients can flow through the sampling step into \(\mu\), \(\sigma\) and the encoder
  • To make sampling faster at inference time

A random draw has no derivative with respect to its parameters. Moving the randomness into an input \(\varepsilon\) makes \(z\) a differentiable function of \(\mu\) and \(\sigma\).

A GAN trained on eight modes produces sharp samples that cover only three of them. What is happening, and which metric shows it most directly?

  • Overfitting; held-out likelihood
  • Mode collapse; recall for generative models is low while precision stays high
  • Posterior collapse; the KL term
  • Underfitting; the discriminator's loss

Precision asks whether samples look real, recall asks whether all of the data is covered. Mode collapse keeps the first and loses the second.

In flow matching with straight-line paths, what is the network trained to predict?

  • The noise that was added, as in DDPM
  • The probability that its input is real
  • The next token
  • The velocity \(x_1 - x_0\) that carries the noise sample to the data sample, at a random point along the line

Generation then integrates the learnt velocity field from noise at \(t = 0\) to data at \(t = 1\).

Model A's FID was computed on 50,000 generated images and model B's on 2,000; B scores worse. What should you conclude?

  • A is better
  • B is better, because FID rewards smaller samples
  • Nothing yet: FID is biased upwards at small sample sizes, so recompute both with the same number of images and the same implementation
  • Both are memorising their training data

You saw the bias directly: two sets of 50 real digits scored 5.44, against 0.24 for the full sets.

Key takeaways

  • A generative model learns \(p(x)\). Some score examples (explicit likelihood), some only sample (implicit), and LLMs, VAEs, GANs, flows and diffusion models are different ways to make that learning tractable.
  • Autoencoders compress well but are not generators, because nothing tells you where their codes live. The VAE's KL term pulls the codes onto a known prior, and the reparameterisation trick makes it trainable.
  • Discrete latents from a VQ-VAE turn images and audio into tokens that transformers can model like text.
  • GANs give one-step sampling through an adversarial game, at the cost of unstable training and mode collapse; lower Adam momentum, spectral normalisation and Wasserstein critics help.
  • Flows give exact likelihoods through invertible layers. Diffusion and flow matching train with simple regression losses, cover every mode, and pay for it with many sampling steps; latent diffusion moves that work into an autoencoder's latent space.
  • Evaluate realism, variety and novelty separately: likelihood, FID at a fixed sample size, precision and recall, human preference, and a nearest-neighbour memorisation check.
