02 The maths behind AI

Just enough linear algebra, calculus and probability to understand what every model is doing, with each idea turned straight into NumPy code.

Study plan: 4 sessions of about an hour

Tick a session when you finish it. Progress is saved in this browser only.

Code for this lesson: notebooks/02-math-for-ai.ipynb, with worked solutions in notebooks/solutions/.

How much maths do you need?#

Less than you fear, more than none. You do not need to prove theorems. You do need to read an equation in a paper and see the code it describes, and to reason about why training is unstable or why two embeddings are "close". Three areas cover almost everything:

  • Linear algebra describes the data and the model: vectors, matrices and how they multiply.
  • Calculus describes how a model learns: gradients tell each parameter which way to move.
  • Probability describes what a model outputs and how we score it: distributions, likelihood, cross-entropy.

Every idea below comes with code. If an equation feels slippery, run the code and change the numbers.

Vectors and similarity#

A vector is an ordered list of numbers. Geometrically it is an arrow from the origin to a point. In AI a vector represents something: a house as (area, rooms, age), a word as 768 learned numbers, a sentence as 1,536 numbers from an embedding model.

The dot product#

The dot product multiplies matching entries and adds them up:

a⋅b=∑i=1naibi \mathbf{a}\cdot\mathbf{b} = \sum_{i=1}^{n} a_i b_i a⋅b=i=1∑n​ai​bi​

It is the single most important operation in deep learning. A neuron computes a dot product of its inputs with its weights. Attention in a transformer is a dot product between queries and keys. Similarity search is a dot product between embeddings.

Length and angle#

The length (Euclidean or L2 norm) of a vector is ∥a∥=a⋅a\lVert\mathbf{a}\rVert = \sqrt{\mathbf{a}\cdot\mathbf{a}}∥a∥=a⋅a​. The dot product also encodes the angle between two vectors:

a⋅b=∥a∥ ∥b∥cos⁡θ⟹cos⁡θ=a⋅b∥a∥ ∥b∥ \mathbf{a}\cdot\mathbf{b} = \lVert\mathbf{a}\rVert\,\lVert\mathbf{b}\rVert\cos\theta \quad\Longrightarrow\quad \cos\theta = \frac{\mathbf{a}\cdot\mathbf{b}}{\lVert\mathbf{a}\rVert\,\lVert\mathbf{b}\rVert} a⋅b=∥a∥∥b∥cosθ⟹cosθ=∥a∥∥b∥a⋅b​

That ratio is cosine similarity: 1 when the vectors point the same way, 0 when they are perpendicular (unrelated), −1 when opposite. It ignores length and compares only direction, which is exactly what you want when comparing the meaning of two texts of different lengths.

import numpy as np

a = np.array([3.0, 4.0])
b = np.array([4.0, 3.0])
print(np.linalg.norm(a))                 # 5.0
print(a @ b)                             # 24.0
cos = a @ b / (np.linalg.norm(a) * np.linalg.norm(b))
print(cos)                               # 0.96: nearly the same direction

Normalise once, then dot

If you scale every vector to length 1 up front, cosine similarity becomes a plain dot product. Vector databases rely on this trick: store normalised embeddings, and similarity search becomes one fast matrix multiplication.

Matrices as transformations#

A matrix is a grid of numbers, but the useful way to think of one is as a function that transforms vectors. Multiplying a vector by a matrix rotates, stretches, squashes or projects it.

R = np.array([[0, -1],
              [1,  0]])                  # rotate 90 degrees anticlockwise
print(R @ np.array([1, 0]))              # [0 1]

S = np.array([[2, 0],
              [0, 0.5]])                 # stretch x, squash y
print(S @ np.array([1, 1]))              # [2.  0.5]

A layer of a neural network is a matrix multiplication followed by a non-linearity: it transforms its input into a new space where the next layer's job is easier. Stack enough of them and the network can untangle very complicated data.

Matrix multiplication, carefully#

For C=ABC = ABC=AB, each entry is the dot product of a row of AAA with a column of BBB:

Cij=∑kAikBkj C_{ij} = \sum_k A_{ik} B_{kj} Cij​=k∑​Aik​Bkj​

So (m, n) @ (n, p) gives (m, p). Two facts trip people up: matrix multiplication is not commutative (AB≠BAAB \neq BAAB=BA in general), and the transpose reverses order, (AB)⊤=B⊤A⊤(AB)^\top = B^\top A^\top(AB)⊤=B⊤A⊤.

When you process a batch, the batch is the rows of a matrix. A batch of 32 inputs with 128 features, through a layer with weight matrix of shape (128, 64), is one multiplication (32, 128) @ (128, 64) -> (32, 64). That is why GPUs, which are very good at large matrix multiplications, are so good at deep learning.

Rank and the SVD, in one paragraph#

Any matrix can be factored as A=UΣV⊤A = U\Sigma V^\topA=UΣV⊤, the singular value decomposition. UUU and VVV are rotations and Σ\SigmaΣ is a diagonal of non-negative singular values that say how much the matrix stretches along each direction. The number of non-zero singular values is the rank: how many independent directions the matrix really uses. A huge matrix with only a few large singular values is "secretly small", and you can approximate it with far fewer numbers. That single idea underlies PCA (lesson 04) and LoRA fine-tuning (lesson 16).

rng = np.random.default_rng(0)
A = rng.normal(size=(100, 20)) @ rng.normal(size=(20, 50))   # a 100x50 matrix built from rank 20
U, S, Vt = np.linalg.svd(A, full_matrices=False)
print((S > 1e-8).sum())          # 20: only 20 directions are really used

Calculus: how models learn#

Training a model means adjusting its parameters to make a loss (a number measuring how wrong it is) as small as possible. Calculus tells us which direction to adjust them in.

Derivatives#

The derivative f′(x)f'(x)f′(x) is the slope of fff at xxx: how much the output changes per tiny change in the input. If the slope is positive, increasing xxx increases fff; to make fff smaller, move xxx the other way.

Gradient descent in one dimension#

That observation is an algorithm. Repeatedly step against the slope:

w←w−η f′(w) w \leftarrow w - \eta\, f'(w) w←w−ηf′(w)

where η\etaη (eta) is the learning rate, the step size.

def f(w):  return (w - 3) ** 2 + 1      # minimum at w = 3
def df(w): return 2 * (w - 3)            # its derivative

w, lr = -4.0, 0.1
for step in range(50):
    w -= lr * df(w)
print(round(w, 4))                       # 2.9999

Try lr = 1.1 and watch w explode, then lr = 0.001 and watch it crawl. Choosing the learning rate is the most important practical decision in training, and you will see it again in every lesson that trains anything.

Many parameters: the gradient#

Real models have millions or billions of parameters. The gradient ∇L\nabla L∇L is the vector of partial derivatives, one per parameter, each saying how the loss changes if you nudge that parameter alone. It points uphill, in the direction of steepest increase, so gradient descent steps the other way:

θ←θ−η ∇θL \boldsymbol{\theta} \leftarrow \boldsymbol{\theta} - \eta\,\nabla_{\boldsymbol{\theta}} L θ←θ−η∇θ​L

The chain rule#

Models are functions of functions: the loss depends on the prediction, which depends on a layer's output, which depends on its weights. The chain rule says the derivatives multiply along the chain:

dLdw=dLdy^⋅dy^dw \frac{dL}{dw} = \frac{dL}{d\hat{y}}\cdot\frac{d\hat{y}}{dw} dwdL​=dy^​dL​⋅dwdy^​​

Backpropagation, the algorithm that trains every neural network, is nothing more than the chain rule applied efficiently from the output back to the inputs. You will implement it by hand in lesson 05.

Worked example: fit a line with gradient descent#

We have points that roughly follow y=2.5x+4y = 2.5x + 4y=2.5x+4 and want to recover the slope and intercept. Prediction y^=wx+b\hat{y} = wx + by^​=wx+b; loss is mean squared error:

L=1N∑i(y^i−yi)2,∂L∂w=2N∑i(y^i−yi) xi,∂L∂b=2N∑i(y^i−yi) L = \frac{1}{N}\sum_i (\hat{y}_i - y_i)^2, \qquad \frac{\partial L}{\partial w} = \frac{2}{N}\sum_i (\hat{y}_i - y_i)\,x_i, \qquad \frac{\partial L}{\partial b} = \frac{2}{N}\sum_i (\hat{y}_i - y_i) L=N1​i∑​(y^​i​−yi​)2,∂w∂L​=N2​i∑​(y^​i​−yi​)xi​,∂b∂L​=N2​i∑​(y^​i​−yi​)
rng = np.random.default_rng(0)
x = rng.uniform(0, 10, 200)
y = 2.5 * x + 4 + rng.normal(0, 2, 200)      # true line plus noise

w, b, lr = 0.0, 0.0, 0.01
for epoch in range(2000):
    err = (w * x + b) - y                     # prediction error, shape (200,)
    loss = (err ** 2).mean()
    dw = 2 * (err * x).mean()                 # dL/dw
    db = 2 * err.mean()                       # dL/db
    w -= lr * dw
    b -= lr * db
    if epoch % 500 == 0:
        print(epoch, round(loss, 3), round(w, 3), round(b, 3))

print(f"w={w:.3f}, b={b:.3f}")               # close to 2.45 and 4.09
print(np.polyfit(x, y, 1))                   # the exact least-squares answer agrees

This loop (predict, measure the error, compute gradients, step) is the skeleton of every training loop in this course, including the ones that train transformers. Only the model and the way gradients are computed change.

Hands-on: check a gradient numerically

Analytic gradients are easy to get wrong. A gradient check compares them with a numerical estimate using a tiny nudge ε\varepsilonε: ∂L∂θi≈L(θ+εei)−L(θ−εei)2ε\frac{\partial L}{\partial \theta_i} \approx \frac{L(\theta + \varepsilon e_i) - L(\theta - \varepsilon e_i)}{2\varepsilon}∂θi​∂L​≈2εL(θ+εei​)−L(θ−εei​)​. Write numerical_grad(loss_fn, params) and confirm it matches dw and db above at params = [1.0, 1.0].

Show a solution 

def numerical_grad(loss_fn, params, eps=1e-5):
    g = np.zeros_like(params)
    for i in range(len(params)):
        e = np.zeros_like(params)
        e[i] = eps
        g[i] = (loss_fn(params + e) - loss_fn(params - e)) / (2 * eps)
    return g

def loss_fn(p):
    w, b = p
    return ((w * x + b - y) ** 2).mean()

p = np.array([1.0, 1.0])
err = p[0] * x + p[1] - y
print(numerical_grad(loss_fn, p))
print([2 * (err * x).mean(), 2 * err.mean()])   # should agree to ~6 decimal places
Researchers still use gradient checks when they write custom layers. It is the unit test of calculus.

Probability: what models output#

A classifier does not just say "cat"; it outputs a probability distribution: 0.92 cat, 0.07 dog, 0.01 car. An LLM outputs a distribution over its whole vocabulary for the next token. To work with these you need a few ideas.

Distributions, expectation and variance#

A probability distribution assigns probabilities that are non-negative and sum to 1. The expectation E[X]=∑xx p(x)\mathbb{E}[X] = \sum_x x\,p(x)E[X]=∑x​xp(x) is the probability-weighted average; the variance measures spread around it. The normal (Gaussian) distribution, the familiar bell curve, appears everywhere: measurement noise, weight initialisation, the noise in diffusion models.

Bayes' rule#

Bayes' rule tells you how to update a belief after seeing evidence:

P(A∣B)=P(B∣A) P(A)P(B) P(A\mid B) = \frac{P(B\mid A)\,P(A)}{P(B)} P(A∣B)=P(B)P(B∣A)P(A)​

Classic example. A fault affects 1% of instruments. A diagnostic test catches 95% of faulty ones but also flags 5% of healthy ones. An instrument tests positive: how likely is it to be faulty?

prior, sensitivity, false_pos = 0.01, 0.95, 0.05
posterior = sensitivity * prior / (sensitivity * prior + false_pos * (1 - prior))
print(round(posterior, 3))       # 0.161, only 16%

Most people guess around 95%. The base rate matters enormously, a lesson that returns when you evaluate classifiers on rare events such as fraud or equipment failures.

Softmax: turning scores into probabilities#

Models produce raw scores called logits that can be any real numbers. Softmax converts them into a distribution:

softmax(z)i=ezi∑jezj \mathrm{softmax}(\mathbf{z})_i = \frac{e^{z_i}}{\sum_j e^{z_j}} softmax(z)i​=∑j​ezj​ezi​​
def softmax(z):
    z = z - z.max(axis=-1, keepdims=True)    # subtract the max for numerical stability
    e = np.exp(z)
    return e / e.sum(axis=-1, keepdims=True)

print(softmax(np.array([2.0, 1.0, 0.1])).round(3))          # [0.659 0.242 0.099]
print(softmax(np.array([1000.0, 1001.0, 1002.0])).round(3)) # works; naive exp(1000) would overflow

Subtracting the maximum does not change the answer (it cancels in the ratio) but prevents overflow. Small details like this are the difference between code that trains and code that produces nan.

Cross-entropy: the loss behind almost every classifier and LLM#

If the true class is yyy and the model gives it probability pyp_ypy​, the cross-entropy loss is

L=−log⁡py L = -\log p_y L=−logpy​

If the model is confident and right (py≈1p_y \approx 1py​≈1), the loss is near 0. If it gives the right answer a tiny probability, the loss is large. LLM pretraining minimises exactly this, averaged over every next-token prediction in trillions of tokens.

p = softmax(np.array([2.0, 1.0, 0.1]))
print(-np.log(p[0]))     # 0.417: the right class had 66% probability
print(-np.log(p[2]))     # 2.317: the right class had only 10%

Entropy and KL divergence#

Entropy H(P)=−∑xP(x)log⁡P(x)H(P) = -\sum_x P(x)\log P(x)H(P)=−∑x​P(x)logP(x) measures how uncertain a distribution is. KL divergence measures how different a distribution QQQ is from a reference PPP:

DKL(P ∥ Q)=∑xP(x)log⁡P(x)Q(x) D_{\mathrm{KL}}(P\,\|\,Q) = \sum_x P(x)\log\frac{P(x)}{Q(x)} DKL​(P∥Q)=x∑​P(x)logQ(x)P(x)​

It is zero only when the two are identical, and it is not symmetric. You will meet it in knowledge distillation (a small model learning to match a big model's distribution) and in RLHF, where a KL penalty stops a fine-tuned model drifting too far from where it started. A useful identity ties it together: cross-entropy equals entropy plus KL divergence, H(P,Q)=H(P)+DKL(P ∥ Q)H(P,Q) = H(P) + D_{\mathrm{KL}}(P\,\|\,Q)H(P,Q)=H(P)+DKL​(P∥Q).

P = np.array([0.7, 0.2, 0.1])
Q = np.array([0.5, 0.3, 0.2])
H  = -(P * np.log(P)).sum()            # 0.8018
CE = -(P * np.log(Q)).sum()            # 0.8869
KL = (P * np.log(P / Q)).sum()         # 0.0851 = CE - H

Hands-on: temperature

LLMs divide their logits by a temperature TTT before softmax. For logits [2.0, 1.0, 0.1], compute the distribution at T=0.2,1,5T = 0.2, 1, 5T=0.2,1,5 and its entropy. Describe in one sentence what temperature does. You will use this when you control LLM sampling in lesson 09.

Show a solution 

z = np.array([2.0, 1.0, 0.1])
for T in [0.2, 1, 5]:
    p = softmax(z / T)
    H = -(p * np.log(p)).sum()
    print(T, p.round(3), round(H, 3))
# 0.2 [0.993 0.007 0.   ] 0.043   nearly deterministic
# 1   [0.659 0.242 0.099] 0.832
# 5   [0.402 0.329 0.269] 1.085   close to uniform
Low temperature sharpens the distribution towards the top choice; high temperature flattens it towards uniform, so sampling becomes more random and more "creative".

Check yourself#

1. Two embedding vectors have cosine similarity 0.02. What does that suggest?

Cosine similarity measures direction only. Near 0 means roughly perpendicular, usually read as "unrelated".

2. In gradient descent, why do we subtract the gradient rather than add it?

The gradient points uphill. Stepping against it goes downhill.

3. Your loss jumps around wildly and then becomes nan. What is the first thing to try?

Steps that are too large overshoot the minimum and can diverge. Lowering the learning rate is the first fix.

4. Why do we subtract max(z) inside softmax?

The constant cancels between numerator and denominator, so the output is unchanged, but exp never sees huge numbers.

5. A model assigns probability 0.01 to the correct next token. What is the cross-entropy loss for that prediction?

−ln(0.01) ≈ 4.605. Confident wrong predictions are punished heavily.

Key takeaways

  • The dot product is everywhere: neurons, attention and similarity search. Cosine similarity compares direction and ignores length.
  • Matrices transform vectors; (m, n) @ (n, p) -> (m, p). The SVD reveals how many directions a matrix really uses, which underpins PCA and LoRA.
  • Training is gradient descent: predict, measure loss, compute gradients with the chain rule, step against them. The learning rate is the critical knob.
  • Models output distributions via softmax; they are trained with cross-entropy. KL divergence measures how far one distribution is from another.
