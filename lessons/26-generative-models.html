Session 1 of 3What a generative model is, the map of model families, and autoencoders

What a generative model is#

A classifier learns p(y∣x)p(y \mid x)p(y∣x): given an image, which digit is it? A generative model learns p(x)p(x)p(x) itself: what do images of digits look like at all? Once you have a good model of p(x)p(x)p(x), you can do two different jobs with it.

  • Density estimation: score how plausible a given example is. This is useful for anomaly detection, compression and comparing models.
  • Sampling: draw new examples that look like the training data. This is what people usually mean by "generative AI".

Some models do both jobs. An LLM is one: it gives the exact probability of any text, token by token, and samples new text the same way (lesson 09). Others can only sample. A GAN can draw a convincing face but cannot tell you how probable a given face is. Models that can compute p(x)p(x)p(x) have an explicit likelihood; models that can only sample define it implicitly.

Models with an explicit likelihood are usually trained by maximum likelihood: choose parameters θ\thetaθ that make the training data as probable as possible,

θ⋆=arg⁡max⁡θ∑ilog⁡pθ(xi),\theta^\star = \arg\max_\theta \sum_{i} \log p_\theta(x_i),θ⋆=argθmax​i∑​logpθ​(xi​),

which is the same as minimising the KL divergence from the data distribution to the model (lesson 02). The simplest model that does both jobs is one you have met already: a Gaussian mixture.

Python
import numpy as np
from sklearn.datasets import make_moons
from sklearn.mixture import GaussianMixture

moons, _ = make_moons(2000, noise=0.05, random_state=0)
gmm = GaussianMixture(n_components=8, random_state=0).fit(moons[:1500])

# job 1, density: log p(x) for a point on a moon and a point far away
print(gmm.score_samples([[0.0, 1.0], [0.0, 3.0]]).round(1))
print(round(gmm.score(moons[1500:]), 3))   # mean log p(x) on held-out points

# job 2, sampling: new points that look like the data
new_points, _ = gmm.sample(3)
print(new_points.round(2))

A point on a moon scores log⁡p(x)=−0.2\log p(x) = -0.2logp(x)=−0.2; a point far from the data scores −69.6, a probability density of about e−70e^{-70}e−70. The held-out average, −0.437 nats per point, is a number to beat in session 3. Mixtures stop working when the data has thousands of dimensions with intricate structure, such as images and audio. Deep generative models learn pθ(x)p_\theta(x)pθ​(x) with neural networks instead, and the families differ mainly in how they make that learning tractable.

The map of model families#

In practice the families are combined. A latent diffusion model is a VAE whose latents are modelled by diffusion, and its decoder is usually trained with a GAN loss. An image or audio tokenizer is a vector-quantised autoencoder whose tokens an autoregressive transformer then models. This lesson builds one of each (except energy-based models) at toy scale, so you can see what each piece contributes.

Autoencoders#

Compress and reconstruct#

An autoencoder has two halves. The encoder fff squeezes an input xxx into a short code z=f(x)z = f(x)z=f(x); the decoder ggg rebuilds the input from the code. Training minimises the reconstruction error ∥x−g(f(x))∥2\lVert x - g(f(x)) \rVert^2∥x−g(f(x))∥2. The narrow code, the bottleneck, is what makes this useful: the network cannot copy pixels through, so it must learn the structure that lets it describe a digit in a few numbers.

An autoencoder is not yet a generative model, because nothing in it defines p(x)p(x)p(x). It is the building block for two that are: the VAE in session 2 and latent diffusion in session 3. We will use scikit-learn's bundled 8×8 digits throughout, plus a digit classifier as a rough judge of generated images. A classifier's confidence on samples is a crude quality signal; session 3 refines this idea into FID.

Python
import torch
import torch.nn as nn
import torch.nn.functional as F
from sklearn.datasets import load_digits
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

torch.set_num_threads(1)     # tiny models: one thread is usually fastest

digits = load_digits()
X = digits.data / 16.0       # 1,797 images of 8x8 pixels, scaled to [0, 1]
X_tr, X_te, y_tr, y_te = train_test_split(
    X, digits.target, test_size=0.25, random_state=0, stratify=digits.target)
Xtr = torch.tensor(X_tr, dtype=torch.float32)
Xte = torch.tensor(X_te, dtype=torch.float32)

# a classifier that will act as a judge of generated digits
judge = LogisticRegression(max_iter=2000).fit(X_tr, y_tr)

def judge_report(images):
    """Mean confidence of the judge, and how many images it calls each digit."""
    p = judge.predict_proba(np.clip(images, 0, 1))
    counts = np.bincount(p.argmax(1), minlength=10)
    return round(float(p.max(1).mean()), 2), counts.tolist()

print(round(judge.score(X_te, y_te), 3))
print(judge_report(X_te))
Output
0.969
(0.9, [45, 52, 43, 45, 43, 47, 43, 47, 41, 44])

The judge gets 96.9% of real test digits right, with an average confidence of 0.9, and it spreads the test set evenly, calling 41 to 52 images each digit. That is what "looks like a real digit" means in numbers. Now the autoencoder, with a two-number code so we can look at it.

Python
class AutoEncoder(nn.Module):
    def __init__(self, d_latent=2):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(64, 128), nn.ReLU(),
                                     nn.Linear(128, d_latent))
        self.decoder = nn.Sequential(nn.Linear(d_latent, 128), nn.ReLU(),
                                     nn.Linear(128, 64), nn.Sigmoid())

    def forward(self, x):
        return self.decoder(self.encoder(x))

def fit(model, loss_fn, epochs=100, lr=2e-3, batch=128):
    """Minibatch training on the digit images; loss_fn(model, x) -> loss."""
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    for epoch in range(epochs):
        for idx in torch.randperm(len(Xtr)).split(batch):
            loss = loss_fn(model, Xtr[idx])
            opt.zero_grad(); loss.backward(); opt.step()
    return model

torch.manual_seed(0)
ae = fit(AutoEncoder(), lambda m, x: F.mse_loss(m(x), x))

from sklearn.decomposition import PCA
pca = PCA(n_components=2).fit(X_tr)           # the linear baseline
pca_recon = pca.inverse_transform(pca.transform(X_te))
with torch.no_grad():
    print("autoencoder", round(F.mse_loss(ae(Xte), Xte).item(), 4))
print("PCA        ", round(((pca_recon - X_te) ** 2).mean(), 4))
Output
autoencoder 0.0382
PCA         0.053

PCA is a linear autoencoder: with squared error, the best linear encoder and decoder span the same subspace as the top principal components (lesson 04). With the same two numbers per image, the non-linear autoencoder reconstructs with error 0.038 against PCA's 0.053.

The latent space#

The codes live in a latent space. Plot them (the notebook does) and you see a cluster for each digit, with gaps between. Can we generate by decoding random codes?

Python
with torch.no_grad():
    Z = ae.encoder(Xtr)                 # the 2-D code of every training digit
print(Z.mean(0).numpy().round(2), Z.std(0).numpy().round(2))

# try to generate: decode random codes from a standard normal
torch.manual_seed(1)
with torch.no_grad():
    fake = ae.decoder(torch.randn(1000, 2)).numpy()
print(judge_report(fake))
Output
[ 1.75 -0.93] [2.92 3.06]
(0.62, [206, 100, 263, 28, 1, 96, 218, 0, 79, 9])

Mostly no. Training put the codes wherever was convenient, centred near (1.75, −0.93) with a spread of about 3, so a standard normal only samples a small patch in the middle. The judge's confidence drops to 0.62, and out of 1,000 samples it finds 1 four, 0 sevens and 9 nines. A plain autoencoder gives you a decoder but no distribution over codes to sample from, and decoding a code from a region it never saw produces a smudge. The VAE fixes exactly this.

Reconstructions flatter a generator

Reconstructions always look good, because the encoder picked the code. The only fair test of a generator is to decode codes drawn from the distribution you will actually sample from.

Denoising autoencoders#

A denoising autoencoder is given a corrupted input and trained to output the clean original. It can no longer get away with copying; it has to learn which way is "back towards real data" from any nearby point.

Python
def denoising_loss(model, x, noise=0.3):
    noisy = x + noise * torch.randn_like(x)    # corrupt the input...
    return F.mse_loss(model(noisy), x)         # ...but score against the clean x

torch.manual_seed(0)
plain = fit(AutoEncoder(d_latent=16), lambda m, x: F.mse_loss(m(x), x))
dae = fit(AutoEncoder(d_latent=16), denoising_loss)

torch.manual_seed(2)
noisy_te = Xte + 0.3 * torch.randn_like(Xte)
with torch.no_grad():
    for name, m in [("plain", plain), ("denoising", dae)]:
        print(f"{name:9s} clean in: {F.mse_loss(m(Xte), Xte).item():.4f}  "
              f"noisy in: {F.mse_loss(m(noisy_te), Xte).item():.4f}")
Output
plain     clean in: 0.0070  noisy in: 0.0404
denoising clean in: 0.0112  noisy in: 0.0197

The denoiser is a little worse on clean inputs (0.0112 against 0.0070) and halves the error on noisy ones (0.0197 against 0.0404). Knowing which way leads back to the data is knowledge about the shape of p(x)p(x)p(x), and Pascal Vincent showed in 2011 that training a denoiser is closely related to estimating the gradient of log⁡p(x)\log p(x)logp(x). Train one network to denoise at every noise level, from a light sprinkle to pure static, and you have a diffusion model. That is session 3.

Session 2 of 3Variational autoencoders, discrete latents and generative adversarial networks

Variational autoencoders#

A latent-variable model#

A variational autoencoder (Kingma and Welling, 2013) starts from a story about how the data was made: first pick a code zzz from a simple prior p(z)=N(0,I)p(z) = \mathcal{N}(0, I)p(z)=N(0,I), then generate xxx from pθ(x∣z)p_\theta(x \mid z)pθ​(x∣z), a decoder network. The probability of an image is then an average over all codes that could have produced it:

pθ(x)=∫pθ(x∣z) p(z) dz.p_\theta(x) = \int p_\theta(x \mid z)\, p(z)\, dz .pθ​(x)=∫pθ​(x∣z)p(z)dz.

Sampling is easy: draw zzz, decode. Training by maximum likelihood is not, because the integral runs over every possible zzz, and for any particular image almost every random zzz explains it terribly. The fix is a second network, the encoder qϕ(z∣x)q_\phi(z \mid x)qϕ​(z∣x), which proposes the codes that are likely for a given xxx. It outputs a mean μ\muμ and a standard deviation σ\sigmaσ for each latent dimension.

The ELBO, gently#

Multiply and divide inside the integral by qϕ(z∣x)q_\phi(z \mid x)qϕ​(z∣x), so it becomes an average over codes drawn from the encoder, then use Jensen's inequality (the log of an average is at least the average of the logs):

log⁡pθ(x)=log⁡Eqϕ(z∣x) ⁣[pθ(x∣z) p(z)qϕ(z∣x)]  ≥  Eqϕ(z∣x)[log⁡pθ(x∣z)]⏟reconstruction  −  DKL(qϕ(z∣x) ∥ p(z))⏟stay near the prior.\log p_\theta(x) = \log \mathbb{E}_{q_\phi(z\mid x)}\!\left[\frac{p_\theta(x \mid z)\,p(z)}{q_\phi(z \mid x)}\right] \;\ge\; \underbrace{\mathbb{E}_{q_\phi(z\mid x)}\big[\log p_\theta(x \mid z)\big]}_{\text{reconstruction}} \;-\; \underbrace{D_{\mathrm{KL}}\big(q_\phi(z \mid x)\,\|\,p(z)\big)}_{\text{stay near the prior}} .logpθ​(x)=logEqϕ​(z∣x)​[qϕ​(z∣x)pθ​(x∣z)p(z)​]≥reconstructionEqϕ​(z∣x)​[logpθ​(x∣z)]​​−stay near the priorDKL​(qϕ​(z∣x)∥p(z))​​.

The right-hand side is the evidence lower bound, or ELBO. The gap between it and the true log-likelihood is exactly DKL(qϕ(z∣x) ∥ pθ(z∣x))D_{\mathrm{KL}}(q_\phi(z \mid x)\,\|\,p_\theta(z \mid x))DKL​(qϕ​(z∣x)∥pθ​(z∣x)), so raising the ELBO both improves the model and makes the encoder a better guess at the true posterior. Read the two terms as opposing forces. Reconstruction wants each code to pin down its image precisely. The KL term wants every code distribution to look like N(0,I)\mathcal{N}(0, I)N(0,I), which packs the codes together around the origin with no gaps. That second force is what was missing from the plain autoencoder. For a Gaussian encoder the KL term has a closed form:

DKL=12∑j(μj2+σj2−log⁡σj2−1).D_{\mathrm{KL}} = \tfrac{1}{2}\sum_j \left(\mu_j^2 + \sigma_j^2 - \log \sigma_j^2 - 1\right).DKL​=21​j∑​(μj2​+σj2​−logσj2​−1).

The reparameterisation trick#

There is one obstacle. Backpropagation cannot pass through "draw zzz from N(μ,σ2)\mathcal{N}(\mu, \sigma^2)N(μ,σ2)", because a random draw has no derivative with respect to μ\muμ. The reparameterisation trick rewrites the draw as z=μ+σ⊙εz = \mu + \sigma \odot \varepsilonz=μ+σ⊙ε with ε∼N(0,I)\varepsilon \sim \mathcal{N}(0, I)ε∼N(0,I). The randomness becomes an input, and zzz is an ordinary differentiable function of μ\muμ and σ\sigmaσ.

Python
class VAE(nn.Module):
    def __init__(self, d_latent=2):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(64, 128), nn.ReLU(),
                                     nn.Linear(128, 2 * d_latent))  # mu, log var
        self.decoder = nn.Sequential(nn.Linear(d_latent, 128), nn.ReLU(),
                                     nn.Linear(128, 64))            # pixel logits

    def encode(self, x):
        mu, logvar = self.encoder(x).chunk(2, dim=1)
        return mu, logvar

    def forward(self, x):
        mu, logvar = self.encode(x)
        eps = torch.randn_like(mu)
        z = mu + torch.exp(0.5 * logvar) * eps     # the reparameterisation trick
        return self.decoder(z), mu, logvar

def elbo_terms(model, x):
    logits, mu, logvar = model(x)
    # reconstruction: -log p(x|z) under a Bernoulli per pixel, summed over pixels
    recon = F.binary_cross_entropy_with_logits(logits, x, reduction="sum")
    # KL(q(z|x) || N(0, I)) in closed form, summed over latent dimensions
    kl = 0.5 * (mu ** 2 + logvar.exp() - logvar - 1).sum()
    return recon / len(x), kl / len(x)          # both per image

def vae_loss(model, x, beta=1.0):
    recon, kl = elbo_terms(model, x)
    return recon + beta * kl                    # the negative ELBO when beta = 1

Three details here prevent the most common VAE bugs. The encoder predicts log⁡σ2\log \sigma^2logσ2 rather than σ\sigmaσ, so any real output is valid. The decoder returns logits and the loss applies the sigmoid itself, as in lesson 06. And both terms are summed over their dimensions before averaging over the batch: if you average the reconstruction over 64 pixels but sum the KL, the KL is effectively 64 times too strong and the model will usually learn to ignore its codes.

The KL term pulled the codes onto the prior: their mean is now about 0 and their spread about 1, so codes drawn from N(0,I)\mathcal{N}(0, I)N(0,I) land where the decoder was trained. Every digit appears among the samples, from 32 ones up to 127 fours, where the autoencoder produced almost no fours or sevens. Notice what did not improve: the judge's confidence, 0.63, is no higher than before. VAE samples are blurry. Each code carries at most about 2.2 nats (3 bits) of information about its image, and the decoder scores every pixel independently, so it hedges with averaged strokes.

Because the latent space has no gaps, you can walk through it. Take the codes of a test 0 and a test 6 and decode points on the straight line between them:

Python
i, j = np.where(y_te == 0)[0][0], np.where(y_te == 6)[0][0]

    path = torch.stack([(1 - a) * mu[0] + a * mu[1]

Every frame is a digit-like image: the judge sees three frames of 0, then five of 6. The notebook shows the frames.

β-VAE and disentanglement#

Weighting the KL term by a factor β\betaβ gives the β-VAE (Higgins et al., 2017). With β>1\beta > 1β>1, the stronger pull towards an independent Gaussian prior can make individual latent dimensions line up with separate factors of variation, such as slant or stroke thickness. This is called disentanglement. It costs reconstruction quality, and later work showed it cannot be guaranteed without extra assumptions or supervision. Push β\betaβ too far and the KL term wins outright: train fit(VAE(), lambda m, x: vae_loss(m, x, beta=4.0)) and the KL falls to 0.00, the decoder ignores zzz, and all 1,000 samples are the same average blob, which the judge calls an 8. This failure is posterior collapse. Going the other way, the autoencoders inside latent diffusion models use a very small KL weight, because a diffusion model, not the Gaussian prior, will model their latents.

VQ-VAE: discrete latents#

The VQ-VAE (van den Oord et al., 2017) replaces the Gaussian code with a lookup table. The encoder outputs a grid of vectors, and each vector is snapped to the nearest of KKK learnt codebook vectors. The image becomes a grid of integers, one codebook index per position. Snapping has no useful gradient, so the straight-through estimator passes the decoder's gradient to the encoder as if the snap were not there. Two extra losses move the codebook towards the encoder outputs and keep the encoder committed to its codes.

Python
def quantise(z, codebook):
    """Snap each row of z to its nearest codebook vector, as in a VQ-VAE."""
    idx = torch.cdist(z, codebook).argmin(dim=1)   # one integer token per row
    z_q = codebook[idx]
    vq_loss = (F.mse_loss(z_q, z.detach())          # pull codes to the encoder
               + 0.25 * F.mse_loss(z, z_q.detach()))  # commit encoder to code
    z_st = z + (z_q - z).detach()  # straight-through: value z_q, gradient to z
    return z_st, idx, vq_loss

torch.manual_seed(0)
codebook = torch.randn(16, 4, requires_grad=True)   # K = 16 codes of size 4
z = torch.randn(6, 4, requires_grad=True)           # six encoder outputs
z_q, idx, vq_loss = quantise(z, codebook)
print(idx)                     # the "image" is now six integer tokens
z_q.sum().backward()
print(z.grad[0])               # ones: the gradient passed straight through
Output
tensor([12, 10,  9,  7,  4,  2])
tensor([1., 1., 1., 1.])

Discrete latents matter because once an image or a sound is a sequence of integers, a transformer can model it exactly like text, with next-token prediction (lesson 08). Neural audio codecs such as SoundStream and EnCodec turn audio into tokens with residual vector quantisation (several codebooks, each quantising what the previous one missed), and speech and music generators predict those tokens. VQGAN-style tokenizers do the same for images. The tokenizer is a generative model in its own right, and the quality of its decoder caps the quality of everything built on top.

Generative adversarial networks#

The game#

A GAN (Goodfellow et al., 2014) gives up on likelihood altogether. A generator GGG turns noise zzz into a sample. A discriminator DDD looks at a sample and outputs the probability that it is real. They play a game: DDD is trained to tell real from fake, and GGG is trained to fool DDD. Think of a counterfeiter and an inspector, each improving because the other does.

min⁡Gmax⁡D    Ex∼pdata[log⁡D(x)]+Ez∼p(z)[log⁡(1−D(G(z)))]\min_G \max_D \;\; \mathbb{E}_{x \sim p_{\text{data}}}\big[\log D(x)\big] + \mathbb{E}_{z \sim p(z)}\big[\log\big(1 - D(G(z))\big)\big]Gmin​Dmax​Ex∼pdata​​[logD(x)]+Ez∼p(z)​[log(1−D(G(z)))]

The original paper shows that for a fixed generator the best discriminator is D⋆(x)=pdata(x)/(pdata(x)+pG(x))D^\star(x) = p_{\text{data}}(x) / (p_{\text{data}}(x) + p_G(x))D⋆(x)=pdata​(x)/(pdata​(x)+pG​(x)), and against that discriminator the generator is minimising the Jensen-Shannon divergence between the data and its own distribution. The same paper points out a practical problem. Early in training DDD rejects fakes easily, log⁡(1−D(G(z)))\log(1 - D(G(z)))log(1−D(G(z))) is flat near D=0D = 0D=0, and GGG gets almost no gradient. The fix is the non-saturating loss: train GGG to maximise log⁡D(G(z))\log D(G(z))logD(G(z)) instead. It has the same goal but strong gradients exactly when the generator is bad. In code, that means scoring the fakes against the "real" label.

A GAN on eight Gaussians#

Images make GAN failures hard to see, so we use a classic 2-D test: eight tight Gaussian blobs on a ring. A helper counts how many of the eight modes a model's samples reach, and what share of samples land within three standard deviations of some mode. We will reuse it for diffusion and flow matching.

Python
angles = torch.arange(8) * 2 * torch.pi / 8
CENTRES = 2.0 * torch.stack([angles.cos(), angles.sin()], dim=1)   # (8, 2)

def sample_ring(n, std=0.05):
    return CENTRES[torch.randint(0, 8, (n,))] + std * torch.randn(n, 2)

def mode_report(x, std=0.05):
    """Modes that get at least 1% of samples, and the share of good samples."""
    d = torch.cdist(x, CENTRES)                  # distance to every centre
    good = d.min(1).values < 3 * std             # within 3 std of some mode
    counts = torch.bincount(d.argmin(1)[good], minlength=8)
    covered = int((counts >= 0.01 * len(x)).sum())
    return covered, round(good.float().mean().item(), 2)

def mlp(n_in, n_out, hidden=128, depth=2):
    layers, d = [], n_in
    for _ in range(depth):
        layers += [nn.Linear(d, hidden), nn.ReLU()]
        d = hidden
    return nn.Sequential(*layers, nn.Linear(d, n_out))

torch.manual_seed(0)
print(mode_report(sample_ring(1000)))   # real data: all 8 modes, 99% good

Python
def train_gan(steps=3000, batch=256, lr=1e-3, betas=(0.9, 0.999)):
    G, D = mlp(2, 2), mlp(2, 1)      # D returns a logit: "how real is this?"
    opt_g = torch.optim.Adam(G.parameters(), lr=lr, betas=betas)
    opt_d = torch.optim.Adam(D.parameters(), lr=lr, betas=betas)
    bce = nn.BCEWithLogitsLoss()
    real_label, fake_label = torch.ones(batch, 1), torch.zeros(batch, 1)
    for step in range(1, steps + 1):
        real, fake = sample_ring(batch), G(torch.randn(batch, 2))
        # 1. discriminator: push D(real) towards 1 and D(fake) towards 0
        d_loss = bce(D(real), real_label) + bce(D(fake.detach()), fake_label)
        opt_d.zero_grad(); d_loss.backward(); opt_d.step()
        # 2. generator (non-saturating loss): make D call the fakes real
        g_loss = bce(D(fake), real_label)
        opt_g.zero_grad(); g_loss.backward(); opt_g.step()
        if step % 500 == 0:
            with torch.no_grad():
                print(step, mode_report(G(torch.randn(1000, 2))))
    return G

torch.manual_seed(8)

Read the log line by line. At step 500 the samples crowd onto one side of the ring and almost none land on a mode; at 1,000 they have spread out but still sit between the modes. By the end the samples are sharp (73% land on a mode) but cover only five of the eight modes, and the notebook's plot shows the shape of the failure: about four in five samples pile up near two modes, while the mode between them gets none. That is mode collapse, here in its partial form. The generator is rewarded for fooling the current discriminator, not for covering the data. If one region fools DDD best, GGG moves its samples there; DDD learns to reject that region; GGG hops elsewhere. Nothing in the loss directly rewards diversity. Rerun with a different seed and the details change: across nine seeds this run ended with anything from one mode to seven. That sensitivity is the practical problem with GANs.

Making GANs train#

A decade of practice produced a toolbox of fixes:

  • The non-saturating generator loss, already used above.
  • Lower momentum in Adam: the DCGAN paper (Radford et al., 2015) found the default β1=0.9\beta_1 = 0.9β1​=0.9 caused oscillation and recommended 0.5.
  • Spectral normalisation (Miyato et al., 2018) rescales each discriminator weight matrix so the discriminator cannot change too sharply, which keeps its gradients informative. In PyTorch it is one wrapper, nn.utils.parametrizations.spectral_norm.
  • Wasserstein GANs (Arjovsky et al., 2017) replace the discriminator with a critic that estimates the Wasserstein distance, which still gives useful gradients when the real and fake distributions do not overlap. The gradient penalty version, WGAN-GP (Gulrajani et al., 2017), keeps the critic smooth by penalising gradient norms away from 1.
  • Separate learning rates for the two players (the two time-scale update rule, Heusel et al., 2017, the paper that also introduced FID).

Watch samples, not losses

GAN losses do not fall steadily as the generator improves, because each player's loss depends on the other. Log a sample-based metric, as mode_report does here, and look at pictures.

Where GANs still win#

Diffusion models overtook GANs for image synthesis around 2021 (Dhariwal and Nichol's paper is titled "Diffusion Models Beat GANs on Image Synthesis"), mainly on diversity and training stability. GANs remain the right tool when you need an output in a single network call: real-time synthesis and super-resolution, where models such as ESRGAN sharpen images. The adversarial loss also lives on inside other models. The autoencoders of latent diffusion are trained with a GAN loss so their decoders produce crisp detail, and SD-Turbo, the one-step generator from lesson 23, was distilled from a diffusion model with an adversarial loss.

Normalising flows#

The change of variables formula#

A normalising flow builds a complicated density by warping a simple one with an invertible function. Take a one-dimensional example first: if a function doubles every number, the probability mass spreads over twice the length, so the density halves everywhere. In general, if an invertible function fff maps data xxx to noise z=f(x)z = f(x)z=f(x) with z∼N(0,I)z \sim \mathcal{N}(0, I)z∼N(0,I), then

log⁡pX(x)=log⁡pZ(f(x))+log⁡∣det⁡∂f(x)∂x∣.\log p_X(x) = \log p_Z\big(f(x)\big) + \log \left| \det \frac{\partial f(x)}{\partial x} \right| .logpX​(x)=logpZ​(f(x))+log​det∂x∂f(x)​​.

The first term asks how likely the noise is; the second corrects for how much fff stretches or squeezes space around xxx. Train fff by maximum likelihood with this exact formula, then sample by drawing zzz and running fff backwards. The design problem is that fff must be invertible and its Jacobian determinant must be cheap: for a general D×DD \times DD×D matrix the determinant costs on the order of D3D^3D3 operations.

An affine coupling layer#

The coupling layer from RealNVP (Dinh et al., 2016) solves both problems with a trick. Split xxx into two halves (a,b)(a, b)(a,b). Leave aaa alone, and scale and shift bbb by amounts computed from aaa:

za=a,zb=b⊙es(a)+t(a),log⁡∣det⁡J∣=∑s(a).z_a = a, \qquad z_b = b \odot e^{s(a)} + t(a), \qquad \log\left|\det J\right| = \textstyle\sum s(a).za​=a,zb​=b⊙es(a)+t(a),log∣detJ∣=∑s(a).

Inverting it needs no inverse of sss or ttt: b=(zb−t(a))⊙e−s(a)b = (z_b - t(a)) \odot e^{-s(a)}b=(zb​−t(a))⊙e−s(a). The Jacobian is triangular, so its log-determinant is just the sum of the log-scales. Because sss and ttt are never inverted, they can be any neural network. Stack several layers, alternating which half is changed, and the flow can bend space in both directions.

Python
class Coupling(nn.Module):
    """Affine coupling: keep one coordinate, scale and shift the other."""
    def __init__(self, flip):
        super().__init__()
        self.flip = flip
        self.net = mlp(1, 2, hidden=64)      # outputs log-scale s and shift t

    def split(self, x):
        a, b = x[:, :1], x[:, 1:]
        return (b, a) if self.flip else (a, b)

    def join(self, a, b):
        return torch.cat([b, a] if self.flip else [a, b], dim=1)

    def forward(self, x):                    # data -> noise, with log|det J|
        a, b = self.split(x)
        s, t = self.net(a).chunk(2, dim=1)
        s = torch.tanh(s)                    # keep the scale factors tame
        return self.join(a, b * torch.exp(s) + t), s.squeeze(1)

    def inverse(self, z):                    # noise -> data
        a, b = self.split(z)
        s, t = self.net(a).chunk(2, dim=1)
        s = torch.tanh(s)
        return self.join(a, (b - t) * torch.exp(-s))

class Flow(nn.Module):
    def __init__(self, n_layers=8):
        super().__init__()
        self.layers = nn.ModuleList(Coupling(flip=i % 2 == 1)
                                    for i in range(n_layers))

    def forward(self, x):                    # data -> noise, summing log|det J|
        log_det = torch.zeros(len(x))
        for layer in self.layers:
            x, ld = layer(x)
            log_det = log_det + ld
        return x, log_det

    def inverse(self, z):                    # noise -> data
        for layer in reversed(self.layers):
            z = layer.inverse(z)
        return z

    def log_prob(self, x):                   # the change of variables formula
        z, log_det = self(x)
        return -0.5 * (z ** 2).sum(1) - np.log(2 * np.pi) + log_det

Diffusion from scratch#

Lesson 23 gave the intuition and the forward process: mix data with noise according to a schedule, xt=αˉt x0+1−αˉt εx_t = \sqrt{\bar\alpha_t}\,x_0 + \sqrt{1-\bar\alpha_t}\,\varepsilonxt​=αˉt​​x0​+1−αˉt​​ε, and train a network εθ(xt,t)\varepsilon_\theta(x_t, t)εθ​(xt​,t) to predict the noise with the loss ∥ε−εθ(xt,t)∥2\lVert \varepsilon - \varepsilon_\theta(x_t, t)\rVert^2∥ε−εθ​(xt​,t)∥2. Here is the whole loop, on the ring that defeated the GAN. Generation, called ancestral sampling, starts from pure noise and takes TTT small denoising steps (Ho et al., 2020):

xt−1=1αt(xt−βt1−αˉt εθ(xt,t))+σt n,n∼N(0,I),x_{t-1} = \frac{1}{\sqrt{\alpha_t}}\left(x_t - \frac{\beta_t}{\sqrt{1-\bar\alpha_t}}\,\varepsilon_\theta(x_t, t)\right) + \sigma_t\, \mathbf{n}, \qquad \mathbf{n} \sim \mathcal{N}(0, I),xt−1​=αt​​1​(xt​−1−αˉt​​βt​​εθ​(xt​,t))+σt​n,n∼N(0,I),

where αt=1−βt\alpha_t = 1 - \beta_tαt​=1−βt​. The added noise σt\sigma_tσt​ can be βt\sqrt{\beta_t}βt​​ or the variance of the true reverse step when x0x_0x0​ is known, β~t=βt(1−αˉt−1)/(1−αˉt)\tilde\beta_t = \beta_t(1-\bar\alpha_{t-1})/(1-\bar\alpha_t)β~​t​=βt​(1−αˉt−1​)/(1−αˉt​). The DDPM paper found the two similar on images; on this tiny dataset β~t\tilde\beta_tβ~​t​ gives noticeably sharper samples, so we use it.

Python
T = 100
betas = torch.linspace(1e-4, 0.2, T)   # linear schedule, rescaled for 100 steps
alphas = 1 - betas
alpha_bar = torch.cumprod(alphas, dim=0)
alpha_bar_prev = torch.cat([torch.ones(1), alpha_bar[:-1]])
sigma2 = betas * (1 - alpha_bar_prev) / (1 - alpha_bar)    # posterior variance

torch.manual_seed(0)
eps_model = mlp(3, 2, depth=3)          # (x_t, t/T) -> predicted noise
opt = torch.optim.Adam(eps_model.parameters(), lr=1e-3)
for step in range(4000):
    x0 = sample_ring(256)
    t = torch.randint(0, T, (256,))
    eps = torch.randn_like(x0)
    ab = alpha_bar[t].unsqueeze(1)
    xt = ab.sqrt() * x0 + (1 - ab).sqrt() * eps            # forward process
    pred = eps_model(torch.cat([xt, t.unsqueeze(1) / T], dim=1))
    loss = F.mse_loss(pred, eps)
    opt.zero_grad(); loss.backward(); opt.step()

@torch.no_grad()
def ddpm_sample(n):
    x = torch.randn(n, 2)                              # start from pure noise
    for t in reversed(range(T)):
        eps = eps_model(torch.cat([x, torch.full((n, 1), t / T)], dim=1))
        x = (x - betas[t] / (1 - alpha_bar[t]).sqrt() * eps) / alphas[t].sqrt()
        if t > 0:
            x = x + sigma2[t].sqrt() * torch.randn_like(x)  # fresh noise
    return x

The network is told the time step, here simply as t/Tt/Tt/T, because the right correction depends on how noisy the input is. And the final step adds no noise.

Flow matching and rectified flow#

Flow matching (Lipman et al., 2022) and the closely related rectified flow (Liu et al., 2022) keep the recipe "corrupt the data, regress a simple target" and strip out the noise schedule. Draw noise x0∼N(0,I)x_0 \sim \mathcal{N}(0, I)x0​∼N(0,I), a data point x1x_1x1​ and a time t∈[0,1]t \in [0, 1]t∈[0,1]. Take the point on the straight line between them, and train a network to predict the velocity along that line:

xt=(1−t) x0+t x1,L=∥vθ(xt,t)−(x1−x0)∥2.x_t = (1 - t)\,x_0 + t\,x_1, \qquad \mathcal{L} = \big\lVert v_\theta(x_t, t) - (x_1 - x_0) \big\rVert^2 .xt​=(1−t)x0​+tx1​,L=​vθ​(xt​,t)−(x1​−x0​)​2.

Many lines pass through any given point, so the network learns their average direction there. That averaged velocity field defines a flow whose paths never cross and which carries the noise distribution onto the data distribution. To generate, start from noise and integrate dx/dt=vθ(x,t)dx/dt = v_\theta(x, t)dx/dt=vθ​(x,t) from t=0t = 0t=0 to t=1t = 1t=1, here with simple Euler steps.

torch.manual_seed(0)

opt = torch.optim.Adam(v_model.parameters(), lr=1e-3)

Latent diffusion and autoregressive models#

Latent diffusion (Rombach et al., 2022) combines the pieces of this lesson. An autoencoder compresses each image into a smaller grid of latents, typically eight times smaller on each side, trained with a small KL term, a perceptual loss and a GAN loss. The diffusion or flow-matching model then works entirely in that latent space, which makes it far cheaper, and the decoder turns its output back into pixels. The last exercise builds a tiny version.

Autoregressive models belong on the same map. The chain rule of probability, p(x)=∏ip(xi∣x<i)p(x) = \prod_i p(x_i \mid x_{<i})p(x)=∏i​p(xi​∣x<i​), turns any sequence model into a generative model with an exact likelihood, and sampling one token at a time from it is ancestral sampling, just as in an LLM (lesson 08). PixelCNN applied this to raw pixels; modern systems apply it to VQ tokens. Autoregressive models dominate text, diffusion and flow matching dominate images and video, and both are used for audio. The main cost of autoregression is sequential sampling, one network call per token.

Evaluating generative models#

A generator can fail in three ways: its samples can be unrealistic, they can lack variety, or they can be copies of the training data. No single number catches all three.

  • Likelihood on held-out data, often reported in bits per dimension, is the natural score for explicit models, as for our flow. It cannot be computed for GANs, and Theis et al. (2016) showed that likelihood and sample quality can disagree: a model can have excellent likelihood and poor samples, or the reverse.
  • FID (Heusel et al., 2017) passes real and generated images through an Inception network trained on ImageNet, fits a Gaussian to each set of features, and computes the Fréchet distance between the two Gaussians: ∥μr−μg∥2+Tr⁡(Σr+Σg−2(ΣrΣg)1/2)\lVert \mu_r - \mu_g \rVert^2 + \operatorname{Tr}\big(\Sigma_r + \Sigma_g - 2(\Sigma_r \Sigma_g)^{1/2}\big)∥μr​−μg​∥2+Tr(Σr​+Σg​−2(Σr​Σg​)1/2). Lower is better.
  • Precision and recall for generative models (Sajjadi et al., 2018; Kynkäänniemi et al., 2019) split quality into two numbers. Precision is the share of generated samples that fall near real data; recall is the share of real data that falls near some generated sample.

Here are both metrics on our models: a Fréchet distance on digits, using features from a small classifier in place of Inception, and k-nearest-neighbour precision and recall on the ring.

    eps = 1e-6 * np.eye(fa.shape[1])           # keeps sqrtm numerically stable
    cov_a = np.cov(fa, rowvar=False) + eps
    cov_b = np.cov(fb, rowvar=False) + eps
    covmean = linalg.sqrtm(cov_a @ cov_b).real
    return ((mu_a - mu_b) ** 2).sum() + np.trace(cov_a + cov_b - 2 * covmean)

print("real vs real    ", round(frechet(X_te, X_tr), 2))
print("VAE samples     ", round(frechet(X_te, samples), 2))
print("AE, N(0,I) codes", round(frechet(X_te, fake), 2))
print("real, only 50   ", round(frechet(X_te[:50], X_tr[:50]), 2))

# 2. precision and recall on the ring (k-nearest-neighbour balls)
def precision_recall(real, fake, k=5):
    def radii(a):          # distance from each point to its k-th neighbour
        knn = NearestNeighbors(n_neighbors=k + 1).fit(a)
        return torch.tensor(knn.kneighbors(a)[0][:, -1])
    def inside(a, b):      # share of a that falls in some ball around b
        return (torch.cdist(a, b) <= radii(b)).any(1).float().mean().item()
    return round(inside(fake, real), 2), round(inside(real, fake), 2)

torch.manual_seed(2)
real = sample_ring(1000)
with torch.no_grad():
    gan_fake = G(torch.randn(1000, 2))
print("GAN  (precision, recall):", precision_recall(real, gan_fake))
print("DDPM (precision, recall):", precision_recall(real, ddpm_sample(1000)))
Output
real vs real     0.24
VAE samples      7.07
AE, N(0,I) codes 20.82
real, only 50    5.44
GAN  (precision, recall): (0.81, 0.6)
DDPM (precision, recall): (0.83, 0.98)

The Fréchet distance ranks the digit models sensibly: two real sets score 0.24, VAE samples 7.07 and the autoencoder's random decodes 20.82. Now look at the fourth line. Two sets of real digits, 50 images each, score 5.44, close to the VAE, because the distance is biased upwards when the sample is small. Image papers usually report FID on 50,000 generated images for this reason. The other well-known pitfalls: scores from different implementations or resizing methods are not comparable (Parmar et al., 2022); ImageNet features may not reflect what matters in your domain, such as medical scans; and one number mixes realism and variety. The ring shows why the split matters. The GAN and the diffusion model have similar precision (0.81 and 0.83), but recall exposes the collapse: 0.60 against 0.98.

Human evaluation remains the final word for text-to-image, speech and music: side-by-side preference tests with clear instructions and enough raters, designed like the evaluations in lesson 17. It is slow and costly, so automatic metrics serve for day-to-day development.

Generators can memorise their training data

Carlini et al. (2023) extracted near-copies of individual training images from Stable Diffusion and Imagen, and images duplicated many times in the training set were the most at risk. A model trained on private photos, medical records or customer data can leak them. Deduplicate training data, check the nearest training example for a sample of your outputs, and treat a generator trained on sensitive data as sensitive itself (lesson 22).

Hands-on: build a tiny latent diffusion model

At your computer 26-generative-models.ipynb, cell “Hands-on: build a tiny latent diffusion model”

  1. Train AutoEncoder(d_latent=8) with fit, encode the training digits, and standardise the codes (subtract the mean, divide by the standard deviation).
  2. Train flow matching in that 8-D latent space: mlp(9, 8, hidden=256, depth=3), 3,000 steps, batch 256.
  3. Generate 1,000 latents with 50 Euler steps, undo the standardisation and decode. Report judge_report and frechet against X_te. Compare with decoding Gaussian codes that have the right mean and standard deviation but no learnt model.
  4. Check for memorisation: compare the median distance from each generated digit to its nearest training digit with the same figure for held-out real digits.

You are done when your latent model beats the VAE's Fréchet distance of 7.07 and covers all ten digits.

Show a solution
Python
# 1. an autoencoder with an 8-D latent: the "VAE" of a latent diffusion model
torch.manual_seed(0)
ae8 = fit(AutoEncoder(d_latent=8), lambda m, x: F.mse_loss(m(x), x))
with torch.no_grad():
    codes = ae8.encoder(Xtr)
c_mean, c_std = codes.mean(0), codes.std(0)
codes = (codes - c_mean) / c_std                 # standardise the latents

# 2. flow matching in the latent space
torch.manual_seed(0)
v_lat = mlp(9, 8, hidden=256, depth=3)
opt = torch.optim.Adam(v_lat.parameters(), lr=1e-3)
for step in range(3000):
    x1 = codes[torch.randint(0, len(codes), (256,))]
    x0 = torch.randn_like(x1)
    t = torch.rand(256, 1)
    xt = (1 - t) * x0 + t * x1
    loss = F.mse_loss(v_lat(torch.cat([xt, t], dim=1)), x1 - x0)
    opt.zero_grad(); loss.backward(); opt.step()

# 3. sample latents, decode, judge
torch.manual_seed(1)
with torch.no_grad():
    z = torch.randn(1000, 8)
    for i in range(50):
        z = z + v_lat(torch.cat([z, torch.full((1000, 1), i / 50)], dim=1)) / 50
    latent_fm = ae8.decoder(z * c_std + c_mean).numpy()
    no_prior = ae8.decoder(torch.randn(1000, 8) * c_std + c_mean).numpy()
print("latent flow matching:", judge_report(latent_fm),
      round(frechet(X_te, latent_fm), 2))
print("independent Gaussian:", judge_report(no_prior),
      round(frechet(X_te, no_prior), 2))

# 4. memorisation check: distance to the nearest training image
def nn_dist(x):
    x = torch.tensor(x, dtype=torch.float32)
    return torch.cdist(x, Xtr).min(1).values.median().item()
print("held-out real digits:", round(nn_dist(X_te), 2))
print("generated digits:    ", round(nn_dist(latent_fm), 2))
Output
latent flow matching: (0.84, [98, 89, 80, 110, 85, 106, 105, 102, 100, 125]) 0.95
independent Gaussian: (0.65, [56, 146, 56, 100, 104, 116, 72, 84, 187, 79]) 3.33
held-out real digits: 1.04
generated digits:     1.01

Latent flow matching reaches a Fréchet distance of 0.95, against 7.07 for the VAE and 3.33 for Gaussian codes, with all ten digits and the judge's confidence at 0.84, close to real digits' 0.9. The autoencoder handles compression and the flow handles the distribution, which is the division of labour in latent diffusion. The memorisation check is reassuring: generated digits sit as far from their nearest training digit (1.01) as held-out real digits do (1.04). Copies would sit much closer. With a large model and a small dataset, run this check before anyone else sees the samples.

Check yourself#

1. What can you do with a model that has an explicit likelihood, such as a normalising flow, that you cannot do with a GAN?

Both can sample. Only explicit models give p(x)p(x)p(x), which you need for density estimation, anomaly scores and likelihood-based comparison.

2. Why does a VAE use the reparameterisation trick z=μ+σ⊙εz = \mu + \sigma \odot \varepsilonz=μ+σ⊙ε?

A random draw has no derivative with respect to its parameters. Moving the randomness into an input ε\varepsilonε makes zzz a differentiable function of μ\muμ and σ\sigmaσ.

3. A GAN trained on eight modes produces sharp samples that cover only three of them. What is happening, and which metric shows it most directly?

Precision asks whether samples look real, recall asks whether all of the data is covered. Mode collapse keeps the first and loses the second.

4. In flow matching with straight-line paths, what is the network trained to predict?

Generation then integrates the learnt velocity field from noise at t=0t = 0t=0 to data at t=1t = 1t=1.

5. Model A's FID was computed on 50,000 generated images and model B's on 2,000; B scores worse. What should you conclude?

You saw the bias directly: two sets of 50 real digits scored 5.44, against 0.24 for the full sets.

Key takeaways

  • A generative model learns p(x)p(x)p(x). Some score examples (explicit likelihood), some only sample (implicit), and LLMs, VAEs, GANs, flows and diffusion models are different ways to make that learning tractable.
  • Autoencoders compress well but are not generators, because nothing tells you where their codes live. The VAE's KL term pulls the codes onto a known prior, and the reparameterisation trick makes it trainable.
  • Discrete latents from a VQ-VAE turn images and audio into tokens that transformers can model like text.
  • GANs give one-step sampling through an adversarial game, at the cost of unstable training and mode collapse; lower Adam momentum, spectral normalisation and Wasserstein critics help.
  • Flows give exact likelihoods through invertible layers. Diffusion and flow matching train with simple regression losses, cover every mode, and pay for it with many sampling steps; latent diffusion moves that work into an autoencoder's latent space.
  • Evaluate realism, variety and novelty separately: likelihood, FID at a fixed sample size, precision and recall, human preference, and a nearest-neighbour memorisation check.
