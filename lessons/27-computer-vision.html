Beyond "what is in this image"#

In lesson 06 you trained a classifier: one image in, one label out. In lesson 23 you met vision transformers and CLIP, which still answer one question about the whole image. Most vision problems in industry ask more. Where is each defect on the circuit board? Which pixels are road? How many people walked through the door, and is the person in frame 200 the same one as in frame 10? The backbones are the CNNs and ViTs you already know. What changes is the head on top, the loss, and above all how you measure success.

Two ideas run through almost every row. You compare a predicted region with a true one by how much they overlap, and you turn thousands of dense, overlapping guesses into a short, clean list. This session builds both from scratch, then uses them to score a detector the way published papers do.

Boxes and how to compare them#

Box formats#

A bounding box is the smallest axis-aligned rectangle around an object, stored as four numbers. Which four depends on who wrote the tool. torchvision and Pascal VOC use the corners, (x1, y1, x2, y2), called xyxy. COCO annotation files use the top-left corner plus width and height, xywh. YOLO label files use the centre plus width and height, divided by the image size so that every number lies between 0 and 1. In all of them x grows to the right and y grows downwards, because images are stored row by row from the top.

Python
import numpy as np
import torch
from torchvision.ops import box_convert

def xywh_to_xyxy(b):
    b = np.asarray(b, dtype=float)
    return np.concatenate([b[..., :2], b[..., :2] + b[..., 2:]], axis=-1)

def xyxy_to_cxcywh(b):
    b = np.asarray(b, dtype=float)
    wh = b[..., 2:] - b[..., :2]
    return np.concatenate([b[..., :2] + wh / 2, wh], axis=-1)

W, H = 64, 48                                  # image width and height
coco_box = np.array([[10, 20, 30, 16]])        # COCO style: x, y, width, height
box = xywh_to_xyxy(coco_box)                   # torchvision style: x1, y1, x2, y2
yolo = xyxy_to_cxcywh(box) / [W, H, W, H]      # YOLO style: normalised centre and size
print(box, yolo.round(3))
print(box_convert(torch.tensor(coco_box), "xywh", "xyxy"))

Mixing formats is the most common silent bug in detection code. A model trained on boxes in the wrong format still trains and its loss still falls; it just never gets accurate. Convert once, where data enters your code, keep one format inside, and draw a few boxes on their images before you train anything. A second trap: some older tools treat coordinates as inclusive pixel indices and add 1 to every width. Here, as in torchvision and COCO, coordinates are continuous, so a box from x = 10 to x = 40 is 30 pixels wide.

Intersection over union#

How good is a predicted box? The distance between corners is a poor answer, because 5 pixels of error ruins a 10-pixel object and does not matter for a 500-pixel one. Intersection over union (IoU) does not depend on scale: it is the area the two boxes share divided by the area they cover together.

IoU(A,B)=∣A∩B∣∣A∪B∣=∣A∩B∣∣A∣+∣B∣−∣A∩B∣\text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|} = \frac{|A \cap B|}{|A| + |B| - |A \cap B|}IoU(A,B)=∣A∪B∣∣A∩B∣​=∣A∣+∣B∣−∣A∩B∣∣A∩B∣​

It is 1 for a perfect match and 0 for boxes that do not touch. It is also stricter than it looks.

The overlap of two axis-aligned boxes is itself a box. Its top-left corner is the larger of the two top-left corners, and its bottom-right corner the smaller of the two bottom-right corners. If that gives a negative width or height, the boxes do not overlap, so clip at zero. Broadcasting computes every pair at once.

Python
from torchvision.ops import box_iou

def box_area(b):
    return (b[..., 2] - b[..., 0]) * (b[..., 3] - b[..., 1])

def iou_matrix(a, b):
    """Pairwise IoU between boxes a (N, 4) and b (M, 4), both xyxy."""
    a, b = np.asarray(a, dtype=float), np.asarray(b, dtype=float)
    top_left = np.maximum(a[:, None, :2], b[None, :, :2])      # (N, M, 2)
    bottom_right = np.minimum(a[:, None, 2:], b[None, :, 2:])  # (N, M, 2)
    wh = np.clip(bottom_right - top_left, 0, None)            # 0 if no overlap
    inter = wh[..., 0] * wh[..., 1]
    union = box_area(a)[:, None] + box_area(b)[None, :] - inter
    return inter / union

a = np.array([[0, 0, 10, 10], [5, 5, 15, 15]])
b = np.array([[0, 0, 10, 10], [20, 20, 30, 30], [0, 0, 10, 5]])
print(iou_matrix(a, b).round(3))

rng = np.random.default_rng(0)
xy = rng.uniform(0, 100, (500, 2))
boxes = np.hstack([xy, xy + rng.uniform(5, 40, (500, 2))])
ours = iou_matrix(boxes, boxes)
theirs = box_iou(torch.tensor(boxes), torch.tensor(boxes)).numpy()
print(np.abs(ours - theirs).max())

Non-maximum suppression#

A detector does not output one box per object. It scores thousands of candidate boxes, and a real object lights up many of them at once, each shifted a little. Non-maximum suppression (NMS) cleans this up greedily: take the highest-scoring box, delete every remaining box that overlaps it by more than a threshold, and repeat with what is left.

Python
from torchvision.ops import nms

def nms_numpy(boxes, scores, iou_thresh=0.5):
    order = np.argsort(-scores)                # best first
    keep = []
    while order.size > 0:
        best = order[0]
        keep.append(best)
        rest = order[1:]
        overlap = iou_matrix(boxes[best][None], boxes[rest])[0]
        order = rest[overlap <= iou_thresh]    # drop boxes that overlap the winner
    return np.array(keep)

# 3 objects, 40 jittered candidate boxes around each
centres = np.array([[20, 20, 50, 60], [45, 30, 90, 70], [10, 70, 40, 95]])
cands = np.repeat(centres, 40, axis=0) + rng.normal(0, 3, (120, 4))
scores = rng.uniform(0, 1, 120)
keep = nms_numpy(cands, scores, 0.5)
keep_tv = nms(torch.tensor(cands), torch.tensor(scores), 0.5).numpy()
print(len(keep), np.array_equal(keep, keep_tv))
Output
5 True

The NumPy version agrees with torchvision.ops.nms exactly. Notice that it kept five boxes for three objects: around the smallest object, two jittered candidates overlapped the winner by less than 0.5 and survived as duplicates. The threshold is a trade-off. Lower it and you remove more duplicates, but you also delete real objects that stand close together, such as people in a crowd. Raise it and duplicates leak through. Two refinements are common: class-aware NMS, where boxes only suppress boxes of the same class (you will build it in the exercise), and Soft-NMS, which lowers the scores of overlapping boxes instead of deleting them.

How detectors work#

Every modern detector has three parts. A backbone, a CNN or ViT usually pretrained on classification, turns the image into feature maps. A neck, often a feature pyramid network (FPN), combines coarse and fine feature maps so that both large and small objects are visible. A head turns features into boxes and classes. The families differ mainly in the head.

Two-stage: propose, then classify#

The R-CNN family splits the problem in two. In Faster R-CNN, a small region proposal network slides over the feature map and, at every position, scores a handful of anchor boxes: reference boxes of several sizes and aspect ratios, such as tall, square and wide. For each anchor it predicts "object or not" and a small correction to the anchor's position and size. The best few hundred corrected anchors, after NMS, become proposals. The second stage cuts each proposal's features out to a fixed grid with RoI pooling (RoIAlign in later versions, which interpolates instead of rounding coordinates), then classifies the crop and refines its box once more. Adding a third small head that predicts a mask for each proposal gives Mask R-CNN, the classic instance segmentation model.

One-stage: predict on a grid#

YOLO ("You Only Look Once", Redmon et al. 2016) dropped the proposal step. It divides the image into a grid and makes each cell predict boxes, an objectness score and class probabilities directly, in a single pass. SSD did the same over feature maps at several scales, with anchors at each position. One-stage detectors are fast enough for real-time video and, after years of refinement in the YOLO line, accurate too.

Anchors bring hyperparameters (how many, which shapes) and a matching rule (an anchor counts as positive if its IoU with an object passes a threshold). Anchor-free detectors drop them. FCOS predicts, at every feature-map location inside an object, the distances to the box's four sides, plus a "centre-ness" score that down-weights locations near the edges. CenterNet predicts a heatmap with a peak at each object's centre and the box size at that peak. The detector you will train in session 2 works in this spirit: the cell that contains an object's centre predicts that object directly.

Set prediction: DETR#

DETR (Carion et al. 2020) treats detection as predicting a set. A transformer decoder (lesson 08) starts from a fixed number of learned object queries, 100 in the paper. Each query attends to the image features and outputs one box and one class, or "no object". There are no anchors and no NMS. The trick is in training: before computing the loss, DETR finds the one-to-one assignment between predictions and true objects with the lowest total cost, using the Hungarian algorithm. Each object is matched to exactly one query, so a second query that predicts the same object is not rewarded; it is trained to say "no object". The loss itself punishes duplicates.

Python
from itertools import permutations

pred_boxes = np.array([[10, 10, 30, 30], [12, 11, 31, 29],

Measuring a detector: precision, recall and mAP#

Accuracy does not work for detection, because there is no fixed list of answers to be right or wrong about. Instead, take all detections of one class across the test set, sort them by score, most confident first, and walk down the list. A detection is a true positive if its IoU with a not-yet-found true object of that class reaches a threshold, usually 0.5. Otherwise it is a false positive: a duplicate, a badly placed box or something that is not there. At each step you have a precision (the fraction of detections so far that were right) and a recall (the fraction of all true objects found so far). The precision-recall curve describes the detector at every possible score threshold at once.

Average precision (AP) is the area under that curve, after replacing each precision with the best precision at any higher recall so that the curve only falls. COCO reads the curve at 101 evenly spaced recall levels. mAP is AP averaged over classes, and the headline COCO number, written mAP@[.5:.95] (COCO itself just calls it AP), also averages over ten IoU thresholds from 0.5 to 0.95. A detector that finds everything with sloppy boxes scores well at 0.5 and badly at 0.95, so the averaged number rewards precise boxes.

Python
def average_precision(det_img, det_score, det_box, gt_boxes, iou_thresh=0.5):
    """AP for one class, COCO-style 101-point interpolation.
    det_*: arrays over all detections; gt_boxes: list of (K_i, 4) per image."""
    n_gt = sum(len(g) for g in gt_boxes)
    matched = [np.zeros(len(g), dtype=bool) for g in gt_boxes]
    tp = np.zeros(len(det_score))
    for k in np.argsort(-det_score):           # most confident first
        g = gt_boxes[det_img[k]]
        if len(g) == 0:
            continue
        ious = iou_matrix(det_box[k][None], g)[0]
        ious[matched[det_img[k]]] = -1         # each object can be found once
        j = ious.argmax()
        if ious[j] >= iou_thresh:
            matched[det_img[k]][j] = True
            tp[k] = 1
    tp = tp[np.argsort(-det_score)]
    recall = np.cumsum(tp) / n_gt
    precision = np.cumsum(tp) / np.arange(1, len(tp) + 1)
    # best precision achievable at this recall or higher
    precision = np.maximum.accumulate(precision[::-1])[::-1]
    levels = np.linspace(0, 1, 101)
    idx = np.searchsorted(recall, levels, side="left")
    return np.mean([precision[i] if i < len(precision) else 0 for i in idx])

# three images of one class; five objects in total
gt = [np.array([[10, 10, 40, 40], [50, 50, 90, 90]]),

                    [50, 52, 88, 90],      # good

                    [24, 34, 62, 72],      # IoU about 0.7

                    [66, 14, 99, 44]])     # IoU about 0.6

from torchvision.ops import batched_nms

def batched_nms_numpy(boxes, scores, labels, iou_thresh=0.5):
    """NMS that only lets a box suppress boxes of its own class."""
    # shift each class to its own far-away region so classes never overlap
    offset = labels[:, None] * (boxes.max() + 1)
    return nms_numpy(boxes + offset, scores, iou_thresh)

Train a tiny detector#

In practice you start from a pretrained detector (session 3), but training one yourself is the fastest way to understand what its outputs mean and why it fails. To keep training to about a minute on a CPU, you will generate the data: 64×64 images with one to three squares, circles and triangles in random colours on a noisy, shaded background. Because you draw the shapes, the boxes and the pixel masks are exact and free.

A synthetic dataset#

Python
CLASSES = ["square", "circle", "triangle"]
SIZE = 64

def make_scene(rng, max_objects=3):
    """One 64x64 RGB image with 1 to 3 shapes, their boxes, labels and mask."""
    yy, xx = np.mgrid[:SIZE, :SIZE]
    bg = rng.uniform(0.2, 0.8, 3)
    tilt = rng.uniform(-0.3, 0.3, 2)
    img = bg + (tilt[0] * (xx / SIZE - 0.5) + tilt[1] * (yy / SIZE - 0.5))[..., None]
    img = img + rng.normal(0, 0.08, (SIZE, SIZE, 3))
    mask = np.zeros((SIZE, SIZE), dtype=np.int64)       # 0 means background
    boxes, labels = [], []
    for _ in range(rng.integers(1, max_objects + 1)):
        for _attempt in range(20):                      # find a free spot
            s = rng.integers(12, 25)
            cx, cy = rng.integers(s // 2, SIZE - s // 2, 2)
            box = np.array([cx - s / 2, cy - s / 2, cx + s / 2, cy + s / 2])
            if not boxes or iou_matrix(box[None], np.array(boxes)).max() == 0:
                break
        else:
            continue
        c = rng.integers(3)
        if c == 0:
            shape = (abs(xx - cx) < s / 2) & (abs(yy - cy) < s / 2)
        elif c == 1:
            shape = (xx - cx) ** 2 + (yy - cy) ** 2 < (s / 2) ** 2
        else:
            top = cy - s / 2
            shape = (yy >= top) & (yy < cy + s / 2) & (abs(xx - cx) < (yy - top + 1) / 2)
        colour = rng.uniform(0, 1, 3)
        while np.abs(colour - bg).max() < 0.4:          # keep it visible
            colour = rng.uniform(0, 1, 3)
        img[shape] = colour + rng.normal(0, 0.08, (shape.sum(), 3))
        mask[shape] = c + 1
        ys, xs = np.nonzero(shape)                      # tight box around the pixels
        boxes.append([xs.min(), ys.min(), xs.max() + 1, ys.max() + 1])
        labels.append(c)
    return np.clip(img, 0, 1).astype(np.float32), np.array(boxes, float), np.array(labels), mask

def make_dataset(n, seed):

    scenes = [make_scene(rng) for _ in range(n)]
    images = torch.tensor(np.stack([s[0] for s in scenes])).permute(0, 3, 1, 2)
    return images, [s[1] for s in scenes], [s[2] for s in scenes], [s[3] for s in scenes]

A grid detector#

The model is a small CNN like the ones in lesson 06. Three max-pooling layers shrink 64×64 to an 8×8 grid of cells, each responsible for an 8×8-pixel patch of the image while seeing a wider neighbourhood through its receptive field. A 1×1 convolution then gives every cell eight numbers: an objectness logit, three class logits and four box numbers. As in YOLO, the cell that contains an object's centre is responsible for it. Its box targets are the centre's offset within the cell and the width and height as fractions of the image, all between 0 and 1, so a sigmoid keeps every predicted box number in range.

The loss has three parts. Objectness uses binary cross-entropy over all 64 cells, so the model learns to say "nothing here" for empty ones. The class and box losses are computed only at cells that hold an object, because an empty cell has no class or box to predict. The box loss is L1, weighted up because its values are small.

Python
import torch.nn as nn
import torch.nn.functional as F

STRIDE = 8                       # each output cell covers 8x8 pixels
GRID = SIZE // STRIDE            # 8x8 grid of cells

def encode_targets(boxes_list, labels_list):
    """Per cell: objectness, class, and box as (centre offset in cell, size)."""
    n = len(boxes_list)
    obj = torch.zeros(n, GRID, GRID)
    cls = torch.zeros(n, GRID, GRID, dtype=torch.long)
    box = torch.zeros(n, 4, GRID, GRID)
    for i, (bxs, lbs) in enumerate(zip(boxes_list, labels_list)):
        for (x1, y1, x2, y2), c in zip(bxs, lbs):
            cx, cy = (x1 + x2) / 2 / STRIDE, (y1 + y2) / 2 / STRIDE
            gx, gy = int(cx), int(cy)                  # the cell holding the centre
            obj[i, gy, gx] = 1
            cls[i, gy, gx] = c
            box[i, :, gy, gx] = torch.tensor([cx - gx, cy - gy,
                                              (x2 - x1) / SIZE, (y2 - y1) / SIZE])
    return obj, cls, box

def conv_block(c_in, c_out):
    return nn.Sequential(nn.Conv2d(c_in, c_out, 3, padding=1),
                         nn.BatchNorm2d(c_out), nn.ReLU())

class GridDetector(nn.Module):
    def __init__(self, n_classes=3):
        super().__init__()
        self.backbone = nn.Sequential(
            conv_block(3, 16), nn.MaxPool2d(2),        # 64 -> 32
            conv_block(16, 32), nn.MaxPool2d(2),       # 32 -> 16
            conv_block(32, 64), nn.MaxPool2d(2),       # 16 -> 8
            conv_block(64, 64), conv_block(64, 64))
        self.head = nn.Conv2d(64, 1 + n_classes + 4, 1)

    def forward(self, x):                              # x: (B, 3, 64, 64)
        out = self.head(self.backbone(x))              # (B, 8, 8, 8)
        return out[:, 0], out[:, 1:4], out[:, 4:].sigmoid()

def detection_loss(pred, target):
    obj_logit, cls_logit, box = pred
    obj, cls, box_t = target
    pos = obj > 0                                      # cells that hold an object
    loss_obj = F.binary_cross_entropy_with_logits(obj_logit, obj)
    loss_cls = F.cross_entropy(cls_logit.permute(0, 2, 3, 1)[pos], cls[pos])
    loss_box = F.l1_loss(box.permute(0, 2, 3, 1)[pos], box_t.permute(0, 2, 3, 1)[pos])
    return loss_obj + loss_cls + 5 * loss_box

Decoding and evaluating#

To get boxes back, convert each cell's numbers into pixel coordinates, score each cell as objectness times its best class probability, drop very low scores and run NMS within each class. Then measure with the average_precision function from session 1.

Python
from torchvision.ops import batched_nms

def decode(pred, score_thresh=0.05, iou_thresh=0.5):
    """Turn grid outputs into a list of (boxes, scores, labels) per image."""
    obj_logit, cls_logit, box = pred
    gy, gx = torch.meshgrid(torch.arange(GRID), torch.arange(GRID), indexing="ij")
    cx = (gx + box[:, 0]) * STRIDE
    cy = (gy + box[:, 1]) * STRIDE
    w, h = box[:, 2] * SIZE, box[:, 3] * SIZE
    all_boxes = torch.stack([cx - w / 2, cy - h / 2, cx + w / 2, cy + h / 2], -1)
    cls_prob, labels = cls_logit.softmax(1).max(1)
    scores = obj_logit.sigmoid() * cls_prob
    results = []
    for b, s, l in zip(all_boxes, scores, labels):
        b, s, l = b.reshape(-1, 4), s.reshape(-1), l.reshape(-1)
        keep = s > score_thresh
        b, s, l = b[keep], s[keep], l[keep]
        keep = batched_nms(b, s, l, iou_thresh)        # NMS within each class
        results.append((b[keep].numpy(), s[keep].numpy(), l[keep].numpy()))
    return results

Augmentation that moves the boxes#

Augmentation for detection has one rule: whatever you do to the pixels, you must also do to the boxes. A horizontal flip maps x to W − x, so the new left edge comes from the old right edge: x1' = W − x2 and x2' = W − x1. Forget the swap and you get boxes with negative widths, which many loss functions accept without complaint. torchvision's transforms.v2 does this bookkeeping for you if you wrap the boxes in tv_tensors.BoundingBoxes.

Python
from torchvision import tv_tensors

def hflip(image, boxes):
    """image: (C, H, W) tensor; boxes: (N, 4) xyxy in pixels."""
    W = image.shape[-1]
    x1, y1, x2, y2 = boxes.unbind(-1)
    return image.flip(-1), torch.stack([W - x2, y1, W - x1, y2], -1)

Segmentation#

Pixel-wise classification#

Semantic segmentation assigns a class to every pixel: road, pavement, car, sky. It does not separate two touching cars; both are just "car" pixels. Instance segmentation does, giving each object its own mask, usually by predicting a mask inside each detected box as Mask R-CNN does. Panoptic segmentation combines the two: countable things such as cars get instance masks, and shapeless regions such as sky and road get class labels.

In code, semantic segmentation is classification with one answer per pixel instead of one per image. The model returns logits of shape (batch, classes, height, width), and F.cross_entropy accepts that shape directly, averaging the loss over pixels. The difficulty is the architecture: a classifier throws away spatial detail as it pools, and spatial detail is exactly what a per-pixel answer needs.

A small U-Net#

The U-Net (Ronneberger et al. 2015, designed for biomedical images) solves this with an encoder-decoder shape. The encoder is an ordinary CNN that halves the resolution and doubles the channels at each level, learning what is in the image. The decoder upsamples back to full resolution. The key is the skip connections: at each level the decoder concatenates the encoder's feature map of the same size, so fine detail about where the edges are flows straight across instead of being squeezed through the low-resolution bottom.

Python
def double_conv(c_in, c_out):
    return nn.Sequential(conv_block(c_in, c_out), conv_block(c_out, c_out))

class UNet(nn.Module):
    def __init__(self, n_classes=4, c=8):
        super().__init__()
        self.enc1 = double_conv(3, c)                   # 64x64
        self.enc2 = double_conv(c, 2 * c)               # 32x32
        self.bottom = double_conv(2 * c, 4 * c)         # 16x16
        self.up2 = nn.ConvTranspose2d(4 * c, 2 * c, 2, stride=2)
        self.dec2 = double_conv(4 * c, 2 * c)           # input: upsampled + skip
        self.up1 = nn.ConvTranspose2d(2 * c, c, 2, stride=2)
        self.dec1 = double_conv(2 * c, c)
        self.out = nn.Conv2d(c, n_classes, 1)           # a class score per pixel

    def forward(self, x):
        s1 = self.enc1(x)
        s2 = self.enc2(F.max_pool2d(s1, 2))
        b = self.bottom(F.max_pool2d(s2, 2))
        d2 = self.dec2(torch.cat([self.up2(b), s2], dim=1))   # skip connection
        d1 = self.dec1(torch.cat([self.up1(d2), s1], dim=1))  # skip connection
        return self.out(d1)                             # (B, n_classes, 64, 64)

Dice and IoU#

Pixel accuracy is the obvious metric and a misleading one. In our images about 88% of pixels are background, so a model that predicts "background" everywhere scores 0.88 while finding nothing. Use an overlap score per class instead. IoU works for sets of pixels exactly as it does for boxes. The Dice coefficient counts the overlap twice against the sum of the two sizes:

Dice(P,T)=2 ∣P∩T∣∣P∣+∣T∣,Dice=2 IoU1+IoU\text{Dice}(P, T) = \frac{2\,|P \cap T|}{|P| + |T|}, \qquad \text{Dice} = \frac{2\,\text{IoU}}{1 + \text{IoU}}Dice(P,T)=∣P∣+∣T∣2∣P∩T∣​,Dice=1+IoU2IoU​

For a single mask one is a function of the other, so they rank results the same way, and Dice is never lower than IoU. Medical imaging tends to report Dice; driving and scene-parsing benchmarks report mean IoU.

Python
def seg_scores(pred, target, n_classes=4):
    """Per-class Dice and IoU, pooled over all pixels of all images."""
    dice, iou = [], []
    for c in range(1, n_classes):                       # skip background
        p, t = pred == c, target == c
        inter = (p & t).sum().item()
        total = p.sum().item() + t.sum().item()
        dice.append(2 * inter / total)
        iou.append(inter / (total - inter))
    return np.array(dice), np.array(iou)

Transposed convolution or upsampling?#

The decoder has to increase resolution. A transposed convolution (sometimes, inaccurately, called a deconvolution) is a learnable upsampler: each input pixel stamps a weighted copy of the kernel onto the output, with the stamps spaced by the stride. The alternative is a fixed resize, nearest or bilinear, followed by an ordinary convolution.

Promptable and open-vocabulary models#

Everything so far has a fixed list of classes, set at training time. Two lines of work relax that, and both build on what you saw in lesson 23.

Segment anything#

SAM (Kirillov et al. 2023) is a promptable segmenter. You give it an image and a prompt, such as a click on an object, a few clicks or a rough box, and it returns a mask for whatever you pointed at, with no notion of class. It was trained on SA-1B, over a billion masks on 11 million images, collected with a "data engine" in which the model helped annotators and, in the final stage, produced the masks itself. The architecture is built for interaction: a heavy ViT image encoder runs once per image, then a light prompt encoder and mask decoder turn each new click into a mask in a fraction of a second. Because one click is ambiguous (the button, the shirt or the whole person?), SAM returns several candidate masks with a predicted quality score for each. SAM 2 (2024) extends the idea to video, following the selected object from frame to frame.

In practice SAM is less a final model than a tool. Pair it with a detector to turn boxes into masks, run it inside an annotation tool to cut labelling time, or prompt it with points from another model.

Open-vocabulary detection#

An open-vocabulary detector finds objects described in text, including classes it was never trained to box: "a forklift", "a cracked insulator", "the red mug". The trick is the one that made CLIP zero-shot. A closed detector ends in a linear layer with one row of weights per class, so its classes are frozen into the weights. An open-vocabulary detector replaces that layer with a comparison between each candidate region's embedding er\mathbf{e}_rer​ and the text embedding tk\mathbf{t}_ktk​ of each prompt:

score(r,k)=σ ⁣(er⋅tkτ+b)\text{score}(r, k) = \sigma\!\left(\frac{\mathbf{e}_r \cdot \mathbf{t}_k}{\tau} + b\right)score(r,k)=σ(τer​⋅tk​​+b)

where τ\tauτ is a temperature and bbb a bias. Change the prompts and you change the classes, with no retraining. OWL-ViT and OWLv2 build this on a CLIP-style image-text model, letting every ViT output token predict a box and an embedding. Grounding DINO fuses text and image features inside a DETR-style detector, and YOLO-World brings the idea to a real-time YOLO. In Hugging Face transformers, pipeline("zero-shot-object-detection", model="google/owlv2-base-patch16-ensemble") is a quick way to try one.

These models are excellent for exploring a problem, prototyping and pre-labelling, and usually weaker than a fine-tuned closed detector on a narrow, well-defined task. A pattern that works well: let an open-vocabulary model pre-label your images, have people correct the labels, and train a small, fast detector on the result.

Video: tracking by detection#

A video is a stack of images, often 25 to 60 per second, and neighbouring frames are nearly identical. That has two consequences. First, you rarely need to process every frame: for many monitoring tasks, a few frames per second, or running only when a cheap motion check fires, saves most of the compute. Second, to count or follow objects you need identities: this box in this frame is the same forklift as that box in the last one.

The standard approach is tracking by detection: run a detector on each frame, then link the detections across frames. The simplest link uses IoU. An object moves only a little between frames, so its new box overlaps its old one.

Python
def iou_track(frames, iou_thresh=0.3):
    """Greedy IoU tracker. frames: list of (N_t, 4) detection arrays.
    Returns one array of track IDs per frame."""
    tracks, next_id, all_ids = {}, 0, []          # tracks: id -> last box
    for dets in frames:
        ids = np.full(len(dets), -1)
        if tracks and len(dets):
            track_ids = np.array(list(tracks))
            iou = iou_matrix(np.array(list(tracks.values())), dets)
            pairs = np.unravel_index(np.argsort(-iou, axis=None), iou.shape)
            for t, d in zip(*pairs):              # best overlaps first
                if iou[t, d] < iou_thresh:
                    break
                if ids[d] == -1 and track_ids[t] not in ids:
                    ids[d] = track_ids[t]
        for d in np.flatnonzero(ids == -1):       # unmatched: start a new track
            ids[d] = next_id
            next_id += 1
        tracks = dict(zip(ids, dets))             # unmatched tracks end here
        all_ids.append(ids)
    return all_ids

# returned in a random order each frame (as a detector would)
rng = np.random.default_rng(0)
start = np.array([[5, 10, 25, 30], [70, 5, 90, 25], [10, 70, 30, 90]], float)
velocity = np.array([[2, 1], [0, 2], [3, 0]], float)

ids = iou_track(frames)
for obj in range(3):

Each object keeps a single ID for all 20 frames. Real trackers add more. SORT predicts where each track will be in the next frame with a Kalman filter (a constant-velocity motion model) and matches with the Hungarian algorithm instead of greedily. DeepSORT adds an appearance embedding for each box, so it can recognise an object again after it was hidden. ByteTrack also uses low-score detections, which are often real objects that are partly hidden, to keep tracks going. All of them keep unmatched tracks alive for a few frames, which is your exercise.

def iou_track_aged(frames, iou_thresh=0.3, max_age=3):
    tracks, next_id, all_ids = {}, 0, []         # id -> (last box, frames since seen)
    for dets in frames:
        ids = np.full(len(dets), -1)
        if tracks and len(dets):
            track_ids = np.array(list(tracks))
            last = np.array([box for box, _ in tracks.values()])
            iou = iou_matrix(last, dets)
            pairs = np.unravel_index(np.argsort(-iou, axis=None), iou.shape)
            for t, d in zip(*pairs):
                if iou[t, d] < iou_thresh:
                    break
                if ids[d] == -1 and track_ids[t] not in ids:
                    ids[d] = track_ids[t]
        for d in np.flatnonzero(ids == -1):
            ids[d] = next_id
            next_id += 1
        new = {i: (box, 0) for i, box in zip(ids, dets)}
        for i, (box, age) in tracks.items():      # keep unmatched tracks a while
            if i not in new and age + 1 <= max_age:
                new[i] = (box, age + 1)
        tracks = new
        all_ids.append(ids)
    return all_ids

rng = np.random.default_rng(3)
dropped_frames, dropped_order = [], []
for f, p in zip(frames, order):
    keep = rng.uniform(size=len(f)) > 0.2         # the detector misses 20%
    dropped_frames.append(f[keep]); dropped_order.append(p[keep])

for name, tracker in [("basic", iou_track), ("max_age=3", iou_track_aged)]:
    ids = tracker(dropped_frames)
    n_ids = len({int(i) for frame in ids for i in frame})
    print(f"{name:>10s}: {n_ids} track IDs for 3 objects")

Keeping a track's last box for a few frames bridges short gaps. It works here because the objects move at most 3 pixels per frame and the boxes are 20 pixels wide, so a box last seen two or three frames ago still overlaps the new one. With faster motion the stale box would not overlap at all, which is why SORT moves each track forward with its motion model before matching.

Depth and 3-D in brief#

A camera flattens a 3-D world onto 2-D pixels, and many applications need some of the third dimension back. Monocular depth estimation predicts a distance for every pixel from a single image. Models such as MiDaS and Depth Anything are trained on large mixed datasets and mostly predict relative depth (this is nearer than that), not distances in metres, unless a version was trained specifically for metric depth. Stereo cameras recover metric depth from the shift between two views, and LiDAR and time-of-flight sensors measure it directly, producing point clouds that networks such as PointNet process. With depth ZZZ and the camera's focal length fff and principal point (cx,cy)(c_x, c_y)(cx​,cy​), pixel (u,v)(u, v)(u,v) maps back to the 3-D point X=(u−cx)Z/fX = (u - c_x)Z/fX=(u−cx​)Z/f, Y=(v−cy)Z/fY = (v - c_y)Z/fY=(v−cy​)Z/f. To reconstruct whole scenes from many photos, neural radiance fields (NeRF) and 3-D Gaussian splatting learn a representation that can render new viewpoints, usually starting from camera poses computed by classical structure-from-motion tools such as COLMAP.

Deploying vision models#

Vision models often run where the camera is: on a phone, a drone, a factory gateway or a small embedded board, with tight limits on latency, power and memory. The levers, roughly in the order to try them:

  • Input resolution. A convolutional network's compute grows with the number of pixels, so doubling the side quadruples the cost. Choose the smallest resolution at which your smallest important objects are still clearly visible: a scratch 10 pixels long at 640×640 is about 3.5 pixels long at 224×224.
  • A smaller architecture. MobileNet, EfficientNet-Lite and the small YOLO variants are designed for devices. Measure accuracy on your own data rather than trusting benchmark tables.
  • Export. torch.onnx.export writes the model as a portable graph that ONNX Runtime, TensorRT (NVIDIA) and OpenVINO (Intel) can run, often faster than PyTorch itself; Core ML and LiteRT (formerly TensorFlow Lite) target Apple and Android devices. Check that the exported model's outputs match the original on real images. Detection post-processing, the decoding and NMS, is the part that most often breaks or quietly differs.
  • Quantisation. Storing weights and activations as 8-bit integers makes a model about four times smaller and usually faster on CPUs and neural accelerators. Static quantisation needs a few hundred representative calibration images, and you must measure the accuracy you lose, as with LLMs in lesson 21.

The cell below measures one backbone at four input sizes. It uses random weights, because speed does not depend on the weight values, so it needs no download.

Python
import time
from torch.utils.flop_counter import FlopCounterMode
from torchvision.models import mobilenet_v3_large

backbone = mobilenet_v3_large(weights=None).features.eval()  # speed only
for side in (224, 320, 480, 640):
    x = torch.randn(1, 3, side, side)
    with torch.inference_mode():
        with FlopCounterMode(display=False) as counter:
            backbone(x)                                       # also a warm-up
        start_t = time.perf_counter()
        for _ in range(10):
            backbone(x)
    ms = (time.perf_counter() - start_t) / 10 * 1000
    gflops = counter.get_total_flops() / 1e9
    print(f"{side}x{side}: {gflops:5.2f} GFLOPs  {ms:5.1f} ms")

The FLOP counts are exact: 0.43 GFLOPs at 224×224 rising to 3.47 at 640×640, eight times the work for 8.2 times the pixels. The times depend on your machine and on what else it is running. On a CPU, one small image does not keep every core busy, so time grows more slowly than the FLOPs at small sizes. Always measure on the target device, with the real resizing, colour conversion and NMS included, since on small devices they can cost as much as the network.

Labelling and data quality#

On most vision projects the dataset matters more than the architecture, and boxes and masks are slow and expensive to draw. A few habits pay off quickly:

  • Write a labelling guide before anyone labels. Say what counts as an object, how tight a box must be, and what to do with objects that are hidden, cut off by the frame or tiny, with pictures of hard cases. Inconsistent labels put a ceiling on mAP, especially at strict IoU thresholds.
  • Measure agreement. Have two people label the same 50 images and compare their boxes with iou_matrix. If annotators agree only to IoU 0.8, a model cannot be expected to score well at 0.95.
  • Use a proper tool. CVAT and Label Studio are widely used open-source annotation tools for boxes, polygons and masks, and both can call a model to pre-label images so that people only correct them.
  • Label what the model finds hard. In active learning, you run the current model over the unlabelled pool, rank images by uncertainty (for example, detections with scores near your threshold), label the top few hundred, retrain and repeat. Compare against labelling a random sample of the same size, which is a surprisingly strong baseline.
  • Hunt for label errors. Sort training images by the model's loss. The top of the list mixes genuinely hard images with wrong labels; fixing the wrong ones is cheap accuracy.
  • Split by source. Frames from the same video, site or day are near-duplicates. If they land in both training and test sets you are measuring memory, not generalisation: the leakage problem from lesson 03.

Check yourself#

1. Two 10×10 boxes overlap in a strip 5 pixels wide and 10 pixels tall. What is their IoU?

The intersection is 50 and the union is 100 + 100 − 50 = 150, so IoU is 50/150. Half-overlapping boxes score only a third.

2. A detector scores mAP@0.5 = 0.90 but mAP@[.5:.95] = 0.45. What is the most likely explanation?

Finding objects is what mAP@0.5 rewards; the stricter thresholds up to 0.95 reward precise boxes, so a large gap points to loose localisation.

3. Why does DETR not need non-maximum suppression?

Hungarian matching gives each true object one query; any other query predicting it is trained towards "no object".

4. A segmentation model reaches 95% pixel accuracy on images in which 94% of the pixels are background. What should you conclude?

Pixel accuracy is dominated by the majority class; overlap scores per class show whether the objects are actually found.

5. How can an open-vocabulary detector find a class that was never in its training labels?

The fixed classification layer is replaced by a comparison with text embeddings from a CLIP-style encoder, so the vocabulary is whatever you type.

Key takeaways

  • Vision tasks differ in what they output (labels, boxes, masks, keypoints, depth, identities), and each comes with its own metric.
  • IoU compares regions regardless of scale, and NMS turns dense, overlapping predictions into one box per object. Both are a few lines of NumPy; keep one box format inside your code.
  • Detectors are a backbone, a neck and a head: two-stage (proposals, then RoI features), one-stage (a grid, with or without anchors) or set prediction (DETR, Hungarian matching, no NMS).
  • mAP averages precision over recall, classes and, in COCO, IoU thresholds. It says nothing about the score threshold you deploy with, which you choose separately.
  • Segmentation is classification per pixel. U-Nets recover detail through skip connections; measure them with Dice or IoU per class, not pixel accuracy.
  • Start from pretrained, promptable (SAM) or open-vocabulary models, track video by linking detections, and deploy by cutting resolution, exporting and quantising, measured on the target device.
