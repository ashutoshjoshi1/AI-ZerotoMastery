03 Machine learning fundamentals

What it means for a model to learn, the workflow every ML project follows, why models overfit and how to stop them, and how to measure performance honestly.

What "learning" means#

Traditional programming takes rules and data and produces answers. Machine learning takes data and answers and produces the rules. You give a model many examples of inputs xxx paired with desired outputs yyy, and an algorithm searches for a function fff such that f(x)≈yf(x) \approx yf(x)≈y, including for inputs it has never seen.

That last clause is the whole game. A model that memorises its training examples is useless; we want one that generalises. Every technique in this lesson is about measuring and improving generalisation.

The kinds of learning#

Kind You provide The model learns Examples
Supervised Inputs and labels A mapping from input to label Spam detection, price prediction, image classification
Unsupervised Inputs only Structure in the data Clustering customers, anomaly detection, compression
Self-supervised Raw data; labels are made from the data itself Rich general-purpose representations LLM pretraining: predict the next word of real text
Reinforcement An environment and a reward signal A policy for acting Game playing, robotics, RLHF for chat models

Supervised learning splits further into regression (predict a number: temperature, price) and classification (predict a category: spam or not, which of 1,000 objects).

Self-supervised learning deserves a note because it is how LLMs are made. Nobody labels the internet. Instead, every sentence provides its own labels: hide the next word and ask the model to predict it. That trick turned the whole web into a training set.

The workflow#

Almost every ML project follows the same loop. Skipping steps is the most common cause of failure.

  1. Frame the problem. What decision will the prediction drive? What does a mistake cost? Which metric reflects that cost?
  2. Get and understand the data. Explore it (lesson 01). Check where labels come from and how noisy they are.
  3. Split the data before you look at it too closely, so the test set stays honest.
  4. Build a baseline. The simplest thing that could work: predict the mean, the most common class, or yesterday's value.
  5. Train models, starting simple.
  6. Evaluate on the validation set, analyse errors, iterate on features and models.
  7. Test once on the held-out test set.
  8. Deploy and monitor, because the world changes and models decay.

Splits, overfitting and generalisation#

Three sets, three jobs#

  • Training set (often 60 to 80%): the model learns its parameters here.
  • Validation set (10 to 20%): you compare models and tune settings such as learning rate or tree depth (the hyperparameters) here.
  • Test set (10 to 20%): touched once, at the end, to estimate real-world performance.

Why a separate test set? Every time you check the validation score and make a change, you leak a little information about the validation set into your choices. After fifty experiments, your validation score is optimistic. The test set is your one unbiased measurement.

Split by what you will see in production

If the model will predict the future, split by time: train on the past, validate on later data, never shuffle across time. If it will see new users or new instruments, make sure no user or instrument appears in both training and test sets. Random splits on such data give scores that look great and mean nothing.

Overfitting, seen with your own eyes#

Fit polynomials of increasing degree to 20 noisy points from a sine wave and compare training and test error.

Python
import numpy as np
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression, Ridge
from sklearn.pipeline import make_pipeline
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error

rng = np.random.default_rng(1)
x = rng.uniform(0, 1, 40)
y = np.sin(2 * np.pi * x) + rng.normal(0, 0.25, 40)
X = x.reshape(-1, 1)                                   # sklearn wants 2-D inputs: (samples, features)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.5, random_state=0)

for degree in [1, 3, 9, 15]:
    model = make_pipeline(PolynomialFeatures(degree), LinearRegression())
    model.fit(X_tr, y_tr)
    tr = mean_squared_error(y_tr, model.predict(X_tr))
    te = mean_squared_error(y_te, model.predict(X_te))
    print(f"degree {degree:>2}: train MSE {tr:.3f}   test MSE {te:.3f}")
Output
degree  1: train MSE 0.161   test MSE 0.145     underfitting: too simple
degree  3: train MSE 0.027   test MSE 0.037     about right
degree  9: train MSE 0.017   test MSE 0.118     starting to overfit
degree 15: train MSE 0.006   test MSE 95408.7   memorised the noise

Training error keeps falling as the model gets more flexible. Test error falls, then rises. The gap between them is the signature of overfitting: the model has learned the noise in its particular training points rather than the underlying pattern.

Bias and variance#

Two kinds of error pull in opposite directions:

  • Bias: error from wrong assumptions. A straight line cannot fit a sine wave however much data you give it. High bias means underfitting: high training error and high test error.
  • Variance: error from sensitivity to the particular training sample. A degree-15 polynomial changes wildly if you swap a few points. High variance means overfitting: low training error, high test error.

Diagnosis in practice:

Training error Validation error Diagnosis Try
High High Underfitting (bias) Bigger model, better features, train longer
Low High Overfitting (variance) More data, regularisation, simpler model, early stopping
Low Low Good Check the test set, then ship

Regularisation#

Regularisation discourages complexity. The most common form adds a penalty on the size of the weights to the loss:

Lridge=MSE+α∑jwj2Llasso=MSE+α∑j∣wj∣L_{\text{ridge}} = \text{MSE} + \alpha \sum_j w_j^2 \qquad\qquad L_{\text{lasso}} = \text{MSE} + \alpha \sum_j |w_j|Lridge​=MSE+αj∑​wj2​Llasso​=MSE+αj∑​∣wj​∣

L2 (ridge) shrinks all weights smoothly. L1 (lasso) pushes many weights to exactly zero, which also performs feature selection. In neural networks the same L2 idea appears as weight decay, alongside dropout and early stopping (lesson 05).

Python
for alpha in [1e-6, 1e-3, 1e-1, 10]:
    model = make_pipeline(PolynomialFeatures(15), Ridge(alpha=alpha))
    model.fit(X_tr, y_tr)
    print(alpha, round(mean_squared_error(y_te, model.predict(X_te)), 3))
# 1e-06 0.035   even a tiny penalty rescues the degree-15 model
# 0.001 0.031   best
# 0.1   0.083
# 10    0.275   too much: now it underfits

The degree-15 model went from a test error of 95,000 to 0.031 with a small penalty. Regularisation strength is itself a hyperparameter, chosen on validation data.

Cross-validation#

With small datasets, one validation split is noisy: you might get lucky or unlucky. k-fold cross-validation splits the data into kkk folds, trains kkk times, each time validating on a different fold, and averages the scores.

Python
from sklearn.model_selection import cross_val_score, KFold

model = make_pipeline(PolynomialFeatures(3), LinearRegression())
scores = cross_val_score(model, X, y, cv=KFold(5, shuffle=True, random_state=0),
                         scoring="neg_mean_squared_error")
print(f"MSE {-scores.mean():.3f} ± {scores.std():.3f}")

Report the spread, not just the mean. If two models differ by less than the standard deviation across folds, you have not shown that one is better.

Metrics that tell the truth#

Regression#

  • MAE (mean absolute error): average size of the error, in the target's units. Easy to explain.
  • RMSE (root mean squared error): punishes large errors more. Use when big misses are especially costly.
  • R²: fraction of variance explained, 1 is perfect, 0 is no better than predicting the mean.

Classification and the confusion matrix#

Accuracy (fraction correct) is misleading whenever classes are imbalanced. If 1% of instruments are faulty, a model that always says "healthy" is 99% accurate and completely useless. Look at the confusion matrix instead:

Predicted positive Predicted negative
Actually positive True positive (TP) False negative (FN)
Actually negative False positive (FP) True negative (TN)

From it come the metrics that matter:

precision=TPTP+FPrecall=TPTP+FNF1=2⋅precision⋅recallprecision+recall\text{precision} = \frac{TP}{TP + FP} \qquad \text{recall} = \frac{TP}{TP + FN} \qquad F_1 = \frac{2\cdot\text{precision}\cdot\text{recall}}{\text{precision} + \text{recall}}precision=TP+FPTP​recall=TP+FNTP​F1​=precision+recall2⋅precision⋅recall​
  • Precision: of the alarms raised, how many were real? Low precision means alarm fatigue.
  • Recall: of the real problems, how many did we catch? Low recall means missed faults.
  • F1: the harmonic mean, a single number that is only high when both are.

Which matters more depends on the cost of each mistake. Screening for a serious disease favours recall; flagging emails as spam favours precision (losing a real email is worse than seeing some spam).

Python
from sklearn.metrics import confusion_matrix, classification_report

y_true = np.array([1, 0, 1, 1, 0, 0, 1, 0, 0, 0])
y_pred = np.array([1, 0, 0, 1, 0, 1, 1, 0, 0, 0])
print(confusion_matrix(y_true, y_pred))      # [[5 1] [1 3]]: TN=5 FP=1 FN=1 TP=3
print(classification_report(y_true, y_pred))

Thresholds, ROC and PR curves#

Most classifiers output a score or probability, and you choose the threshold above which to say "positive". Lowering the threshold raises recall and lowers precision. The ROC curve plots true-positive rate against false-positive rate across all thresholds, and ROC-AUC summarises it (0.5 is random, 1.0 perfect). For rare positives, the precision-recall curve and its average precision are more informative, because ROC can look flattering when negatives vastly outnumber positives.

Baselines and leakage#

Always beat a baseline#

Before training anything clever, compute what a trivial predictor scores: the mean for regression, the majority class for classification, "same as yesterday" for time series. scikit-learn's DummyClassifier and DummyRegressor do this in one line. If your model barely beats the baseline, it has not learned much, whatever the absolute number looks like.

Data leakage#

Leakage is information in your training data that will not be available at prediction time. It produces models that score brilliantly in testing and fail in production. Common forms:

  • Target leakage: a feature that is computed from the label. Predicting equipment failure with a "repair cost" column that is only filled in after a failure.
  • Preprocessing leakage: fitting a scaler or imputer on the whole dataset before splitting, so test-set statistics leak into training. Fix it by putting preprocessing inside a scikit-learn Pipeline so it is fit on training folds only.
  • Temporal leakage: shuffling time series, so the model trains on the future to predict the past.
  • Duplicate leakage: the same or near-identical examples in train and test. This is a real concern for LLM benchmarks too, where test questions may have appeared on the web the model trained on (lesson 17).

The leakage smell test

If a result seems too good, it probably is. Ask of every feature: would I really know this value at the moment I need the prediction?

Hands-on: an honest evaluation

At your computer 03-ml-fundamentals.ipynb, cell “Hands-on: an honest evaluation”

Use scikit-learn's built-in breast cancer dataset (from sklearn.datasets import load_breast_cancer).

  1. Split 80/20 with stratify=y so both sets keep the class balance.
  2. Score a DummyClassifier(strategy="most_frequent") baseline.
  3. Train a LogisticRegression inside a pipeline with StandardScaler, using 5-fold cross-validation on the training set to pick C from [0.01, 0.1, 1, 10].
  4. Report precision, recall and F1 on the test set, once.
  5. In this problem, which error is worse, a false negative or a false positive? How would you change the threshold?
Show a solution

Python
from sklearn.datasets import load_breast_cancer
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.model_selection import train_test_split, GridSearchCV
from sklearn.metrics import classification_report

X, y = load_breast_cancer(return_X_y=True)   # in this dataset 1 = benign, 0 = malignant
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)

base = DummyClassifier(strategy="most_frequent").fit(X_tr, y_tr)
print("baseline accuracy", base.score(X_te, y_te))        # about 0.63

pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))
search = GridSearchCV(pipe, {"logisticregression__C": [0.01, 0.1, 1, 10]}, cv=5, scoring="f1")
search.fit(X_tr, y_tr)
print(search.best_params_)
print(classification_report(y_te, search.predict(X_te)))   # accuracy around 0.96 to 0.97
Missing a malignant tumour (a false negative for the malignant class) is far worse than an unnecessary follow-up test. You would lower the threshold for flagging "malignant", for example by using predict_proba and flagging anything with more than 10 to 20% malignancy probability, accepting more false alarms for higher recall. Note that the scaler lives inside the pipeline, so cross-validation never leaks test-fold statistics.

Check yourself#

1. A model has 2% training error and 25% validation error. What is the most likely diagnosis?

A large gap between training and validation error is the signature of high variance.

2. Why keep a separate test set if you already have a validation set?

Every decision informed by validation results leaks information about it. The test set is used once, at the end.

3. Only 1 in 200 transactions is fraud. Your model is 99.5% accurate. What should you conclude?

With heavy imbalance, accuracy hides everything. Compare against the majority-class baseline and use precision, recall or PR-AUC.

4. You standardise all features using the mean and standard deviation of the full dataset, then split. What is the problem?

This is preprocessing leakage. Small here, but it is the same mistake that produces badly inflated scores in other settings.

5. Which kind of learning is LLM pretraining?

The labels come free from the data itself. RLHF, applied later, is the reinforcement learning part.

Key takeaways

  • The goal is generalisation to unseen data, not performance on the training set.
  • Split into train, validation and test, matching how the model will be used (by time, by user, by instrument).
  • Compare training and validation error to diagnose underfitting versus overfitting. Regularisation, more data and simpler models fight overfitting.
  • Pick metrics that reflect the real cost of mistakes. Accuracy lies on imbalanced data; use precision, recall, F1 and PR curves.
  • Beat a trivial baseline, and hunt for leakage whenever results look too good.
