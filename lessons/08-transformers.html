08 Attention and the transformer

The architecture behind every modern LLM, built up piece by piece: self-attention in NumPy, masking and multiple heads, the transformer block, then a small GPT you train yourself in PyTorch.

Study plan: 5 sessions of about an hour

Tick a session when you finish it. Progress is saved in this browser only.

Code for this lesson: notebooks/08-transformers.ipynb, with worked solutions in notebooks/solutions/.

The idea in one paragraph#

Every token in a sequence looks at every other token and decides how much each one matters to it right now. It then pulls in a weighted mix of their information. "It" in "the animal didn't cross the street because it was too tired" should pull heavily from "animal"; in "...because it was too wide", from "street". That operation, self-attention, repeated in many layers with small neural networks in between, is the transformer. Everything else is engineering to make it train well and run fast.

Self-attention, step by step#

Each token's vector xix_ixi​ is projected three ways by learned matrices:

  • a query qi=xiWQq_i = x_i W_Qqi​=xi​WQ​: what am I looking for?
  • a key kj=xjWKk_j = x_j W_Kkj​=xj​WK​: what do I contain, for others to match against?
  • a value vj=xjWVv_j = x_j W_Vvj​=xj​WV​: what do I hand over if someone attends to me?

Token iii scores every token jjj by the dot product qi⋅kjq_i\cdot k_jqi​⋅kj​ (high when they match), turns the scores into weights with softmax, and outputs the weighted sum of values. For all tokens at once, in matrix form:

Attention(Q,K,V)=softmax ⁣(QK⊤dk)V \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V Attention(Q,K,V)=softmax(dk​​QK⊤​)V

That one line is the heart of every LLM. Here it is in NumPy:

import numpy as np

rng = np.random.default_rng(0)

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

T, d_model, d_k = 4, 8, 8                    # 4 tokens, 8-dim vectors
X = rng.normal(size=(T, d_model))            # stand-in for 4 token embeddings
Wq, Wk, Wv = (rng.normal(0, d_model ** -0.5, (d_model, d_k)) for _ in range(3))

Q, K, V = X @ Wq, X @ Wk, X @ Wv             # each (4, 8)
scores = Q @ K.T / np.sqrt(d_k)              # (4, 4): token i's score for token j
weights = softmax(scores)                    # each row sums to 1
out = weights @ V                            # (4, 8): a new vector for each token
print(weights.round(2))

[[0.34 0.13 0.33 0.2 ]
 [0.78 0.   0.05 0.17]
 [0.25 0.28 0.29 0.18]
 [0.22 0.28 0.21 0.29]]

Row 1 says token 1 takes 78% of its new representation from token 0. With random weights the pattern is meaningless; training shapes WQW_QWQ​, WKW_KWK​ and WVW_VWV​ so the patterns become useful: pronouns attending to their referents, verbs to their subjects, a closing bracket to its opening one.

Why divide by √d_k?#

The dot product of two random vectors with ddd independent unit-variance components has standard deviation d\sqrt{d}d​. With large ddd, scores get huge, softmax saturates into a near one-hot distribution, and its gradients vanish. Dividing by dk\sqrt{d_k}dk​​ keeps scores at unit scale whatever the dimension.

for d in [4, 64, 1024]:
    q, k = rng.normal(size=d), rng.normal(size=(1000, d))
    print(d, (k @ q).std().round(1), (k @ q / np.sqrt(d)).std().round(1))
# 4 1.8 0.9    64 8.6 1.1    1024 31.5 1.0

Masking, heads and positions#

Causal masking: no peeking at the future#

A language model predicts the next token, so position iii must not see positions after it. Set those scores to −∞-\infty−∞ before softmax; they become exactly zero weight.

mask = np.triu(np.ones((T, T), dtype=bool), k=1)   # True above the diagonal = the future
weights = softmax(np.where(mask, -np.inf, scores))
print(weights.round(2))
# [[1.   0.   0.   0.  ]     token 0 can only see itself
#  [1.   0.   0.   0.  ]
#  [0.31 0.34 0.35 0.  ]
#  [0.22 0.28 0.21 0.29]]    the last token sees everything

A neat consequence: one forward pass over a sequence of length TTT gives TTT training examples at once (predict token 1 from token 0, token 2 from tokens 0 and 1, and so on), all computed in parallel. That parallelism is why transformers train so much faster than RNNs.

Multi-head attention#

One attention pattern per layer is limiting: a token may need to track its syntactic head, the topic, and a matching quotation mark all at once. Multi-head attention splits the model dimension into hhh smaller heads, runs attention independently in each, concatenates the results and mixes them with an output projection WOW_OWO​. Same cost, many different "views".

def multi_head(X, Wq, Wk, Wv, Wo, n_heads, causal=True):
    T, d_model = X.shape
    d_head = d_model // n_heads
    # (T, d_model) -> (n_heads, T, d_head)
    split = lambda M: M.reshape(T, n_heads, d_head).transpose(1, 0, 2)
    Q, K, V = split(X @ Wq), split(X @ Wk), split(X @ Wv)
    s = Q @ K.transpose(0, 2, 1) / np.sqrt(d_head)          # (n_heads, T, T)
    if causal:
        s = np.where(np.triu(np.ones((T, T), dtype=bool), 1), -np.inf, s)
    out = softmax(s) @ V                                      # (n_heads, T, d_head)
    out = out.transpose(1, 0, 2).reshape(T, d_model)          # concatenate heads
    return out @ Wo

d_model, H = 16, 4
X = rng.normal(size=(6, d_model))
Ws = [rng.normal(0, d_model ** -0.5, (d_model, d_model)) for _ in range(4)]
print(multi_head(X, *Ws, n_heads=H).shape)                    # (6, 16)

Modern LLMs often use grouped-query attention (GQA): many query heads share a smaller number of key and value heads. Quality barely changes, and the memory needed to cache keys and values during generation drops several-fold.

Position: attention alone is order-blind#

Look at the attention formula again: shuffle the tokens and each token's output is the same, just shuffled. Attention treats its input as a set. Order has to be injected.

  • Learned absolute positions (GPT-2): add a trainable vector for each position 0, 1, 2, ... to the token embeddings.
  • Sinusoidal positions (original transformer): add fixed sine and cosine waves of different frequencies.
  • Rotary position embeddings, RoPE (most current open LLMs): rotate query and key vectors by an angle proportional to their position, so the dot product qi⋅kjq_i\cdot k_jqi​⋅kj​ depends on the relative offset i−ji-ji−j. It generalises better and can be stretched to longer contexts.

The transformer block#

Attention lets tokens exchange information. A per-token MLP (two linear layers with a non-linearity, typically expanding the dimension fourfold in between) then processes what each token gathered. Wrap both in residual connections and layer normalisation, the stabilisers from lesson 05, and you have a block:

x←x+MultiHeadAttention(LayerNorm(x))x←x+MLP(LayerNorm(x)) \begin{aligned} x &\leftarrow x + \mathrm{MultiHeadAttention}(\mathrm{LayerNorm}(x)) \\ x &\leftarrow x + \mathrm{MLP}(\mathrm{LayerNorm}(x)) \end{aligned} xx​←x+MultiHeadAttention(LayerNorm(x))←x+MLP(LayerNorm(x))​

Two useful mental models:

  • The residual stream. Think of xxx as a shared workspace flowing up through the network. Each attention and MLP sub-layer reads from it and writes an update back. Interpretability research uses this picture heavily.
  • Attention moves information between tokens; MLPs process it within a token. Much of a model's factual knowledge appears to be stored in the MLP weights.

Encoders, decoders and both#

Architecture Attention Trained to Examples Good for
Encoder-only Bidirectional (sees all tokens) Fill in masked-out words BERT, RoBERTa Classification, embeddings, search ranking
Decoder-only Causal (sees the past only) Predict the next token GPT, Claude, Llama, Mistral, Qwen Text generation, chat, essentially all modern LLMs
Encoder-decoder Encoder bidirectional, decoder causal plus cross-attention Map input sequence to output sequence Original transformer, T5, Whisper Translation, speech recognition, summarisation

Decoder-only models won the generality race: with enough scale, "predict the next token" covers translation, classification and everything else as special cases.

Build a tiny GPT#

Now the real thing, in about a hundred lines of PyTorch. It is a character-level model, so the "tokens" are single characters and you need no tokenizer yet (that comes in the next lesson). Train it on any plain-text file; the classic choice is Tiny Shakespeare, about 1 MB of plays. Run this on a Colab GPU for speed, although a modern laptop CPU will finish a shorter run.

Data#

import math, torch, torch.nn as nn, torch.nn.functional as F

device = "cuda" if torch.cuda.is_available() else "cpu"
torch.manual_seed(0)

# wget https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt
text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text))
vocab_size = len(chars)                                   # 65 for Tiny Shakespeare
stoi = {c: i for i, c in enumerate(chars)}
itos = {i: c for c, i in stoi.items()}
encode = lambda s: [stoi[c] for c in s]
decode = lambda ids: "".join(itos[i] for i in ids)

data = torch.tensor(encode(text), dtype=torch.long)
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]

block_size, batch_size = 128, 64                           # context length, sequences per batch

def get_batch(split):
    d = train_data if split == "train" else val_data
    ix = torch.randint(len(d) - block_size - 1, (batch_size,))
    x = torch.stack([d[i : i + block_size] for i in ix])          # (B, T)
    y = torch.stack([d[i + 1 : i + block_size + 1] for i in ix])  # targets: shifted by one
    return x.to(device), y.to(device)

Model#

class CausalSelfAttention(nn.Module):
    def __init__(self, d_model, n_heads, dropout):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model)        # W_Q, W_K, W_V in one matrix
        self.proj = nn.Linear(d_model, d_model)           # W_O
        self.attn_drop = nn.Dropout(dropout)
        self.resid_drop = nn.Dropout(dropout)

    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(C, dim=2)
        # (B, T, C) -> (B, n_heads, T, head_dim)
        q, k, v = (t.view(B, T, self.n_heads, C // self.n_heads).transpose(1, 2) for t in (q, k, v))
        att = (q @ k.transpose(-2, -1)) / math.sqrt(k.size(-1))           # (B, H, T, T)
        mask = torch.triu(torch.ones(T, T, dtype=torch.bool, device=x.device), diagonal=1)
        att = att.masked_fill(mask, float("-inf")).softmax(dim=-1)
        y = self.attn_drop(att) @ v                                        # (B, H, T, head_dim)
        y = y.transpose(1, 2).contiguous().view(B, T, C)                   # re-join heads
        return self.resid_drop(self.proj(y))
        # Production code replaces the four attention lines with
        # F.scaled_dot_product_attention(q, k, v, is_causal=True), which uses FlashAttention kernels.


class Block(nn.Module):
    def __init__(self, d_model, n_heads, dropout):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = CausalSelfAttention(d_model, n_heads, dropout)
        self.ln2 = nn.LayerNorm(d_model)
        self.mlp = nn.Sequential(
            nn.Linear(d_model, 4 * d_model), nn.GELU(),
            nn.Linear(4 * d_model, d_model), nn.Dropout(dropout),
        )

    def forward(self, x):
        x = x + self.attn(self.ln1(x))       # tokens talk to each other
        x = x + self.mlp(self.ln2(x))        # each token thinks on its own
        return x


class TinyGPT(nn.Module):
    def __init__(self, vocab_size, block_size, d_model=256, n_heads=4, n_layers=4, dropout=0.1):
        super().__init__()
        self.block_size = block_size
        self.tok_emb = nn.Embedding(vocab_size, d_model)
        self.pos_emb = nn.Embedding(block_size, d_model)          # learned absolute positions
        self.drop = nn.Dropout(dropout)
        self.blocks = nn.ModuleList([Block(d_model, n_heads, dropout) for _ in range(n_layers)])
        self.ln_f = nn.LayerNorm(d_model)
        self.head = nn.Linear(d_model, vocab_size, bias=False)
        self.head.weight = self.tok_emb.weight                    # weight tying: input and output share embeddings
        self.apply(self._init)

    def _init(self, m):
        if isinstance(m, (nn.Linear, nn.Embedding)):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)         # small init keeps the initial loss near ln(vocab)
        if isinstance(m, nn.Linear) and m.bias is not None:
            nn.init.zeros_(m.bias)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        pos = torch.arange(T, device=idx.device)
        x = self.drop(self.tok_emb(idx) + self.pos_emb(pos))      # (B, T, C)
        for block in self.blocks:
            x = block(x)
        logits = self.head(self.ln_f(x))                          # (B, T, vocab)
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
        for _ in range(max_new_tokens):
            logits, _ = self(idx[:, -self.block_size:])          # crop to the context window
            logits = logits[:, -1, :] / temperature               # only the last position matters
            if top_k is not None:
                v, _ = torch.topk(logits, top_k)
                logits[logits < v[:, [-1]]] = float("-inf")
            next_id = torch.multinomial(F.softmax(logits, dim=-1), num_samples=1)
            idx = torch.cat([idx, next_id], dim=1)
        return idx

Train and sample#

model = TinyGPT(vocab_size, block_size).to(device)
print(sum(p.numel() for p in model.parameters()) / 1e6, "M parameters")   # about 3.2M
opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)

@torch.no_grad()
def estimate_loss(iters=50):
    model.eval()
    out = {}
    for split in ["train", "val"]:
        out[split] = sum(model(*get_batch(split))[1].item() for _ in range(iters)) / iters
    model.train()
    return out

for step in range(5001):
    if step % 500 == 0:
        print(step, estimate_loss())          # step 0 should show about ln(65) = 4.17
    x, y = get_batch("train")
    _, loss = model(x, y)
    opt.zero_grad(set_to_none=True)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step()

start = torch.tensor([encode("ROMEO:")], device=device)
print(decode(model.generate(start, 400, temperature=0.8, top_k=40)[0].tolist()))

The validation loss should fall from about 4.17 to roughly 1.5 in a few thousand steps. The samples go from random characters, to word-shaped gibberish, to recognisably Shakespearean formatting: speaker names in capitals, line breaks, archaic-sounding words, invented but plausible. Nobody told the model about any of that. It learned it all from predicting the next character, which is the same objective, at vastly smaller scale, that produces modern LLMs.

Hands-on: experiments on your GPT

  1. Remove the causal mask and retrain for a few hundred steps. The training loss drops suspiciously fast. Why, and what happens to generation?
  2. Delete the position embedding. How does the validation loss and the sample quality change?
  3. Double n_layers to 8, then separately double d_model to 512. Record parameters, validation loss and time per step. Which gave more improvement per parameter?
  4. Train on a different text: your own notes, a public-domain book, or Python source code.
Show what you should find
  1. Without the mask, each position can see the very token it is asked to predict, so the model learns to copy it and the training loss collapses towards zero. At generation time there is no future token to copy, so samples are garbage. This is the most instructive bug in the course: a loss that looks too good usually means leakage, the same lesson as in lesson 03.
  2. Without positions the model only knows which characters are in the context, not their order. Loss ends noticeably higher and text loses structure (words and line layout degrade), though it still learns some local statistics through the causal mask.
  3. Both help a little at this scale. Wider models tend to be faster per parameter on a GPU (bigger matrix multiplications); deeper models can represent more compositional structure. Scaling laws (next lesson) study exactly these trade-offs at large scale.
  4. On Python code the model quickly learns indentation and keywords, and soon produces plausible-looking, non-working code: a miniature version of why code LLMs work and why their output needs testing.

Generation, the KV cache and the cost of attention#

Generation is a loop#

An LLM produces text one token at a time: run the model on the context, sample a token from the last position's distribution, append it, repeat. Our generate method does exactly that, and so does every chat model, which is why responses stream in word by word.

The KV cache#

Our naive generate recomputes keys and values for the whole context at every step, which is wasteful: past tokens' keys and values never change. Real inference engines store them in a KV cache and compute only the new token's query, key and value per step. This turns generation from quadratic to linear work per token, at the cost of memory. For an 8-billion-parameter model with 32 layers, 8 key-value heads of dimension 128, in 16-bit precision, the cache is

2×32×8×128×2 bytes≈131 KB per token 2 \times 32 \times 8 \times 128 \times 2\ \text{bytes} \approx 131\ \text{KB per token} 2×32×8×128×2 bytes≈131 KB per token

which is about 1 GB for one 8,000-token conversation. KV cache memory, not model weights, often limits how many users a GPU can serve at once (lesson 17), and it is why grouped-query attention matters.

Attention is quadratic in sequence length#

Every token attends to every other, so the score matrix is T×TT \times TT×T. Doubling the context quadruples attention compute. Long-context models rely on optimised kernels such as FlashAttention, which computes exact attention without ever materialising the full matrix in slow GPU memory, plus position schemes like RoPE that extend gracefully. The quadratic cost is also why "just put everything in the context" is not free, which you will weigh against retrieval in lesson 13.

Check yourself#

1. In self-attention, what determines how much token i attends to token j?

Scores are q_i · k_j / √d_k, normalised by softmax across j.

2. Why is the causal mask necessary when training a GPT-style model?

Without it the model cheats by copying the answer, and the low training loss means nothing.

3. Self-attention without any positional information treats its input as...

Order must be injected, by learned positions, sinusoids or rotary embeddings.

4. What is the KV cache?

It trades memory for speed, and its size often limits how many concurrent users a GPU can serve.

5. Doubling a transformer's context length roughly does what to the cost of the attention score computation?

The score matrix is T × T, so attention compute grows with the square of sequence length.

Key takeaways

  • Self-attention: softmax(QK⊤/dk)V\mathrm{softmax}(QK^\top/\sqrt{d_k})Vsoftmax(QK⊤/dk​​)V. Tokens score each other with query-key dot products and mix their values.
  • Causal masking makes a next-token predictor and gives TTT training examples per sequence in parallel. Multi-head attention runs several patterns at once; positions must be injected (learned, sinusoidal or RoPE).
  • A block is attention then MLP, each wrapped in layer norm and a residual connection. Decoder-only stacks of these blocks are today's LLMs.
  • You built and trained one. The objective is the same as for frontier models; the difference is scale, data and post-training.
  • Generation is a sampling loop; the KV cache makes it efficient but costs memory; attention cost grows quadratically with context.
